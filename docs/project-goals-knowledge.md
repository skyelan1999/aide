# 项目目标、验收与知识决策记录

本页描述 2026-11-13 的源码增补，基于既有任务规划、执行/交付回执和项目 token 记忆。**v0.1.19.0-RC2 安装包不包含本次增补**；源码、安装包与运行实例分别核对。[English](en/project-goals-knowledge.md)。

## 建立目标并逐项验收

1. 选择正确项目与会话，打开“轨迹 → 任务与规划”。空会话也能先建立目标。
2. 输入任务目标；可展开“交付物与验收条件”，每行填写一项。验收条件应能被实际观察，例如“回归测试通过”“报告中列出了计算依据”。
3. 添加后点“交给 aide”。目标的交付物、条件和最近用户复核意见进入该次执行上下文；模型还可用只读 `task_acceptance` 查看当前条件，按 `criterionId` 读取完整观察。
4. 执行结束后，检查文件、命令和实际输出。在“目标与验收”逐项记录通过、未通过、受阻或待验收，并填写实际观察；可关联本轮工具证据。
5. 所有条件通过后，目标才显示完成。执行成功但尚未签收显示“待验收”；存在失败、阻塞、待审批文件或缺失交付时仍保留缺口。

未提交的目标与条件在当前页面按项目/会话隔离保留，切换轨迹视图或面板重绘不会清空；整页刷新或关闭页面不是草稿持久化。

未设置验收条件的旧任务保持原有行为。验收记录是**用户观察记录**，不是另一套自动测试结果；工具摘要和模型回答也不能代替业务正确性判断。文件尚未应用、执行未完成或交付缺失时不能签收通过。模型没有修改用户签收状态的工具。

条件修改后重新验收。重跑会使旧执行的签收记录失效，历史观察仍保留；模型可据此处理缺口。证据绑定任务、工作区、文件提案状态和工具记录快照；变化后旧页面提交返回冲突。它不是持续监控磁盘或外部业务系统的校验器，外部文件改变后需要重读、执行并复核。

含验收条件的目标固定到建立时的项目。切换项目不能把旧目标直接改写或执行到新项目；需要跨项目复用时，导出再导入规划。导入保留条件和依赖，重建 ID、项目绑定，并清空运行与验收状态。关闭未验收目标不会解除后续依赖；已验收目标关闭后仍可作为完成的依赖。

每个目标最多 10 项交付物（每项 200 字）、20 项条件（每项 500 字）；观察最多 2000 字。每项保留最近 10 条历史复核，目标保留最近 5 份条件修订快照。当前和历史记录可通过规划 JSON 导出；单项历史复核也可在页面展开查看。

## 项目知识与决策

在同一面板展开“项目知识与决策”，记录以下四类资料：

| 类型 | 适合记录 |
| --- | --- |
| 事实 | 已观察的版本、设备参数、项目现状 |
| 约束 | 兼容范围、禁止修改的部分、必须遵守的条件 |
| 决策 | 采用的方案、原因及适用版本 |
| 未决问题 | 尚待确认的输入或设计问题 |

填写主题、内容和“来源与版本”，例如 `specification.md / v3 / 第 4 节`，或本次用户明确给出的决定。来源是可追溯的引用说明，不代表系统独立核验过其内容。

新记录先进入“待确认”。模型可通过 `project_knowledge` 提议记录，并保留所属会话/执行身份；**只有用户页面/API 操作可以确认、明确替代或归档**。确认代表用户核对过这条历史记录，不授予新权限，也不证明外部操作成功。

更新决策时，新增同类型、同主题的记录，在确认前勾选明确要替代的旧记录。旧内容、来源、确认时间与替代关系保留，不静默覆盖。未选择替代而确认多条同主题记录时，页面和模型上下文会提示核对冲突。主题匹配只归一化空白和大小写，不是任意文本之间的语义矛盾检测。

归档使记录退出默认模型参考，历史仍在页面和导出记录内。刷新、确认其他记录或归档其他记录不会清空尚未提交的新增草稿；并发写入冲突保留草稿，刷新后重新核对提交。

## 跨会话与现有记忆兼容

结构化记录扩展现有缓存 `aide/memory-tokens.json`，按工作区身份隔离，沿用既有本地或 SSH 项目缓存同步。旧 `read_memory` / `write_memory`、24 KiB 文本记忆和 `memory.md` 投影继续工作；外部编辑兼容文本不会抹掉结构化记录。结构化记录不重复写进兼容文本。

新会话请求会注入当前项目的有界参考：优先已确认记录，并明确标注待确认和同主题冲突；已替代、已归档记录不作为当前参考。最多 12 条、合计 6000 字节的完整行，不保证覆盖全部知识。摘要不足时，模型可搜索/分页读取 `project_knowledge`；默认每页最多 10 条、上限 20 条，记录 JSON 约 24 KiB 预算，使用返回的 `nextCursor` 和相同查询继续。知识或查询变化后旧 cursor 失效。

每份缓存最多 128 条结构化记录（含归档/替代历史），主题、内容、来源分别最多 200、2000、1000 字；整个 token JSON 上限 2 MiB。达到上限会拒绝新增，不自动淘汰历史。先导出与备份，再受控整理，归档本身不释放记录数量。

并发快照检查与文件互斥保护同一 Aide 服务内的更新；不构成多个进程或远端 SFTP 写入者之间的分布式锁/CAS。SSH 读取失败会报错，不回退同名本地数据；同步失败后应重新读取确认远端状态。上下文只读本机工作副本，不在构造模型请求时等待 SSH。

历史知识始终是参考资料，不能覆盖当前用户要求或成为审批授权。来源文件变化不会自动重判一条事实或决策；应更新来源、提议修订并明确替代。回退旧程序前应备份完整缓存，旧程序写 JSON 未必保留新增字段。

## API 与模型工具

所有端点沿用现有认证与同源规则；记录接口在锁屏时拒绝访问。操作快照仅用于冲突检测。

| 接口 | 行为 |
| --- | --- |
| `POST /api/sessions/{id}/plan` | 既有新增任务接口增加可选 `contract`，含 `deliverables` 和 `criteria:[{text}]`；页面同时提交目标 `workspaceId` 防止项目切换失配 |
| `GET /api/sessions/{id}/plan/{item}/acceptance` | 返回条件、有效状态、实际工具证据索引、当前项目及 `snapshot` |
| `PUT /api/sessions/{id}/plan/{item}/acceptance` | 使用 `snapshot` 和新 `contract` 修订条件；运行中不能替换 |
| `POST /api/sessions/{id}/plan/{item}/acceptance` | 使用 `snapshot`、`criterionId`、`state`、`note` 和可选 `toolIndex` 记录用户复核；状态为 `pending/passed/failed/blocked` |
| `GET /api/project-knowledge` | 返回当前项目记录、冲突提示、`workspaceId` 和 `snapshot` |
| `POST /api/project-knowledge` | 提交同项目 `workspaceId`、`snapshot` 和 `action:propose/confirm/archive`；确认可带明确的 `supersedes` ID 列表 |
| `task_acceptance` | 模型只读工具；可选 `criterionId`，无签收操作 |
| `project_knowledge` | 模型 `list/propose` 工具；列表支持 `query/cursor/limit/includeArchived`，模型不能确认/替代/归档 |

`confirm/archive` 针对 `id`；`propose` 接收 `kind/subject/content/source`。两个模型工具均可在现有工具开关中关闭。导入规划时页面附 `destinationWorkspaceId`，目标项目变化会拒绝；外部旧格式调用仍兼容。

## 验证与交付边界

聚焦 API/持久化/并发/context 回归位于 `goal_acceptance_test.go`、`project_knowledge_test.go`；日常基础 Go 门禁包含这些测试。真实浏览器场景为 `TestProjectRecordsBrowser` 与 `scripts/browser-project-records.cjs`，正式 Delivery 的原浏览器门禁也调用同一场景。

本次命令、源码指纹、实际页面观察和限制以[任务记录](tasks/project-goals-knowledge-20261113.json)及其引用证据为准。浏览器使用隔离数据和确定性模型夹具，不等于付费模型、真实客户 SSH、原生设备或生产部署验收。

小秘跟进也按目标状态区分执行结束与目标签收；条件改动会形成新的待验收提示。关闭且未验收的目标不会被当作待自动继续的工作。

后续能力：[变更影响与分阶段业务流程](project-impact-workflows.md)在这些目标、验收和既有项目能力上接续。
