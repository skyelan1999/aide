# aide v0.1.18.0-RC1

## 新增与改进

- 聊天默认使用异步协同。调度器按任务决定是否拆分，独立执行环境按需拉起插件能力、交换结果并合并；保留普通项目开发能力和现有串行路径，不要求占满所有并发槽。
- 聊天输入框支持拖入文件、粘贴图片，附件沿用既有发送链路；图片不再因模型名称或视觉能力标记被预先拒绝。
- 开发文件提案移除原数量/内容大小门槛，保留路径边界、原文件版本/哈希冲突与审批机制；大型变更仍需核对实际上下文与内存开销。
- 自开发候选使用隔离的工作目录、数据、Compose 项目、端口和 A/B 槽，构建/验证后再明确提升，避免覆盖正在运行的项目。
- 审批卡片补充批准后的执行意图、目标与完整原始命令；保留手动确认、沙箱和授权边界。
- 日常 push/PR 改为基本 CI；完整发行增加双架构全量验证、Windows/macOS 宿主、三浏览器 48 格矩阵，以及全部当前公开插件现有安装包的实际安装和功能验证。测试用例和操作边界集中到 [Release 验收文档](../testing/release-validation.md)。

- 增加跨模块与插件的结构化异常事件：关联请求/任务、插件版本、失败阶段、错误类别和代码位置，有界持久化并并入诊断包，见[异常定位](../architecture/diagnostics.md)。

## 修复

- 长运行上下文摘要恢复增强：处理包裹的 JSON、截断或不合格摘要，保留任务上下文并给出可复核的恢复状态。
- 改善并行文件草稿、工具执行资源、取消清理与工作区变化时的结果校验，避免旧环境结果被错误合入。
- 流式文件读取保留完整接收与文件内容对应的回执，减少长读取丢失或误报完成的机会。
- 发布收据检查实际测试完成情况、完整公开插件集合和共同源码身份；退役旧的一次性发布旁路。

## 升级影响

- 使用与宿主对应的 ARM64/AMD64 完整运行包；开发工具为独立可选 SDK，不进入默认运行镜像。已有数据、工作区、插件和凭据保留，升级前仍应备份。
- 插件继续从市场独立安装。此版本验证现行公开发布包，不要求把全部插件重新编译，也不在 Aide 发行镜像内捆绑公有或私有插件。
- 性能取决于任务拆分、服务商延迟和合并成本。并发上限不承诺等比例加速，历史 Luna 基准只适用于对应任务/配置。
- 本次 Release 不自动替换维护者本机运行服务。使用现有 A/B 槽和旧运行包回退；不要通过删除数据目录来处理升级问题。

## 已知问题

- 不支持图片的模型端点仍可能返回接口错误；取消 Aide 预检查不意味着所有模型具备识图能力。
- 插件功能验收使用合成数据及隔离服务。真实付费模型、余额账户、操作系统隐私授权、机器人、SSH 设备和串口硬件需要对应环境的独立验收。
- Linux WebKit 测试不等同于原生 Safari；Windows/macOS 宿主检查不等于 Docker Desktop 完整真机升级生命周期。File Preview 的图片渲染通过不能替代全部 Office/HTML 格式验收。
- 功能开关和可选集成测试的跳过项会单独记录在发行附件 `RELEASE-VALIDATION.json`，不能解读为已经验证。六个 DSH 公开能力预设没有独立执行 handler，验收的是其实际安装与能力声明。
