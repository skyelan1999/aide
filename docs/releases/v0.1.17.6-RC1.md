# aide v0.1.17.6-RC1

## 新增与改进 / Added and improved

- Aide 可选集成 Codex Bridge 宿主管理组件，支持 macOS、Windows 与 Linux。镜像构建时从固定版本的公开 Release 取回组件，并校验源码提交及 SHA-256；插件未启用时不会启动宿主组件。用户可在已启用的 Codex Bridge 插件中安装、启动、停止、卸载和生成一次性连接密钥。
- Aide 宿主管理能力只提供固定生命周期操作，不提供通用 Shell、任意下载、Codex 登录或模型供应商凭据读取。插件 API Key 仅用于模型认证，不会作为宿主配对密钥。
- 本次由用户明确要求的发布在最近一次公开 Release 七天内进行，因此通过可审计的手动工作流原因字段执行一次例外；默认发布路径仍强制至少间隔七天，自动候选构建不受影响。

The optional Codex Bridge host manager now integrates with Aide on macOS, Windows and Linux. The image build retrieves a pinned public release and verifies its source commit and SHA-256 digest. The host component starts only when the plugin is enabled. The enabled plugin exposes fixed install, start, stop, uninstall and one-time pairing-key actions.

Host management does not expose a general shell, arbitrary downloads, Codex sign-in or provider credentials. Model API keys remain separate from host pairing keys. The owner-authorized publication uses a logged, manual-only cadence exception; normal and automatic release cadence remains seven days.

## 修复 / Fixed

- Windows 原生启动器以常驻子进程方式启动管理 helper，避免启动器清理短生命周期子进程时误结束宿主管理器。
- 发布包携带各平台所需的固定管理 helper；运行时从所选、已校验的 Aide 镜像提取，不再依赖重新拉取插件仓库源码。

The native Windows launcher keeps the helper alive under the resident host process instead of terminating it with short-lived launcher cleanup. Platform helpers ship with the release package and are extracted from the selected, verified Aide image rather than fetched from a plugin source repository at runtime.

## 升级影响 / Upgrade impact

- 需要同时使用 Aide v0.1.17.6-RC1 完整发行包及 Codex Bridge v0.4.0。已有安装须更新主程序镜像与宿主启动器；仅更新插件 ZIP 不会提供宿主管理组件。Aide 主程序不捆绑或自动启用插件。
- 请按 Docker 引擎架构选择对应完整包。保留现有 `.env`、`.aide-data` 与工作目录设置。新组件由插件工作台控制，未启用插件时不会启动。
- 本次只发布 GitHub Release 与市场元数据，不替换或重启本地 9999 服务。

Use the full Aide v0.1.17.6-RC1 release package together with Codex Bridge v0.4.0. Existing installations must update both the application image and host launcher; replacing only the plugin ZIP does not add the host manager. Aide does not bundle or enable the plugin. Keep existing environment, data and workspace settings. This release does not replace or restart the local 9999 service.

## 已知问题 / Known limitations

- 组件生命周期、协议、安装包摘要及 macOS/Linux 隔离宿主路径已通过本地与 CI 检查；Windows CI 覆盖原生进程及 PowerShell 5.1/7 代理回归，但未在用户的 Windows 桌面和真实 Codex 账户上完成全链路验收。
- 额度展示取决于 Codex CLI 本机可提供的账户接口；当前发行不保证所有账户、登录方式或订阅类型均可返回余额或额度百分比。缺失时应明确显示不可用，不推断或伪造数值。
- 宿主要求 Node.js 18+ 与已登录的 Codex CLI。插件市场兼容性声明不能代替具体 Windows 主机的安装和运行验收。

CI covers native Windows process behavior and PowerShell 5.1/7 update-agent regressions, but no end-to-end acceptance was performed on the user's Windows desktop or real Codex account. Usage/quota visibility depends on data exposed by the local Codex CLI and is not guaranteed for every account type. The host requires Node.js 18+ and an already authenticated Codex CLI. Marketplace compatibility metadata is not a substitute for validation on a specific machine.
