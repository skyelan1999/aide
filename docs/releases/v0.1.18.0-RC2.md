# aide v0.1.18.0-RC2

## New features

- Paired with Terminal 1.6.0: independent session copy and copy-and-connect, including multiple independent streams through one existing relay.
- Telnet supports direct and relay connections, IAC negotiation, terminal type, window size and NVT line endings. Passwords are entered interactively and never copied as session settings.
- Independent device SSH sessions support explicit untrusted X11 forwarding. The runtime includes xauth; an accessible authenticated X Server, DISPLAY and private Xauthority remain user prerequisites. No X Server installation or access-control changes happen automatically.

## Fixes

- Preserve canonical session identity and private key references when copying; hidden and cross-workspace sessions remain isolated.
- Workspace SSH copies use an inode-pinned short ControlPath, avoiding Unix socket path limits without retargeting an existing SSH master.
- Display all populated terminal session groups; canceling a pending Telnet connection cannot resurrect a closed session. Telnet input obeys dynamically disabled send policy and preserves fragmented CRLF/Unicode input.

## Compatibility and verification

- Terminal 1.6.0 requires Aide 0.1.18.0 RC2 or newer. Upgrade the host before installing it from the marketplace. Plugins remain separately distributed; no public or private plugin ZIPs are bundled in Aide images.
- Release validation requires both native Linux architectures, the current public package inventory with actual installation and functional assertions, browser and native host checks, package import and runtime checks. Terminal 1.6.0 additionally runs original-ZIP copy/Telnet admission checks; runtime and reimport smoke checks require a real xauth executable.
- Exact source, package identities and executed/skipped checks are recorded in RELEASE-VALIDATION.json. Isolated fixtures are not acceptance of customer devices. Linux Xvfb/OpenSSH testing does not establish native macOS XQuartz, Windows X Server, physical serial or customer network compatibility.

## Upgrade and rollback

- Back up data before upgrading; keep the previous Aide package and Terminal 1.5.3 package available. Stopping/upgrading the plugin disconnects sessions; it does not replay commands or reconnect automatically.
- This publication does not restart the maintainer production service or alter its data, relay keys or existing sessions. Use the existing A/B upgrade process for deployment.

Publication state and exact immutable assets are determined by the corresponding GitHub Release. Failed or skipped checks are not described as passing.
