# 远程目录中继（源码功能，Issue #644）

项目文件的“引用”支持 **远程中继目录**。先离线保存远程设备地址与共享目录，再下载配置好的 Python 脚本，在保存文件的设备上手动运行。Aide 通过中继读写该固定目录，无需 SSH 账户或在 Aide 容器中安装 Terminal 插件。

## 配置与部署

1. 在项目文件中切换到“引用”，添加来源，选择“远程中继目录”。填写 Aide 能访问的主机/IP、TCP 端口（默认 `8767`）和远程绝对目录，例如 `/srv/refs` 或 `C:\Refs`。目录必须已存在。
2. 默认保持只读。密钥留空自动生成；编辑时留空保留现有密钥。通常不需要手动填写密钥。
3. 保存后在来源条目点击“下载脚本”。此时远程设备可以离线。将下载的 `.py` 文件保存到远程共享目录**之外**，限制其他账户读取。
4. 在远程设备安装 Python 3.10+ 及 `cryptography`，在终端执行：

   ```sh
   python -m pip install cryptography
   python aide-reference-relay-来源ID.py
   ```

   Windows 如果 `python` 不对应 Python 3，可使用 `py -3`。脚本前台运行；停止该进程即停止中继。没有自动后台安装、远程执行命令或自动修改防火墙。
5. 确保 Aide 所在设备/容器能连接填写的主机及中继 TCP 端口，点击“检测中继”，再选中该来源浏览文件。远端位于 NAT 内时，需要现有 VPN、端口转发或可达网络；这个文件服务没有自动穿透能力。

脚本默认监听所有 IPv4 接口；填写 IPv6 字面地址时下载版本监听 IPv6。可用 `--listen-host 127.0.0.1` 仅绑定回环地址，以便经既有隧道访问。端口已占用、目录不存在或依赖缺失时，脚本会拒绝启动。修改端口或共享目录后重新下载部署；同时保留旧进程会导致检测失败或仍连接旧配置。

## 读写与 AI 可见性

浏览、文本/二进制预览、下载、知识索引和 AI 文件读取沿用现有来源入口。上传、复制、移动、创建目录、重命名、删除、编辑器保存及 Markdown 历史恢复接入现有文件接口。上传下载和复制使用原有分块传输引擎，支持校验、暂停和断点恢复；并非通过预览接口传输大文件。

写入必须同时满足 Aide 中该来源已标记“读写”、下载部署的脚本允许写入，以及远程运行账户的操作系统权限。只在 Aide 解锁不能使旧的只读脚本获得写权限；解锁后需要重新下载并替换运行脚本。在 Aide 重新锁为只读会立即拒绝新的写入请求。已经开始提交到远端的单个操作可能完成；锁定不回滚已经完成的写入。

“对工作区可见”继续控制 AI 的读取、目录附件、搜索及文档提案；用户手动浏览独立于该开关。AI 文件修改使用现有提案/审批路径，编辑器保存继续检查读取版本。来源停用、删除、共享配置或密钥变化会拒绝旧连接请求、旧传输任务和旧提案继续使用该绑定。修改权限或配置后应重新打开文件；修改密钥后重新下载并重启远端脚本。

文件中继不提供 shell，不能作为 Terminal 的远程工作区执行命令。AI 也不能代替用户下载含密钥的部署脚本。

## 协议与范围

- 传输使用 TLS 1.3；随机 32 字节密钥派生 Ed25519 服务身份并在客户端固定校验，再通过随机挑战 HMAC 验证访问。身份和消息域与 Terminal 中继分离。每次请求绑定来源 ID 与共享根目录，防止改路径后误连旧部署。
- 密钥复用来源凭据保险库及其既有回退存储规则，不进入普通来源配置、来源列表或 AI 发现结果。脚本下载是唯一显式导出路径，要求现有 Aide 鉴权，返回 `Cache-Control: no-store`；保险库锁定时拒绝导出，不静默更换已有密钥。
- 远端只共享启动时的固定目录。拒绝绝对协议路径、`..`、符号链接、Windows 重解析点、特殊文件及内部临时文件名。自身脚本和临时证书目录按文件身份隔离，含指向脚本的硬链接。远端账户仍应只授予实际所需的目录权限。
- POSIX 使用目录描述符和 `O_NOFOLLOW`；Windows 使用目录句柄、禁止共享删除、重解析点检查及最终路径核验。脚本本身及复制的含密钥配置仍须由部署者妥善保管；复制成其他普通文件的密钥不会被自动内容识别。
- 整体读取/编辑上限 64 MiB；实际文本编辑还受现有文本大小和格式策略限制。随机传输每块最多 4 MiB，大文件沿用传输引擎。目录单次最多 2,000 项和 1 MiB JSON；超限明确失败，不能将截断目录冒充完整索引。
- 最多 8 个并发连接、128 个打开的传输句柄；连接读写超时 30 秒、会话绝对上限 60 秒，空闲句柄 120 秒后回收。传输和知识请求取消时关闭客户端连接；既有普通同步文件调用受 30 秒超时约束；离线/失联句柄最终由代理回收。
- 编辑保存先接收并校验完整内容，写临时文件、同步后替换；传输在私有暂存文件完成后发布。新建和重命名不覆盖已有目标。远端其他程序同时编辑文件仍可能形成竞争，应遵循现有版本冲突提示。

## API 与验证

`Source.type = "relay"`，公开配置为 `config.host / port / path`，写权限沿用 `rw`，凭据通过 `secrets[id].key` 更新。以下入口均沿用 Aide 访问令牌：

| 方法与路径 | 行为 |
| --- | --- |
| `PUT /api/sources` | 离线保存配置，首次自动生成密钥 |
| `GET /api/sources/{id}/relay-script` | 下载该来源的完整部署脚本，含密钥与本次读写设置 |
| `POST /api/sources/{id}/relay-probe` | 显式检测，返回 `online / remoteWritable / rw` |
| 原有文件、传输、知识和提案 API | 使用同一来源 ID |

`scripts/test_reference_relay_agent.py` 验证实际内嵌脚本的目录边界、链接/私有文件、写入中断、校验失败和句柄限制；Go `TestReferenceRelay*` 用 API 实际下载并启动脚本，验证 TLS、读写、权限、撤销、知识、提案和断点传输。前端行为回归在 `scripts/source-relay-ui.test.cjs`。Windows 文件边界测试加入原有 Windows CI；尚未通过的目标平台不能据此宣称已验收。

浏览器验收可显式运行 `AIDE_RELAY_BROWSER_FIXTURE=1 go test -v -timeout=26m ./internal/server -run '^TestReferenceRelayBrowserFixture$'`，使用一次性目录和合成令牌，在 `18977` 端口提供真实工作台与中继。该入口仅用于隔离开发环境，测试结束后退出并清理；不读取真实会话、不调用模型。当前任务验收与未验证项见 [任务账本](tasks/reference-relay-20261030.json)。


## SFTP 脚本中继（#655）

SFTP 来源可选择“直接连接”或“通过远程脚本中继”。中继设备只需能够访问目标 SFTP 服务；SFTP 主机名按该设备所在网络填写。Aide 必须能访问中继主机及其监听端口，端口默认 `8768`。

1. 添加来源，类型选 SFTP，连接方式选“通过远程脚本中继”。填写目标 SFTP 主机/端口、用户名、密码或私钥、远程目录，再填写中继主机/端口。保持读写复选框未选中即为只读；中继密钥留空自动生成。
2. 先保存来源，再在来源条目下载 `aide-sftp-relay-来源ID.py`。脚本包含独立的中继访问密钥；放在 SFTP 共享目录之外并限制读取权限。脚本不含 SFTP 密码或 SSH 私钥。
3. 在中继设备安装 Python 3.10+ 和 cryptography（`python -m pip install cryptography`），前台运行 `python aide-sftp-relay-来源ID.py`。默认监听所有 IPv4 接口；中继地址为 IPv6 字面值时监听 IPv6。脚本不自动修改防火墙或安装后台服务。
4. 点击“检测中继”，检查 TLS 身份、挑战证明、固定部署配置和目标端口可达性；打开来源目录才实际执行 SSH 主机密钥与 SFTP 认证。检测成功不代表 SFTP 登录成功。编辑器中的草稿目录选择暂不支持未部署中继；部署后从来源浏览目录。
5. 需要写入时在 Aide 打开读写锁；仍须满足 SFTP 账户权限与既有提案/审批规则。SFTP 中继采用现有 SFTP 读写控制，不使用本地目录中继脚本的 `rw` 开关。改变目标主机、端口、目录或中继监听端口后重新下载部署；更换 SSH 账号、密码、私钥及 Aide 读写锁无需重发脚本。

实现保留 `Source.type="sftp"`，可选公开配置为 `config.relayHost / relayPort`，独立密钥通过 `secrets[id].relayKey` 更新。SFTP 密码、SSH 私钥和中继密钥合并存入既有每来源凭据保险库，部分更新保留其他字段；普通来源列表不回传密钥。脚本下载与探测复用上表 API。SSH 连接使用原目标身份与既有主机密钥策略（首次接受并记录，后续变更拒绝），通过私有临时 ProxyCommand 客户端传输；临时文件权限 0600，连接建立或失败返回后清理。目标/中继/目录及凭据变化会关闭旧 SSH 主连接。

外层中继采用独立协议域的 TLS 1.3、密钥派生的 Ed25519 身份固定和每连接挑战 HMAC；认证完成前不发送 SSH 凭据。远程脚本只连接内嵌的单个目标，不从请求接收目标地址；SFTP 协议仍由 Aide 的 OpenSSH 客户端与原服务处理。最多 8 个并发连接，握手超时 15 秒，目标连接超时 10 秒，空闲转发超时 60 秒（既有 SSH 保活每 15 秒）。中继检测只建立目标 TCP 连接后关闭，不执行 SFTP 操作。

`TestSFTPRelayActualSSH` 使用 API 实际下载启动代理，并与临时 SSH/SFTP 服务交互；覆盖密码/私钥认证、列表/读/写、只读拒绝、错误中继身份、过期部署和 SSH 主机密钥更换。`TestSFTPRelayVaultPatch` 验证三字段凭据部分更新及锁定保护；`TestSFTPRelayRejectMalformedExistingCredentials` 验证启用中继不覆盖损坏的既有密文。前端回归扩展在 `scripts/source-relay-ui.test.cjs`。实际浏览器可用 `AIDE_SFTP_RELAY_BROWSER_FIXTURE=1 go test -v -timeout=25m ./internal/server -run '^TestSFTPRelayBrowserFixture$'`，仅临时数据，在 `18978` 端口提供工作台。
