# REQ-001 · 辅助审批展示执行意图并绑定具体待执行内容

- 编号：REQ-001
- 创建时间：2026-10-31 16:31:40
- 状态：待评审
- 关联需求：无

## 需求描述
修复辅助审批信息不足的问题，在待审批的 shell 命令和文件提案卡片中展示可核对的执行意图，明确动作、目标/工作目录、影响及无法静态确认的部分。意图必须根据实际待执行命令或文件提案生成，不得由模型臆造替代原始操作内容。

## 目标
- 审批者能在决定前理解批准后会执行什么、作用于哪里、可能产生何种状态变化。
- 审批摘要与实际命令/文件提案保持一致；原始完整命令、路径与内容继续可展开核验。
- 对无法可靠推断的副作用明确标记为未知/需核对，不错误承诺安全或可逆。

## 范围
- shell 命令审批卡片及独立辅助审核输入：展示“运行命令”、任务工作目录、潜在文件/外部状态/网络影响需根据完整命令核对，并显示完整命令。
- 文件提案审批卡片及独立辅助审核输入：展示待写入目标、创建/修改类别、文件数量和写入副作用；继续展示实际差异/内容。
- 对当前实现的关键意图数据增加针对性测试。
- 不更改审批策略授权范围、记忆规则、沙箱、命令执行语义或文件提案版本保护；不把意图摘要视作批准本身。

## 验收标准
- shell 审批明确显示执行动作及工作目录，且清楚说明具体目标和副作用必须以原始完整命令为准；命令本身仍可查看。
- 文件审批明确列出未应用目标、创建/修改操作及写入影响，范围与将实际应用的文件一致；原始提案内容仍可查阅。
- 自动审核接收的意图摘要来自同一份待审批命令/提案，并同时接收原始命令/完整提案；任何摘要失败不扩大审批权限。
- 无法确认的目标、网络/外部状态影响或可逆性不得描述成已确认事实。
- 现有拒绝、审批持久化失败拒绝放行、审批轮次过期及提案版本检查不被削弱。
- 新增测试通过；本轮如运行构建/测试，报告真实结果，不宣称未经运行时验证的行为。

## 技术考量
执行意图优先作为服务端由真实 pending command / Change 数据确定的结构化描述，再用于 UI 与辅助审核载荷，避免前端或模型单方面生成。shell 静态分析不能完整安全解释任意复合命令，必须保留完整命令并明示其未知副作用。文件意图需排除已应用项目，以免摘要超出实际待应用范围。审批仍绑定原命令指纹或文件提案指纹，摘要不是可复用授权。
