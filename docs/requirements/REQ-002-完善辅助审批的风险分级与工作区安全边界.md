# REQ-002 · 完善辅助审批的风险分级与工作区安全边界

- 编号：REQ-002
- 创建时间：2026-11-01 01:23:46
- 状态：待评审
- 关联需求：无

## 需求描述
完善 aide 辅助审批能力，减少安全、任务相关操作被无差别转为手动审批的情况，尤其支持 Git 管理项目中的常见构建、测试、代码生成与受版本保护的文件修改；同时明确区分沙箱执行权限、用户任务授权与辅助审核判断。Git 仓库不是安全白名单，不得因存在 `.git` 就放行任意命令。

## 目标
- 辅助审批可判断用户明确授权范围内的低风险/可逆中风险命令，不再仅因 `rm`、`chmod` 等单词出现就机械转人工；仍对高风险、外传、凭据访问、越界及无法可靠判断的操作转人工或由既有沙箱拒绝。
- 支持对本地工作区内已读取、基线哈希有效、内容完整可审核的现有文件修改提案进行辅助审核；应用时继续使用原有版本校验、绑定路径检查、持久化与历史保护。
- 对工作区内 `.git` 元数据目录/文件增加确定性保护；不能由辅助审批放行对仓库元数据的直接破坏操作。常见只读 Git 操作及用户明确授权的常规 Git 操作仍可进入独立审核，不以仓库存在作为自动授权。
- 执行意图应尽可能列出命令/文件操作动作、目标和已知副作用；无法静态解析、可能访问网络或影响 Docker/宿主/外部服务的内容明确标为未知，并将原始内容一并审查。
- 长时间命令按现有执行超时/取消机制管理；审批不得因命令运行时间长而扩大权限。保留记录、失败关闭、取消/轮次校验和手动审批回退。

## 范围
- 调整辅助 Shell 审查策略、确定性风险门禁及 Git 元数据保护。
- 将本地、可验证版本的现有文件提案纳入辅助审查候选；排除远程、只读、符号链接/绑定边界不可靠、截断原文、基线不匹配、`.git` 目标及超出审核载荷的提案。
- 补充 shell/文件资格判断、`.git` 保护、任务授权与拒绝/边界用例的单元测试。
- 不改变 shell 执行器、Landlock/容器沙箱配置、网络隔离、插件权限、手动审批的确认语义；不将辅助审批或 Git 状态当作沙箱权限。

## 验收标准
- 普通受任务授权的构建/测试/代码生成命令不因命令中出现通用文件操作词而固定转人工；明确高风险或不可判断操作仍转人工，且 `shellBlocked`、私有区、read-only、SSH/交互限制仍不可由辅助审批覆盖。
- 对 `.git` 元数据的直接删除、覆盖、权限更改等操作必须在独立模型批准后仍被确定性拒绝自动放行；对安全的 Git 检查命令不因 Git 关键词被拒绝。
- 本地现有文件提案仅在目标、基线哈希、实际版本、完整审核内容和路径绑定均可核验时进入辅助审查；任何变化都不自动应用；版本/保存失败维持失败关闭。
- 远程、只读、越界、无基线、内容截断、`.git` 目标或未知绑定不自动应用。
- 测试覆盖允许/转人工/硬拒绝和竞态/变更保持边界；执行可用的格式、测试和差异检查，准确报告未运行项。
- 不声称 Landlock 或外层 Docker 已提供网络隔离/插件隔离；意图和 UI 明示执行器的外部副作用仍需按原始命令核对。

## 技术考量
- 审批三层：确定性沙箱/路径策略定义可执行上限，真实用户请求定义任务授权，辅助审核器只判断本次操作是否落在授权与风险范围内；不得互相覆盖。
- 删除/权限操作由完整命令、明确目标与任务授权判定，未知目标或动态脚本转人工；不要采用危险词表作为唯一资格判定。
- Git 仓库检测仅提供审核上下文，不作为放行证明；`.git` 可为目录或 worktree 指针文件，需保护精确路径分量和可能触及元数据的操作。
- 文件自动应用仅面向本地当前工作区，且沿用 `applyTaskGuarded` 和哈希校验；审核通过前提案不能写入。
- 当前 Landlock 约束文件范围但没有网络隔离，插件也不在该 shell 沙箱内；容器部署只作为额外边界，不能据此假设容器配置/宿主挂载一定安全。
