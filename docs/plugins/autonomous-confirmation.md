# 自主执行与必要询问

每轮聊天和工作流的最新指令携带统一执行策略。用户在任务范围内的既有授权持续有效；可逆的常规步骤、只读查询和沿来源链接查证按合理默认值继续，不以阶段完成为理由再次确认。

真正阻塞的关键输入、用户明确设置的审核关卡、超出授权范围的操作需要询问。模型应调用 `ask_user`，由现有询问卡片显示问题与选项；单选使用 2 至 3 个实际方案，推荐项在前；输入型用于无合理选项的关键参数；确认型说明具体操作与影响。回答后继续执行。

服务端规范空选项：确认型补标准确认/调整选项，缺少选项的单选或多选降为输入型，避免无法回答的卡片。不会自动选择答案或把超时当作授权。插件操作确认、网站范围和命令审批仍沿用既有执行门禁。

对“要我继续”“请补充最关键”等明确索取回答却没有调用工具的正文，服务端最多追加一轮纠正，让模型继续执行或调用询问卡片。纠正次数有上限，不自动替用户回答；流式显示期间可能短暂出现原正文。

对末尾“我这就用”等明确承诺立即继续读取却没有工具调用的回复，服务端最多追加两轮纠正，要求执行已承诺的只读步骤或报告具体阻塞原因。普通建议不触发继续执行；既有工具预算和权限门禁保持有效。

浏览器读取器对导航造成的短暂上下文失效最多重试两次，并优先返回 PDF 链接（最多300个去重链接），避免导航栏挤掉文档入口。`browser_read` 可直接读取允许域名中的公开 PDF 文本，逐次校验重定向域名，限制32 MiB、每次200页/30000字符、解析60秒；返回总页数、起始页、已读页数、下一页和截断标记。`fromPage` 可继续长文档。使用无用户登录信息的获取和 pypdf 的 crypto 依赖；不写入用户工作目录，不支持扫描件 OCR，不索取 PDF 密码。

部署镜像使用 `pypdf[crypto]==6.19.0`；离线构建应先按 `scripts/prebuild-wheels.sh` 准备含加密依赖的 wheelhouse。单次失败不得推断其他官网入口已经查尽，也不得把“可/继续”理解成用户承诺上传文件。

这项修改引导模型的行为，不能保证模型每次都正确判断是否需要询问，也不能覆盖所有自然语言问法。PDF提取结果有上限；未实际读取的页数不得声称已完整查证。
