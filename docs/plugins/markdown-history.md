# Markdown 历史版本

## 状态与原文编辑

`markdown-history` 为原生保存服务支持的插件。新版镜像内置安装，首次注册默认启用；已保存的启用／停用状态及设置保持不变。设置 → 文件查看与渲染中的“Markdown 历史版本追踪”读取 `/api/plugins` 并更新服务端插件状态，不使用浏览器本地偏好。插件设置 `trackEmbedded` 默认为 `true`，可通过插件设置调整。

AI 上下文读取已持久化的插件状态：启用后先读现有 MD，再向原路径提交修改，不为备份创建副本；用户明确要求复制时仍尊重其要求。该指引不取消审批，也不保证模型永远遵从。`markdown_history` 工具可查询状态、列表与版本原文；`asset` 可读取指定版本的资源快照（base64）。停用后已有历史仍可通过文件界面查看。

## 保存与去重

- 原生手动保存、自动保存、工作区文件提案应用、绑定系统文档发布及可写来源保存接入统一钩子；支持 `.md` / `.markdown`。
- 第一次保存现有文档先归档旧正文及资源，再记录有变化的新状态。新建文档只有初始版本。
- SHA-256 内容寻址：重复正文／资源复用对象；当前正文与资源指纹均不变时，不追加版本。恢复旧正文后再保存属于一次实际变化，追加新版本但复用已存在对象。
- 保存前归档失败会阻止写入；保存后归档失败返回“文件已保存，但历史归档失败”，不虚报成功、不自动重复覆盖。
- 可写引用保存也验证读取时 hash；工作区和来源身份隔离，切换路径／服务器不会混用历史。
- AI 提案保存的慢 I/O 不持有应用状态锁；操作完成后再次校验提案，取消不被错误标记为完成。

## 嵌入资源

索引 Markdown 行内图片／链接、引用式定义及 HTML 的 `src` / `href`，解析同一工作区／来源内的相对路径。已归档父文档的资源通过 Aide 写入时，同步记录父 Markdown 的新状态，即使正文不变。draw.io XML、SVG 内嵌图表与 data URI 的变更由其原始字节指纹体现。

正文保存也重新比较引用资源，可发现两次保存之间外部程序更新的资源。直接 shell 或外部程序写入不触发保存钩子；启用时下一次 Aide 保存或打开历史列表会重新检查正文与直接引用资源并归档当前变化，无法补录从未归档的中间版本。当前没有后台定时监测。未索引的父文档不会因资源写入自动建立历史。

每个文档最多扫描 64 项直接引用，资源合计最多 32 MiB；超过时明确报错。无法读取的相对资源标记为 `unavailable`，不声称已备份。外部 URL、绝对路径、越界路径、远程网页资源不下载；不递归扫描被链接文档的下级资源。代码围栏中的示例引用忽略；复杂 Markdown 语法的引用识别仍有边界。

## 查看与存储

文件编辑器／独立文件页中的“历史版本”提供版本选择、历史／当前正文对比、资源指纹与资源快照下载。查看不会替换编辑正文。启用追踪且目标可写时，可先对比恢复范围，再显式确认恢复正文与该版本已归档的直接引用资源；也可取消勾选，只恢复正文。存在未保存草稿或进行中的保存时先处理草稿，恢复请求期间编辑器暂时只读。未归档资源会阻止整版恢复，不能声称附件已备份。恢复保留当前其他资源，不删除共享文件。启用时打开列表会在服务数据中归档观察到的实际变化；停用时不记录。当前文件检查失败仍可查看已有版本，界面明确显示失败。锁定会关闭历史窗口，未确定锁态或已锁定时不能打开；解锁后可重新打开。列表返回最近 200 条及总数，旧版本可按编号通过 API 查询。读取正文／附件快照验证 SHA-256；损坏对象或非法摘要拒绝返回。工作区读取固定当前本地路径或 SSH 会话代际，避免配置切换后读取另一工作区；SSH 系统文档读取也固定路径和代际。

接口：`GET /api/file/history`，查询字段 `path`、`source`、`workspaceId`、`revision`、`asset`。不带 `path` 查询服务端状态；指定 `asset` 须同时指定版本编号。沿用现有鉴权。

恢复预览：`GET /api/file/history/restore?path=...&revision=...&assets=1`，返回来源身份与逐项 before/after SHA-256（不存在为 `missing`）。恢复：`POST /api/file/history/restore`，请求 `path/source/workspaceId/revision/assets/identity/expected`；身份或任一预期指纹不一致返回 409。服务器从已验证的历史对象读取路径与字节，不接受客户端恢复字节。

恢复前归档当前正文与引用，并将所有将被覆盖文件存入对象库；操作记录保存在身份目录的 `restores/<操作编号>.json`，包含前后摘要、已应用/已读回验证项目、pending 路径和错误。每个文件写入后读回校验，成功恢复形成新的实际变更版本。多文件恢复不是一个文件系统事务：资源先写、正文最后写；失败或连接中断会报告操作编号与已写文件，保留记录，不自动重试 SSH 写入。进程异常退出可能留下 `writing/pending`，须检查当前字节后判断结果；当前尚无操作记录管理或一键撤销界面。外部程序仍可能在检查与写入之间修改文件，指纹检查不等价于跨程序文件锁。

历史保存在服务数据目录 `markdown-history/<身份摘要>/`，元数据原子替换、正文和资源按 SHA-256 存储，文件权限 0600。当前不自动删除历史，应将该目录纳入服务数据备份；这不是 Git 提交或远端备份。镜像升级／服务数据卷丢失的边界与其他服务数据相同。

### 单文档历史备份与统计

历史窗口提供“历史存储统计”和“下载完整历史备份”。统计为当前文档全部已索引版本及其引用的去重对象字节数，不是整个服务数据卷的占用量，不包括其他文档、未引用旧对象及恢复操作记录。统计不校验对象摘要；下载时逐个校验，缺失或损坏对象拒绝导出，不返回部分ZIP。已标为 `unavailable` 的资源不会补录；清单及界面显示其记录数。

`GET /api/file/history/backup` 沿用鉴权，参数为 `path/source/workspaceId`；默认返回 `versions/objects/objectBytes/unavailableAssets/limitBytes/integrityChecked`。`archive=1` 返回ZIP的base64、文件名和归档字节数，浏览器直接下载。ZIP包含 `manifest.json`（格式 `aide-markdown-history`、schema 1、身份摘要、全部版本元数据）和 `objects/<SHA-256>`，共享对象只写一次。它不受历史列表最近200条窗口限制，不读当前文档或远端资源，不改变历史或源文件。请求固定来源/工作区身份；过期工作区返回409。

单次归档的清单与未压缩对象总量最多64 MiB；超量明确拒绝，须通过服务数据卷备份。此功能是导出已有归档，不是导入、跨设备自动恢复或服务数据灾备；恢复操作记录和恢复前专用备份仍须随整个服务数据卷备份。当前没有自动保留期、垃圾回收或删除管理。
