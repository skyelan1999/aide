# 独立文件草稿并行候选

## 目标

将明确独立的既有文件修改从“多个分析草稿，再由主模型重新生成全部内容”改为“工作者生成限定文件的完整内容，主执行器通过普通 write_file 登记提案，再作最终说明”。写入磁盘、审批和应用时的版本校验继续由既有主流程负责。此候选不等于十分钟到一分钟性能验收通过。

## 资格与原文

只处理用户明确独立的分项：每项恰好出现一个支持的相对代码文件路径，目标互不重复，任务有修改意图，且不是用户要求不调用工具的纯草案。本地任务必须绑定当前工作区身份与修订，无既存待审提案，write_file 未被禁用，且没有相关工具钩子需要特殊处理。其他类型、远程来源、复杂依赖或不满足资格的项目沿用普通执行流程。

初次尚无完整读取快照时由主任务先读文件，不启动盲目拟稿。每个原文快照必须有完整哈希，且 Before 的内容哈希等于基准哈希；被截断的预览不能充当完整替换原文。当前候选对这类文件回到普通执行流程，后续全量原文绑定仍需扩展。完整原文固定在每个工作者的末条任务消息中，避免历史压缩后只凭摘要重建源码；模型窗口仍按实际输入检查。文件正文是不可信资料，不能改变任务授权。

## 登记、审批与恢复

工作者没有工具，只返回严格 JSON 的 path/content。整批先验证数量、唯一目标、状态、用户范围、完整 JSON 和非空内容，再复核读取快照及工具资格。未知字段、来源/命令载荷、改路径、旧范围、预览截断或不完整批次均不能走快速登记。

主执行器按顺序通过 executeToolCall(write_file) 登记；复用任务禁用工具、工作区/恢复、原文版本、绑定目录和原生编辑器等检查，保留前后钩子、意图、执行检查点、审计及普通工具调用预算。工作者不执行命令、不批准文件，也不直接修改磁盘。工具结果以正常 assistant/tool 协议返回主模型，主模型只作用户要求的最终说明，审批仍在其后。部分失败或取消时保留实际提案及结果，对未执行调用补齐明确回执；不得伪造全部成功。DraftPath 与累计 DraftProposals 是可选诊断字段。

## 证据

HTTP fixture/race 覆盖先读后拟稿、无磁盘预写、审批后应用、外部修改导致409、整批错误不登记、越界路径/未知字段、工作区变化、禁用工具、钩子、预算、旧用户范围、截断预览和取消后的协议闭合。调度/扇出/续跑/ROS2文档/端到端 fixture 回归通过。

Luna/high 小函数 coding 基准题目未改变，隐藏回归10/10通过：配对1x任务27.794s/含应用测试27.978s，10x任务22.228s/含应用测试22.447s；固定完整原文后的10x复测任务19.458s/含应用测试19.658s。单组配对约1.25x，不以旧的较慢1x样本推导更大加速比。首次配对预检EOF失败，无性能样本。原文固定后的10x复测仍通过全部隐藏测试。最新纯诊断计数字段加入后有本地race证据，尚无新的live计数快照。
