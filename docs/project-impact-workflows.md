# 变更影响与分阶段业务流程

这是 2026-11-13 的源码能力，基于现有知识星图、任务规划、插件工具、文件审批和[目标验收](project-goals-knowledge.md)。**已发布的 v0.1.19.0-RC2 包不包含这些增补**。本轮不自动升级运行实例、安装插件或执行发布。[English](en/project-impact-workflows.md)。

## 第一次使用，从这里开始

选择正确项目和会话，打开 **轨迹 → 任务与规划**。

- 想知道“一个参数改了，还要检查哪些文件”：展开 **需求变更影响分析**。
- 想按步骤完成一次软件维护或工程交付：展开 **可复用业务流程**。
- 已经建立过流程：先看面板上的阶段进度和“下一步”提示，点击当前阶段的主按钮。无需重新建立一份流程。

空会话也能使用。输入草稿按当前页面的项目/会话隔离保留；刷新整个页面或关闭页面不会持久保存未提交草稿。

## 查找需求变更的影响

1. 写清这次改什么，例如“设计压力从 10 调整到 12 MPa，要核对计算与报告”。
2. 在文件列表搜索并勾选**直接改动**的文件。需要多个起点时可以继续搜索和勾选。找不到文件，先刷新；手动路径在折叠的补充入口内，文件仍须出现在当前工作区索引中。
3. 点击“分析并保存影响清单”。展开结果，查看文件之间的关系路径、原始关系方向、定位和证据节选。
4. 逐项检查并选择分类：**必须修改**表示确认要改；**需要复核**表示还不确定；**暂不受影响**应有检查依据。系统默认把直接起点标为必须修改，相关候选标为需要复核，均是待复核建议。
5. 处理后填写实际依据，标为已处理；无法继续时标为受阻并写原因。修改复核保留最近十条旧记录。导出影响清单可保存分析、关系与观察记录。

系统把既有文件/符号关系归并到文件层级，在不使用目录包含关系的情况下，沿静态关系双向查找最多三跳、80 个文件。原始箭头、关系等级和证据不因反向遍历而改变。文件选择列表最多 16,000 条/1 MiB 路径，一次显示四十个匹配项。起点最多八个，每会话最多二十份分析；说明和观察各最多 2,000 字。每会话影响记录 JSON 上限 2 MiB，达到数量或体积上限后，导出留存并在新会话继续，导出本身不清空记录。

**未被列出不等于不受影响**。代码解析、文档前缀、二进制仅名称、可见来源、渐进索引与读取预算继续生效；分析不是工程计算器或运行时追踪。图纸、计算或报告只有被索引且存在已知关系时才可能成为候选。索引未覆盖、关系截断及读取失败会保留提示；不把搜索不到作为不受影响的证明。

分析绑定项目和文件/符号索引版本。文件内容、来源身份、关系或覆盖变化后，旧分析保留为历史，拒绝继续写复核，应重新分析。普通会话消息和正常刷新计数不构成文件变化。远程缓存仍遵守原索引缓存策略，不是实时监控磁盘、客户 SSH 或外部系统。

## 按业务流程交付

1. 选择“软件维护”或“工程交付”，填写具体目标与范围。
2. 展开阶段可预览交付物和验收标准；只有需要专业工具时，才展开插件配置。按插件名称或功能搜索并勾选，通常不需要知道工具编号。不选也能建立流程，执行仍沿用现有工具开关与审批。
3. 点击“建立分阶段目标”。会建立五个普通规划目标，显示已验收数量、当前阶段和下一步，并定位第一阶段。
4. 点击“开始本阶段”。模型和插件沿既有执行通道工作；文件提案仍需按原策略审批。
5. 执行后先核对实际成果，再在目标里逐项记录验收。全部通过才解锁下一阶段。可以展开“阶段输入与来源”查看前置执行、文本、文件摘要和工具回执。
6. 后续阶段失败时，前面已验收的成果保留。在当前阶段处理缺口并重新执行；暂停任务可从原执行记录核查后继续。不确定外部效果必须先使用现有恢复审查入口核查，不能通过重发阶段自动重放。

| 场景 | 五个阶段 |
| --- | --- |
| 软件维护 | 理解问题 → 复现与影响分析 → 实现修改 → 回归验证 → 审查与交付 |
| 工程交付 | 核对工程资料 → 计算与分析 → 生成报告或图纸 → 校核成果 → 修订与交付 |

每阶段都有交付物、两项可编辑的验收条件和前置依赖。模板不会自动证明计算正确、测试通过、文件保存或外部 PR/发布成功，也不会代替用户签收。专业能力依赖实际安装、启用和配置的插件及模型。既有 PW 可视化工作流和签名运行时保持原能力与权限边界；本页场景通过普通规划/插件执行复用业务阶段，不修改其签名引擎。

选用的专业工具绑定创建或配置时的插件版本/工具定义；阶段开始和该工具调用时重查可用性。没有该工具的实际回执，不能完成验收；出现回执也不自动证明结果正确。工具被停用或升级后，先核对插件，在该目标的“配置阶段插件工具”重新选择并保存。改变配置须重新执行本阶段，并使依赖它的旧签收失效。

下一阶段接收的是**已验收前置执行快照**：来源目标/运行、最终已完成步骤的有界文本、已应用文件的提案内容摘要，以及工具回执摘要。最多八份直接输入；每份保留 4,000 字正文、40 个文件摘要和十份各 1,000 字工具摘要，超出会标记截断。摘要不是对当前磁盘的重新核验，遗漏部分应回读原文件或原执行。

前置验收、条件或执行改变后，下游旧结果会被标为输入失效，不能沿用旧签收；即使后来把前置重新标为通过，也须重新执行后续阶段。完成步骤不会因为另一步失败而自动重做。保留原规划导出/导入：导入重新映射任务与流程身份、依赖和工作区，清空运行/签收，并把所选工具绑定到导入时当前可用定义。编辑导出的规划可以复用阶段内容；流程必须保留验收条件，不能缺失依赖或成环。

## 模型可读取什么

- `change_impact` 只读当前会话、当前项目的影响分析。先取摘要，再用 `analysisId/snapshot/offset` 分页；每页最多十项、约 24 KiB 记录 JSON，观察节选为 400 字。它不能改分类或签收，返回的是历史参考，不保证来源此刻仍新鲜。
- `workflow_inputs` 读取本轮绑定的前置快照。用 `inputIndex` 选择输入，按返回的 `nextInputIndex`、`nextOutputOffset`、`nextFileOffset`、`nextReceiptOffset` 继续。每页至多 1,000 字正文、五个文件、两份工具摘要，总结果上限 64 KiB。存储已截断的内容不能靠分页恢复，需要回读原记录。
- 两个工具均在现有工具开关中；历史资料不会成为新授权。当前目标条件、最近影响清单及前置摘要进入既有规划上下文，且明确标注证据边界。

## 接口与存储

| 接口 | 行为 |
| --- | --- |
| `GET /api/sessions/{id}/impacts` | 当前项目分析、是否过期/处理完成、可选文件列表、当前索引版本与写入快照 |
| `POST /api/sessions/{id}/impacts` | `workspaceId/snapshot` 加 `action:analyze`、`change/paths`；或 `action:review`、`id/itemId/classification/state/note` |
| `GET /api/sessions/{id}/plan/flows?language=en` | 场景预览、可用插件工具及可读名称、规划快照 |
| `POST /api/sessions/{id}/plan/flows` | `workspaceId/snapshot/recipe/brief/language/stageTools` 建立五个阶段；`recipe` 为 `software/engineering` |
| 同上，`action:configure` | `workspaceId/snapshot/itemId/tools` 明确修改某阶段工具；运行或待审批期间拒绝修改 |
| 既有规划导出/导入、执行与验收接口 | 保存/重映射流程元数据，沿用原审批和签收 |

影响记录扩展已有会话 JSON 的 `impacts`；阶段元数据扩展 `PlanItem.flow`，输入快照保存在 `Task.flowInputs/flowTools`。没有新增调度器、模型账号或项目记忆存储。接口沿用已有认证/同源规则，新增接口锁屏时拒绝访问，更新通过快照检查防止覆盖并发修改；不构成跨进程数据库事务。

升级前备份会话与项目缓存。旧程序可能丢弃新增 JSON 字段，回退前保留完整数据副本。源码验证、浏览器检查、安装包发布和生产部署分别记录，见[任务账本](tasks/project-impact-workflows-20261113.json)。
