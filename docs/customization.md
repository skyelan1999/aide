# 按专业场景扩展 aide

aide = AI + IDE，主旨是让人更专注于专业工作。本文介绍需要扩展时的开发方法，不是产品的使用前提。开发 AI 可以复用已有能力，按明确的场景和验收标准完成二次开发；统一 Agent 路由管理这一过程。

## 两种起点

- **先体验**：从 GitHub Release 下载 Docker 归档，校验并导入，按 [镜像说明](../docker-images/README.md) 启动。
- **开始定制**：Fork/克隆源码，安装 Git、Docker 和开发检查所需的 Python 3 / Node.js，按 [Agent 路由](agent/WORKFLOW.md) 创建任务。镜像是运行交付物，不包含完整开发仓库。

## 可复制给 AI 的任务模板

```text
请基于 aide 定制我的工作台。先读取 AGENTS.md 与 docs/agent/WORKFLOW.md，
确认当前分支、已有改动和客户端能力，创建任务记录，不覆盖其他人的工作。
场景：[例如技术资料分析 / 软件研发 / 内部流程]
用户与目标：[谁使用，最终要完成什么]
输入资料：[目录、文件格式、远程来源及允许访问范围]
需要的能力：[现有能力如何复用，哪些需要新增]
界面要求：[导航、主题、输出形式、桌面或窄屏]
模型与工具：[提供商、模型、外部服务；密钥另行配置，不写入源码]
验收标准：[可重现的输入、操作、预期结果]
部署目标：[操作系统、CPU 架构、挂载路径、数据保留要求]
预算和权限：[模型调用预算；可否推送、发布、替换现有服务]
先给出范围与实现方案，再按路由实现、测试、更新文档与打包。
没有实际验证的功能明确标注；未经授权不发布或调用付费模型。
```

```bash
python3 scripts/agent-route.py start my-aide --request "我的场景与验收要求"
python3 scripts/agent-route.py prompt codex  # 可换 claude/deepseek/doubao/workbuddy
```

## 扩展位置

| 定制内容 | 起点 | 验收重点 |
| --- | --- | --- |
| 外观、布局、菜单 | internal/server/web | 实际浏览器、明暗主题、窄屏、键盘 |
| 模型策略和参数 | 应用模型/策略设置；现行架构文档 | 真正选中模型、预算和失败提示 |
| 工具与插件 | plugins、docs/plugin-protocol.md | 输入校验、提案审批、错误与结果回传 |
| API、来源与工作流 | internal/server | 权限、并发、持久化、取消与重启 |
| 运行工具链 | Dockerfile | 目标架构、非 root、健康检查和镜像重建 |

配置和插件可以复用现有能力；完整 MCP、PTY、流式输出等缺失能力仍需实现，不能因为登记了来源就宣称接入成功。插件执行可信代码，不提供独立安全沙箱。

## 交付与升级

完成文档与检查后，授权发布者使用现有 version.sh 升版，构建带版本/SHA 的镜像，保存到 docker-images 并上传 Release；归档不进 Git。见 [交接手册](../HANDOVER.md)。同一次交付保留源码 tag、镜像校验和、测试记录和回滚说明。定制分支升级上游时先合并并验证，不直接覆盖业务数据。

仓库工作流是协作约定和检查入口，不保证每个外部 AI 自动加载。首次接入必须确认 AI 读到了规则；无法访问本地文件的客户端需要人工提供内容。各客户端差异见 [适配说明](agent/ADAPTERS.md)。
