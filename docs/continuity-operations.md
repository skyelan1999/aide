# 连续工作操作、排障与交付手册

核对日期：2026-10-17。面向使用者、验收者与接手开发者；当前状态和12项工作流见[总交接](continuity-handoff.md)，本手册给出操作顺序及结果解释。本文的检查步骤是复测方法，只有链接的收据代表已经执行；不能把步骤本身算成新的验收。Windows由用户测试，真实向量测试暂缓。

## 1. 先确定正在操作哪一套 AIDE

当前开发目录为 `/Volumes/MY PASSPORT/aide_ws/aide`。旧iCloud目录的启动器会操作另一份目录，不能仅凭页面标题判断实例。每次记录启动器绝对路径、最终HTTPS地址、工作区来源、产品构建提交和镜像ID。

在当前仓库执行以下只读检查；Docker未启动时部分命令失败属于环境结果，不要为文档检查自动启动或重置Docker。

```bash
pwd
git status --short --branch
git log -1 --format='%H %s'
bash scripts/version.sh show
bash scripts/aide.sh source-sha
bash scripts/aide.sh status
docker ps -a --format '{{.Names}} | {{.Image}} | {{.Status}}'
docker stats --no-stream
df -h .
```

`git log`是检出提交；`source-sha`是产品构建输入摘要；full收据还覆盖流程和构建配置；Docker ID才指向实际镜像。文档提交可以改变Git HEAD而不改变产品源码指纹。当前产品提交75278e2f、源码406b1984、候选ARM5dc1／AMD14cb与公开旧07c包的完整身份均集中在[总交接身份表](continuity-handoff.md#1-先确认四个不同身份)，避免在多份操作手册重复维护摘要。

## 2. 从完整包导入并启动

### 2.1 选择与检查

1. 先确认Docker Engine架构：`docker info --format '{{.Architecture}}'`。ARM64选linux-arm64包，x86_64／amd64选linux-amd64包；操作系统名称不决定CPU架构。
2. 使用包含镜像的 `*-offline.tar.gz` 完整包。只含脚本的源码下载或启动器ZIP不等于完整包。
3. macOS／Linux可用 `shasum -a 256 '/实际路径/完整包.tar.gz'` 核对外层摘要；Windows可用 `Get-FileHash -Algorithm SHA256 '实际路径\完整包.tar.gz'`。文件名和预期摘要从同一交付记录取得，摘要不同即停止。
4. 先列包内容 `tar -tzf '/实际路径/完整包.tar.gz'`，确认来自可信交付，再解压到新的独立目录。不要覆盖仍在运行的旧目录或把陌生包解压到工作区根目录。
5. 完整包通常包含 `aide-offline/BUILD.txt`、`.aide-image`、启动／停止／清缓存脚本、`compose.yaml`、`docker-images/aide-local.tar` 及内层 `SHA256SUMS`。进入解压后的 `aide-offline`，用 `cat BUILD.txt` 核对平台、源码和镜像身份；不要输出含凭据的运行配置。
6. 在包内 `docker-images` 目录执行 `shasum -a 256 -c SHA256SUMS`。外层摘要验证传输文件，内层摘要验证镜像tar；两者不能证明应用可运行。

当前406两包在开发机已实际导入和分范围运行，但公开上传尚未完成，接收端不能假设Release已有这两个新文件。准确大小／SHA及限制见[406交付报告](reviews/2026-10-17/continuity-runtime-406.md)和[机器收据](reviews/2026-10-17/continuity-runtime-406-proof.json)。

### 2.2 启动与确认

使用解压目录自己的 `start.command`（macOS）、`start.bat`／`start.ps1`（Windows）或 `start.sh`（Linux）。启动器负责本地镜像导入和实例初始化，不要先随意改镜像别名、跳过架构守卫或复制旧 `.env` 覆盖新包。

按以下层次分别确认：

| 层次 | 成功依据 | 尚不能说明 |
| --- | --- | --- |
| 镜像导入 | 启动日志明确本地导入成功，实际镜像ID／平台匹配BUILD | 服务健康或数据迁移正确 |
| 服务启动 | 启动器输出“aide 已就绪”与实际端口，容器健康检查通过 | 浏览器解锁及业务功能通过 |
| 页面进入 | 实际地址打开，正常解锁／进入目标工作区 | 保存、模型或CAD成功 |
| 数据读写 | 写入专用测试内容，回读、刷新及重启后精确一致 | 所有工作区或所有设备都通过 |
| 交付完成 | 公开附件校验、接收端导入与所需环境验收分别有收据 | 生产已替换，除非另有部署记录 |

首次新证书告警按系统与客户端要求由用户确认。自动打开失败时先保留启动日志、检查实际地址；不要反复双击堆叠启动进程和页面。现有测试页可设置 `AIDE_OPEN_BROWSER=0` 后运行原启动器并复用该页。只关闭测试者创建的页面，保留用户页面与草稿。

### 2.3 停止与缓存清理

先在对应目录预览：

```bash
bash scripts/aide-maintenance.sh stop --dry-run
bash scripts/aide-maintenance.sh clean-cache --dry-run
```

确认实例后，macOS可用该目录 `stop.command`；其他平台用对应stop脚本。停止保留数据与镜像，运行中的任务会受到影响。源码中的stop按Compose工作目录及aide／cad服务标签寻找容器；迁移过的旧容器可能不匹配，不等于可以删除全部Docker容器。

`clean-docker-cache.command`及其他平台对应脚本清的是当前Engine默认builder的未使用构建缓存，**这个范围由多个项目共享**，不是仅AIDE缓存。容器、镜像、卷、会话、设置、工作区和离线包保留；清缓存后下一次源码构建可能更慢。检查资源前不要先执行清理，以免丢失原因证据。Docker不可用时维护脚本报错且不主动启动它。

## 3. 常见故障的判断顺序

| 现象／原始提示 | 先检查什么 | 下一步与停止条件 |
| --- | --- | --- |
| 双击后不弹主页 | 是否真的出现“aide 已就绪”；macOS启动器打印的 `.agent-state/startup/start-*.log` 路径；地址和端口 | 未就绪先解决启动错误；已就绪再检查自动打开与浏览器。不能把无窗口直接判断为页面渲染故障 |
| `Native CAD runtime is missing` | 当前是否源码构建模式、完整包是否缺失、平台是否匹配 | 普通使用优先使用校验后的完整包；不要先反复在线编译CAD。本地依赖重建另按[离线说明](../docker/OFFLINE.md)评估 |
| `Multiple legacy containers ... refuse ambiguous import` | 旧容器Compose项目、工作目录、状态和数据挂载，确认哪些属于旧实例 | 这是迁移歧义保护，不是要求清空Docker；先识别数据归属和备份，再处理准确旧实例 |
| 重新启动开始长时间编译 | 启动日志的source-sha对比、预编译清单平台和包身份 | 源码与镜像不同会触发构建；普通文档变化不应被误认为产品变化。仅pull源码不会自动获得尚未上传的新镜像 |
| 锁屏后提示状态已变化 | 多标签／其他实例、实际地址、请求时间和服务重启；保留错误文字 | 在一个页刷新后重新确认状态；仍失败记录复现，不循环重置密码，不删除鉴权文件或保险库 |
| 推理强度切换后又变回 | 当前会话ID、选值、保存反馈、切回和刷新后的值；是否409版本冲突 | 409先重读，不覆盖其他会话；分清会话选值与全局默认，按下节复测 |
| 成果总数不更新／编号不对 | 运行镜像是否含406修复；总览／单轮详情；已加载数量与总轮数 | 外部事件刷新已在当前候选通过；窗口相对编号仍是开放问题，不把两者混为同一个结论 |
| 星图空白或“尚无索引节点” | 来源真实路径、任务进度、权限、覆盖／预算／节点上限、是否仍扫描 | 先用小范围唯一标记确认可检索和预览，再扩范围。保留已有图，不删整个索引或会话来重试 |
| 切到后台连线似乎停止 | 记下切后台和返回时间，核对服务器扫描记录与节点／边计数 | UI动画与后台扫描分别观察；不要仅凭点击后重绘推断扫描实际暂停 |
| Docker `Engine stopping`／无响应 | Docker API、磁盘、内存；记录容器与卷能否检查 | 停止新增构建和重复启动。强杀后台、删除虚拟磁盘是另一次明确授权操作，不在清缓存脚本范围 |
| 内存或磁盘压力 | `docker stats --no-stream`、`docker system df`、宿主资源和页面数 | 串行重型验证、复用页面和已合格镜像；Docker.raw含Engine数据，不和内部镜像／缓存统计重复相加 |
| Release显示 `Upload failed`／通用处理错误 | 附件是否真的进入uploaded、文件字节数／摘要和公开下载URL | 保留失败与旧包；当前406换内置盘和唯一文件名仍失败，原因未确证，不能写成网络／文件系统已定位 |

仅在本地查看完整日志；公开提交脱敏后的错误、时间、版本、摘要与最小复现。不要发送模型密钥、access-token、保险库、会话正文或完整环境变量。

## 4. 可重复的功能验收

每个场景先建立自己的临时工作区／文件／会话并记下名称，避免改真实资料；测试前后记录内容和身份，失败保留现场。以下步骤不需要默认调用收费模型。

### 4.1 会话推理强度与并发隔离

1. 创建A、B两个会话，在会话策略中分别选不同模型／推理强度；记录保存反馈。
2. A、B交替切换，再刷新页面：各自显示自己的配置，全局默认不被当作会话值回写。
3. 验收端可同时写A、B，分别回读API和磁盘；单会话旧版本写入应409，不能覆盖新值。
4. 用原始stop/start重启，重新进入A、B，确认选值和版本保留。仅页面选中不算持久化通过。

当前ARM完整包已验证10次跨会话写入、五种强度、旧版本409与实际进程重启；不含真实模型推理、原生Windows或AMD整套浏览器复测，详见[406机器收据](reviews/2026-10-17/continuity-runtime-406-proof.json)。并行倍率是调度上限，不保证每个请求都能独立拆分；规划、实际调用、工具读写调度和上下文统计需各自证据，不能用倍率选中证明并发成功。

### 4.2 成果总览与流式输出

1. 在有已完成轮次的会话打开“轨迹 → 输入与输出”，记录已加载数／总数与最新轮次。
2. 由正常任务入口触发下一轮，保持总览不点击，观察运行与完成是否自动出现；SSE重连后应重新读取当前会话。
3. 保持单轮详情时产生新活动：详情不应被新轮次替换；返回总览后应读到最新计数。
4. 关闭面板、切换会话或锁屏后，旧响应不得重新打开面板或切回原会话；解锁后重新读取。
5. 重启后确认已记录成果仍可读取。当前总览加载窗口30条时，第64轮选择器可能显示#30，记录这个缺口，不以刷新成功关闭编号问题。

[实际修复收据](reviews/2026-10-17/outcome-external-events.md)覆盖32→64、65、66与重启67。成果详情是持久化摘要；思考状态卡、逐段输出和工具执行原始回执应分别审查。`completed`表示任务终态，不等于工具命令成功、证据独立成立或成果已经发布。

### 4.3 文件草稿、保存与历史

1. 在正确来源打开专用Markdown，输入唯一文本，关闭重开并检查草稿恢复；草稿不应被自动发送。
2. 显式保存、从来源重新回读；分别验证正文、光标与滚动，不能只看编辑框尚未丢字。
3. 外部修改同一文件，触发冲突时保留双方正文和版本，审阅合并后再保存，不无限自动覆盖。
4. 在历史中选择一个含正文及引用SVG的版本，核对后恢复；回读正文与SVG，确认两者一致。
5. SSH断连后尝试恢复：具体失败原因保留、重复失败不堆卡；重连后手动重试并回读。网络恢复不应自动替用户确认整版恢复。

当前SFTP来源与SSH工作区有不同范围的直接验收，见[SSH原生报告](reviews/2026-10-17/ssh-workspace-native.md)和[恢复反馈](reviews/2026-10-17/markdown-restore-feedback.md)。自动保存与整版恢复耦合、写入中断、所有资源类型和GC实际执行仍有缺口。GC预览或取消不能记录为清理成功。

### 4.4 审批、星图与引用

审批先用无副作用的最小命令：记录命中原因、范围与到期时间，再撤销并跨会话重试。看原始执行返回，不以任务completed判断执行成功。并发旧版本写入必须拒绝，重启后已撤销规则不得复活。真实结果见[审批专项](reviews/2026-10-17/approval-cross-session-native.md)。

星图从小目录唯一标记开始，记录来源、覆盖状态、节点／边数量和时间；扫描期间保留部分图。点击引用预览，核对原文行号和摘要，再修改文件复读，旧摘要不能继续指向新正文。移除测试来源后确认旧缓存清除；20,000节点上限不代表全目录覆盖。历史比较离线时应仍保留原依据，重连的新观察不覆盖旧观察，人工关联不证明模型读过依据。证据入口见[十二项矩阵](continuity-handoff.md#2-十二项需求证据与剩余工作)。

## 5. 发布、回退与交接清单

### 5.1 开发交付必须分开记账

| 交付项 | 最低证据 | 当前记录入口 |
| --- | --- | --- |
| 源码进入main | 干净Git、提交SHA、push结果、独立远端查询 | [总交接](continuity-handoff.md)及各任务账本 |
| 精确full | 当前文件指纹、完整退出码、全部命令收据、失败后修复重跑记录 | [验证说明](verification.md) |
| 本地镜像与完整包 | 两平台同源码、镜像ID、内外摘要、实际导入／运行范围 | [406报告](reviews/2026-10-17/continuity-runtime-406.md) |
| 公开附件 | 唯一文件名、uploaded、字节数、SHA-256、准确URL | `scripts/verify_prebuilt_assets.py`只读检查 |
| 默认提升 | 两架构均合格后更新清单／摘要；变更指纹后重新full和门禁 | [统一工作流](agent/WORKFLOW.md) |
| 生产更新 | 明确实例、备份、停机影响、前后镜像、健康／鉴权／数据不变量、回退结果 | 独立部署收据；本轮没有替换生产 |

当前公开默认仍是旧07c；新406候选公开校验失败。`release-check`通过只表示所检查的默认清单和本地前提满足，不能把旧清单通过解释为新候选已公开。只读核验命令：

```bash
python3 scripts/verify_prebuilt_assets.py
python3 scripts/verify_prebuilt_assets.py .agent-state/continuity-runtime-406-20261017/prebuilt-images.candidate.tsv
```

第二条依赖开发机私有候选文件；其他设备没有该文件时应从已审核收据重新准备候选，不能把“文件不存在”改记为通过。网络／API失败保留失败，不跳过门禁。不要删除旧附件以掩盖新附件失败，也不要改写旧tag。

### 5.2 回退原则

文档错误通过准确文档提交revert；产品代码通过专用分支revert并重新验证。镜像回退选择已验证平台与ID，保持数据挂载稳定；旧镜像与新数据是否兼容需先确认。恢复数据备份是独立操作，不能在换镜像时顺带覆盖现有会话。任何回退都记录目标、前后身份、读写／鉴权检查和未恢复事项。
