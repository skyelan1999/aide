# 小鲸：统一虚拟形象与动画素材

## 当前设计

2026-10-01，按用户最新要求，aide 与小秘共用一个虚拟形象、一套素材包和显示设置。角色沿用用户参考图里的蓝发、鲸尾、圆脸、蓝眼睛、白色头饰与深蓝金边女仆裙。聊天框边缘和锁屏是主要显示位置，动作由实际任务事件驱动。

动作规格为 **16 类场景、38 套变体，每套至少 30 个不同绘制帧**。规格清单见 [virtual-avatar-scenarios.json](virtual-avatar-scenarios.json)。这表示交付要求，不代表每套素材已经通过视觉验收；实际制作、测试与 Safari 验收状态以 [任务记录](../tasks/virtual-avatar-alpha.json) 为准。

早期独立管理 aide／小秘的方案、几何 SVG 形象及四组各六姿势的样稿均已被新方案取代。旧文件可能暂留作配置兼容；不能用旧样稿的测试结论证明新 38 套素材已合格。

## 角色来源与制作方式

用户提供的「照片 4」作为角色身份参考，「照片 5」提供趴睡姿态方向。素材通过内置 `image_gen` 的参考图编辑生成，保持角色脸型、服饰、发色和鲸尾。它们是参考角色的新绘制连续姿势，不是原图逐像素抠图，也不是 Live2D 骨骼模型；本项目不据此宣称原角色归属或原创身份。

生产提示词、场景 ID、变体标签及生成来源登记在 [virtual-avatar-generation.json](virtual-avatar-generation.json)。每套独立生成，要求手臂、手掌、眼睑、嘴部、头发和尾部发生连续变化，保留准备动作、主体动作、收势与回到起始姿势。

`scripts/pack_avatar_art.cjs` 仅进行技术处理：根据透明度连通区域提取人物与附属道具、保留贴近边缘的抗锯齿像素、等比例缩放、统一人物定位、生成精灵图集与 WebP。它不插值重画人物，也不复制静止帧补够 30 帧。原始生成图的实际排布可能偏离要求，因此检测出的帧数、边界接触和相邻角色粘连警告必须人工复核。

每套审计记录包含源文件 SHA-256、帧数、不同 RGBA 帧哈希数、提取方式及警告。哈希不同只能证明像素不同，不能替代连贯性、角色一致性和动作语义的视觉检查。

## 素材目录与 manifest

内置资源目录：`internal/server/web/avatars/xiaomi-original/`。每个变体 ID 采用 `场景-v序号`，例如 `generating-v2`：

| 文件 | 用途 |
| --- | --- |
| `generating-v2-atlas.webp` | 带透明通道的精灵图集，六列、按实际帧数确定行数，单格 256 × 256 |
| `generating-v2.webp` | 可独立播放的透明动态 WebP |
| `generating-v2-poster.webp` | 单帧静态缩略图 |
| `manifest.json` | 图集、逐帧时长、循环规则、场景到变体映射 |
| `art-audit.json` | 已发布到 manifest 的素材审计摘要 |

manifest 的核心结构：

```json
{
  "version": 1,
  "poster": "idle-v1-poster.webp",
  "sheets": {
    "generating-v2": {
      "src": "generating-v2-atlas.webp",
      "columns": 6,
      "rows": 5
    }
  },
  "clips": {
    "generating-v2": {
      "sheet": "generating-v2",
      "frames": [0, 1, 2],
      "durations": [75, 75, 75],
      "loop": true
    }
  },
  "scenes": { "generating": ["generating-v2"] },
  "variants": {
    "generating-v2": {
      "scene": "generating",
      "label": "抱碗一勺勺吃 token",
      "poster": "generating-v2-poster.webp",
      "animation": "generating-v2.webp",
      "frames": 30,
      "uniqueFrames": 30
    }
  }
}
```

示例中的 `frames` 与 `durations` 数组仅展示格式；生产数据必须包含全部帧，数量与元数据一致。帧号从零开始，时长单位为毫秒，相对路径以 manifest 所在目录解析。

1 倍播放速度以实际 `durations` 为准，帧数与帧率分别记录。当前打包脚本使用普通动作 75ms、待机 95ms、睡眠 110ms 的单帧时长；这分别约为 13.3、10.5、9.1 帧/秒，并非 24 帧/秒播放。至少 30 个不同帧不能独自保证流畅或不卡顿，还需检查动作连续性、帧间节奏、解码和实际设备渲染。若后续调整节奏，应同步重新输出动态 WebP 和 manifest 并重新检查循环衔接。

独立动态 WebP 用于循环演示；聊天框和锁屏的实际循环／单次播放由 manifest 的 `loop` 控制。完成与错误可使用单次动作；暂停姿势可保持轻微循环。

打包时的中间审计和接触表放在 `.agent-state/avatar-packed/`。默认发布门禁要求至少 38 套已标记复核的可用变体、覆盖 16 场景；`--allow-partial` 仅供有明确缺口标注的局部预览。不得仅根据 `--reviewed` 标记宣称视觉验收通过。

## 设置与旧配置迁移

设置入口为「虚拟形象」，无人格切换页签。默认关闭；用户可以启停总开关、单独控制聊天框或锁屏显示、调整透明度、导入／删除／激活素材包。关闭总开关后两个显示位置均移除形象。

配置以数据结构版本 6 存于工作区数据卷 `config/virtual-avatar-settings.json`，并缓存在浏览器 `localStorage` 的 `aide.virtual-avatars.v2` 键。工作区副本让 `localhost` 更换端口或浏览器 origin 后仍保留偏好和导入素材；空白新 origin 的默认值不会覆盖已有工作区配置。首次导入时仅在新键不存在的情况下，从旧 `aide.virtual-avatars.v1` 迁移；旧数据保留。隔离存储键可防止未刷新的旧标签删掉它不认识的播放速度与补帧字段。跨标签接收变更只读取，不回写归一化结果。

```json
{
  "version": 6,
  "avatar": {
    "enabled": false,
    "chat": true,
    "lock": true,
    "opacity": 100,
    "playbackRate": 1,
    "smoothFrames": true,
    "activePack": "builtin-whale",
    "packs": []
  }
}
```

迁移规则：

- v1 的单图列表及 v2–v5 的双方素材包合并到 `avatar`。
- 相同内容的自定义包去重；同 ID 不同内容的包重命名保留，不覆盖原素材。
- 两套旧内置包合并为 `builtin-whale`；两边均已删除时不会重新添加。
- 优先沿用已启用且使用自定义包的一方，其次沿用已启用的一方；旧偏好在 `migration.preferences` 中保留。
- 任一旧角色已启用则保持启用；显示位置合并已启用角色的选择，透明度和激活包沿用优先配置。
- v6 内置包元数据可按 `revision` 更新；只更新仍存在的内置条目，自定义包、启停、透明度、激活包与删除状态保持。

内置条目只引用一个 manifest。素材包列表按实际 manifest 统计场景与动作，最多显示八张延迟加载的静态 poster，不同时播放全部动作缩略图。

自定义包支持 PNG、JPG、动态 WebP、GIF；最多 48 个文件，每个不超过 800KB，浏览器存储预估总上限 3.5MB。文件名用场景 ID，末尾可加 `-v1`、`-v2`、`-v3`，如 `sleeping-v2.webp`；不匹配的文件归为待机。旧 `eating`、`working`、`done`、`tantrum` 文件名仍映射到对应新场景。导入图片只保存在当前浏览器，不上传服务端。

用户导入的普通动态图通过浏览器原生图片播放，没有图集的帧元数据检查；不能据此保证至少 30 帧。内置帧播放器的暂停、预解码和逐帧验收能力不应套用于这类导入图片。

## 播放速度倍率

设置 → 虚拟形象提供数值输入“播放速度”，范围 0.25–4 倍，默认 1 倍；0.5 为半速，2 为双倍速，支持小数并可一键恢复 1 倍。有效输入立即作用于聊天框、锁屏与设置预览，保留当前帧和播放进度，不重新加载素材。倍率保存在统一配置 `avatar.playbackRate`；历史配置缺失该字段时补为 1，跨当前版本标签页同步并在刷新后保留。空值、无效或越界输入不会覆盖已保存倍率。

倍率通过播放器时钟缩放帧时间，不调用模型、不影响 token 统计。慢速播放时，场景内轮换等待时间至少覆盖当前倍率下的一次完整动作。后台、离屏与减少动态效果继续遵守暂停策略。倍率适用于内置 manifest 帧动画；导入的 GIF/动态 WebP 由浏览器原生图片播放器处理，保持文件自身速度，设置页会禁用倍率输入并说明。

## 自动平滑补帧

设置 → 虚拟形象新增“自动平滑补帧”，默认开启；保留形象总开关原有状态。配置字段为 `avatar.smoothFrames`，聊天框、锁屏与设置预览共用，可即时关闭对比，刷新后保留，不触发模型请求或增加 token 消耗。

播放器根据原始帧时长和播放倍率，在相邻原画之间按浏览器绘制节奏计算混合权重，通过 Canvas 预乘透明度加权生成显示用中间画面。它不会复制素材充当新原画，也不会改变动作总时长。关闭后恢复按原始帧时长换帧；减少动态效果、后台和离屏暂停策略仍然有效。

这是轻量帧混合，不是光流或生成式关节补帧；姿势差异大时可能出现短暂重影，可关闭。原始素材仍为每套30帧，不能把绘制频率写成生成原画帧数，亦不保证设备恒定60fps。导入的GIF/WebP由浏览器原生图片播放，无法通过这套图集播放器补帧，设置会说明并禁用此开关。

同一场景自动轮换变体时预载目标，等当前动作的循环边界再切换；任务真实状态变化和手动场景预览仍即时响应。未显示的锁屏不挂载角色；解锁后释放锁屏播放器。画布尺寸和上下文缓存由尺寸变化失效，避免插值时每帧重新读布局。

## 运行时状态与 AI 反馈

前端根据任务、工具和音频事件选择场景，不扫描聊天正文来猜状态。处理优先级如下：

1. 正在聆听的语音状态。
2. 当前任务的等待审批、等待补充或暂停状态；SSE 状态先于轮询结果生效。
3. 与当前任务匹配的短暂终态／工具失败反馈；旧任务的完成反馈不能覆盖新任务。反馈停留约六秒。
4. 正在播放的音频或语音合成。
5. 当前会话的运行阶段：等待／停滞、生成、工具分类、推理。
6. 正在提交或等待回复。
7. 空闲待机；连续空闲超过 45 秒后进入睡眠。

已结束任务以及其他会话残留的 `runPhase` 不参与活动状态判断。`completed`、`failed`、`cancelled`、`interrupted` 使用服务端真实状态；SSE `done` 表示流结束，单独出现时不代表成功。锁屏使用同一个角色和任务状态，不从对话正文生成额外气泡。

`window.aideAvatarCue({scene, variant, emotion, intensity})` 仅接受白名单场景、对应变体序号、`calm|curious|happy|frustrated|sleepy` 和 1–3 的强度。反馈只能选择当前真实场景中的可用动作，不能让未完成任务显示为已完成。场景变化立即跟随实际事件；同一场景中的变体至少驻留四秒或完整一遍动作时长，以较长者为准。无新反馈时轮换动作，避免连续自动重复同一个变体。

AI 反馈通过现有模型请求中的可选 `aide_avatar_cue` 工具返回，随 SSE `avatar` 或小秘文字／语音接口的 `avatarCue` 字段传递。总开关默认关闭，客户端只在启用时发送 `avatarFeedback: true`。播放本身不会调用模型，系统没有按帧请求或定时分类请求。

工具定义与反馈 JSON 会占用正常请求的 token；开启、关闭、导入启用、跨标签页启停变化会刷新上下文预算。现有请求流与接口限制以 `internal/server/avatar_feedback.go`、`workflow.go` 和 `assistant_agent.go` 为准：每个模型响应最多接受一个有效反馈，aide 一个任务累计最多接受三个，跨工作流步骤与恢复共用限额；重试建立新任务及新额度，小秘每次交互有独立的三个反馈限额。使用 JSON `response_format` 的阶段不注入该工具。

有效反馈若带有 `reply`，可直接复用这次响应作为正常回答；若只返回空反馈而无正文／工作工具，服务会移除反馈工具，再进行一次回答恢复请求，因此不能承诺任何情况下都绝无额外模型轮次。系统仅保存最新反馈供断线恢复。

启用状态在开始、重试或恢复请求时快照。运行中关闭总开关会立即隐藏形象；已经开始且启用过反馈的任务，仍可能保留工具定义直到剩余额度耗尽或任务结束。新请求按当前关闭状态省去该工具。

## 播放器与资源控制

`internal/server/web/avatar-player.js` 的 `mount(slot, manifestURL, sceneOrClip)` 返回播放器控制器；`setMotion` 选择场景或具体变体，`setPlaybackRate` 设置倍率且保留进度，`setInterpolationEnabled` 控制帧混合，`preload` 只预载一个候选，`destroy`／`unmount` 释放引用。

- 全部帧播放器共用一个 `requestAnimationFrame` 时钟。
- 相同动作更新不重置播放；切换时保留旧帧，待新图解码完成后替换。
- 只预载当前场景的下一候选；隐藏、离屏、页面后台和系统减少动态效果时暂停动画并释放无用预载。
- 可释放图片缓存按四张／约 8M 像素预算淘汰；仍被实际播放器引用的图片另算，不承诺总内存固定为该数。
- 缺失或加载失败的图集按同场景其他变体、待机、其他可用动作、静态 poster 的顺序降级。
- 设置预览与实际场景分开，手工预览不会修改任务状态或触发模型调用。

## 聊天框浮层布局

虚拟形象仅在输入框右侧边缘绝对定位，不通过输入框外边距或内边距占用整行高度；启停形象不应缩短聊天滚动视口。浮层不接收指针事件，透明区域可继续滚动和选择消息。桌面形象148px，窄屏116px。2026-10-01移除原116px/94px上边距，以修复小秘会话底部出现整行空白的问题。
