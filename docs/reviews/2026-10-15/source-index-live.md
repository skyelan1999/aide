## 验收断言

- 将范围限定为 `nested`，优先指定 `nested/live-priority.md`。每批最多两个文件和一个目录，首次文件批次已有优先节点，仍报告未完成；根目录文件不进入结果。
- 用相同工作区／数据目录创建新的独立 App，从磁盘加载来源、密钥、规则及加密游标。后续批次保留之前节点并继续推进。这里是 App 重载，不是独立操作系统进程重启。
- 取消下一次观察后，结果为 unavailable，不声称总量已知，已发布节点仍在；恢复后继续推进，最终限定目录七个文件、pending 为零且总量已知。
- 从这份实际目录结果调用生产原文检索引擎，对六份远端文件返回六个不同文件命中，核对来源、路径、定位及与实际准备内容一致的哈希。此项不经过浏览器和 HTTP 检索入口，也不调用生成模型或向量服务。

首轮测试夹具错误地将内部工作区配置 ID 作为图谱工作区 ID，检索被正确拒绝；第二协议更新已存在的准备文件时未提供哈希也被正确拒绝。修正为实际图谱 ID 和读取后带哈希写入。后续又修正了夹具对来源缺失文件返回码的假设：该入口当前返回 400，而非 404；仍要求受哈希保护的 PUT 成功，不能借此覆盖不可读的已有文件。失败日志保留，不记为产品已修复缺陷。
