## 环境与故障方式

先执行用户指定的 `AIDE_OPEN_BROWSER=0 bash ./start.command`。源码摘要未变，启动器复用已运行的9999实例，没有构建或重启，也没有新增浏览器标签页。实际故障测试另用当前应用镜像 `0e29f3cafa29` 启动一次性容器，镜像默认 UID/GID 1000，无网络、宿主端口或用户数据挂载，512MiB内存、单CPU、cap-drop ALL、no-new-privileges。

数据目录挂载8MiB tmpfs，工作区位于容器独立可写层；以4096字节块写入专用 filler，三次实际获得 errno28（ENOSPC）及零可用块，分别填入8314880、8306688、8278016字节。删除 filler 恢复空间。它没有填满本机磁盘，也不模拟掉电、物理磁盘坏块或断网。客户端通过容器内部实际 HTTPS API 访问，用生成证书建立进程内信任，不改浏览器信任设置。

首次夹具把 tmpfs 挂在尚未创建的父目录下，导致默认用户无法建立工作目录，未进入验收；改为独立 `/tmp/aide-data`、显式UID/GID1000后正常启动。没有改用root运行应用或放宽容器安全配置。私有日志保留于 `.agent-state/storage-fault-live/`。

## 实际结果

| 场景 | 核对方法与结果 |
| --- | --- |
| 保存前归档失败 | 先记录基线历史，外部改动正文，再填满数据目录。PUT文件返回400及ENOSPC；当前正文哈希、所有旧历史对象与索引摘要保持。释放空间后用原读取哈希重试成功，基线、外部变更和新正文均保留，共3版。 |
| 正文已写入、新历史归档失败 | 旧正文已归档，填满数据目录后写新正文。接口返回400，明确含“文件已保存，但历史归档失败”；GET正文核对新哈希。历史列表显示observation unavailable及ENOSPC，旧版本仍可精确读取。使用旧哈希再写返回409，未覆盖新正文。 |
| 解除故障后观察及去重 | 释放空间后历史观察补入新正文；同正文保存不再增加版本。没有把失败响应冒充成功，也没有把旧读取哈希当成最新版本。 |
| 星图与知识时光写入失败 | 满空间期间实际updates响应保留节点，并包含“知识历史未保存”及ENOSPC警告；历史条目ID、Markdown历史及加密时间线文件摘要保持。释放空间后下一次同步成功增加知识历史条目。 |
| 整版恢复的准备阶段失败 | 准备Markdown与SVG的两版历史，生成旧版恢复计划，再填满数据目录。POST恢复返回500及ENOSPC；正文与SVG均维持当前哈希，原历史文件摘要保持。 |
| 恢复中途权限失败 | 释放空间后将工作区根设为0500，保留资源子目录可写。旧版SVG先写入并读回确认，正文写入被拒绝；接口返回409、state incomplete，SVG applied/verified为true，正文applied为false。实际读取恢复日志，核对pending为正文路径及已验证资源记录。 |
| 明确重试与中间态归档 | 恢复权限后重新获取计划与期望哈希，再恢复成功，所有文件verified，正文和SVG都匹配旧版。历史实际为4版：基线、恢复前、部分恢复中间态、最终恢复版。精确读取倒数第二版，核对当前正文与已恢复旧SVG的组合。最初探针误期望3版，断言失败后核对实际行为，保留失败日志并改为验证中间态；没有删掉该版本或放宽为任意数量。 |
| 实际应用进程重启 | 保持同一容器tmpfs，停止应用子进程，由独立监督进程启动新PID。重新通过HTTPS读取，旧历史／时间线文件摘要保持，正文、SVG、历史版本和时间线条目ID一致。不是容器重建或掉电持久性证明。 |
