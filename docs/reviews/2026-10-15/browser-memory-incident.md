## 原因判断与证据边界

直接触发是交换空间不足。大量 Safari 网页进程与虚拟机同时保留内存，结合重复 AIDE 标签的截图和重复开页行为，支持“验收页累积与其他重负载共同造成内存压力”的判断。打开操作超时后转向其他开页入口，会增加结果未知的请求与页面数量，这种重试方式也需要停止。

现行 `starmap.js` 在隐藏时取消动画帧、停止实时同步，`pagehide` 会停止同步并关闭通道；这些措施暂停工作，但不会释放仍打开页面的完整图数据。后台标签因此仍可能长期保留较大内存。事故报告没有逐页 URL、堆快照或分配时间线，不能把所有 WebContent 都归为 AIDE，也不能据此宣布某一模块泄漏或已经修复泄漏。09:01 的 WebContent CPU 诊断没有足够 URL 归属信息，不能单独用于给 AIDE 定责。

## 已采取的措施

已将以下规则加入 [统一开发工作流](../../agent/WORKFLOW.md)：每轮先盘点并复用测试标签，同实例最多一个自建工作台页和一个当前组件页；打开下一轮前关闭上一轮自建页，组件验收结束立即关闭。保留用户页面、草稿和未保存表单。打开超时先核对结果，不追加不同入口的打开请求。发生内存压力先暂停新增页面和重型并行任务。

继续实际工作台验收仍使用用户指定的 `start.command`；已有可复用页时设置 `AIDE_OPEN_BROWSER=0` 启动，再通过 UI 复用该页。这是现有启动选项与验收流程约束，本次没有实现跨浏览器自动关闭用户标签的产品功能。
