# 全量 Go 超时排查（#903）

## 原因与修复

此前两次命令分别给整个 `internal/server` 测试包设置 5 分钟、15 分钟累计限时。panic 栈中 Harness / Reminder 当前测试仅运行约一秒，均在 `New → BuildBaseline → currentBinarySHA256 → os.ReadFile / SHA256`，不是这两个测试各自卡住。

隔离 Linux ARM64 / Go 1.26.10 编译的非 race 测试程序为 298,589,417 字节。三个测试应用的分配 profile 中，整份读取程序累计分配约 1,708.55 MiB，占总分配 99.15%；同一内容还会在建立基线和启动校验中分别读取。CPU profile 也主要在 SHA-256。大测试包累积这些工作，固定的短包级限时不能表示单个测试是否挂起。

修复将程序哈希改为流式读取，避免与可执行文件大小成正比的内存分配。没有缓存哈希、按时间戳跳过、禁用完整性检查或缩减测试列表；每次校验仍重新读取程序内容。16 MiB 文件基准分配 33,224 B/op（8 次分配）。同一组三应用加新回归的 profile 总分配约 16.34 MiB；这不是单次延迟的稳定提速承诺。

新增回归核对空文件、多块文件、相同大小且保留时间戳的内容变化、路径替换、文件缺失及读取错误。新算法的摘要与独立 `sha256.Sum256` 结果相同。

## 全量验证

运行仓库标准 `python3 scripts/agent-route.py verify full`，指定固定的本地运行镜像与 SDK 镜像。标准流程从当前 Git 文件建立一次性 Linux 本地源码快照，不挂载运行实例的数据、关闭容器网络；编译 race 测试程序后按全部 Test/Fuzz/Example 注册项分成互斥分片，记录每项完成状态与跳过原因；其余包、平台契约和 vet 继续完整执行。使用既有的两工作进程选项，结果待结束后补记。

`bash scripts/aide.sh test` 的旧实现仍有直接挂载源码、固定 15 分钟限时的路径，也已统一到同一 Go 快照执行器。回归检查设置与错误码传递、旧内部变量不再绕回旧路径、进入测试不触发配置或运行实例操作。标准 full 与实际快捷入口分别完成后记录结果。

短的单进程包级命令不再作为整个大服务器包的完整验收入口；标准分片不是只选部分测试。任何分片失败、缺失执行收据或后续包/vet 失败都不能报告 full 通过。

## 数据与交付边界

测试在独立工作树和无生产挂载容器内执行；不启动源码服务器、不写运行数据、不重建或重启运行中的 Aide。不新增版本、标签或 Release。生产完整性、容器身份与受保护数据将在结束时只读复核，日志保留本机 `.agent-state/go-full-timeout-20261114/`，不提交凭据或私有快照。
