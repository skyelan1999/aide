# 按钮等待反馈检查 · 2026-10-20

用户报告：部分 Aide 按钮需要反复点击，感觉没有响应。范围为 Aide 主界面及内建面板；独立插件 iframe 内部按钮不在本轮逐项验收范围。

## 原因和修改

公共 `action()` 和消息按钮的 `safe()` 只捕获异常，没有等待提示或重复提交保护。工作区配置、插件删除、目录浏览等入口还通过内部调用丢失事件目标；小秘入口丢失内部异步返回值，无法跟踪认证与加载。

新增 `async-action.js`，仅对显式包装的按钮或提交表单跟踪 pending。处理函数仍同步执行，不人为延时，不改变剪贴板或文件选择器的用户激活。等待时保留标签、大小和业务禁用状态，以局部边框、角标和 `aria-busy` 提示；同一按钮/表单重复提交被拦截，其他操作可用；失败同样恢复。

设置面板和文件根目录切换已有同步绘制与请求代次处理，显式保留这些导航的可重复操作，不让公共去重阻止关闭后重开或快速切换。小秘认证的回车统一点击确认按钮。

实际浏览器使用一次性 Go `testApp` 和真正嵌入的 Aide 页面、系统 Chromium。使用鼠标点击检查命中；将目标 HTTP 请求扣留至少 150ms，验证首个动画帧已出现等待状态；再次点击/键盘提交不重复发请求，随后继续真实隔离后端请求或返回 503 验证恢复。共用一个页面，结束关闭浏览器及测试服务。没有读取或修改用户运行数据。

`feedbackMs` 记录点击至首个动画帧的观察值，不是网络完成时间或硬件无关的延迟承诺。测量开发中曾观察到 134ms 帧调度，因此测试断言首帧状态正确，不使用不稳定的固定 100ms 门槛。
