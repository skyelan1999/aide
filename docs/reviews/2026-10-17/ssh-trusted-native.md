# 可信工作台上的真实 SFTP 原生验收

继续连续工作目标，使用当前本机 9999 工作台、现有隔离 OpenSSH 服务和专用目录，不切换用户工作空间，也不绕过浏览器证书提示。本记录覆盖独立 SFTP 来源，不能替代 SSH 工作空间模式、用户真实主机或 Windows 验收。

## 原生操作与独立核对

- 在含空格的远端目录打开 Markdown，输入并保存标记，整份 API 正文与实际 SSH 文件字节一致。
- 关闭重开后切回编辑，画面保持相同顶部位置；第二个标记紧接上次标记，整份远端文件比对证明光标准确恢复。
- 自动保存关闭时输入草稿，确认远端未变；刷新经浏览器离开确认后自动重开同一文件，页面提供明确的恢复按钮。手动恢复后在原光标继续输入并保存，整份远端正文精确包含连续标记。
- 实际外部修改正文和 SVG，历史新增第五版，页面实际显示 V2 正文和图片。选择最初版本，恢复计划明确列出正文与资源两个文件；确认后两者均显示 V1，并与 SSH 文件系统原始字节一致。重复观察不新增版本。
- 同一真实 SFTP 来源的按钮、事件、回调、HTTP、路由及服务六步路径在原生 Safari 显示；来源、候选类型和哈希保留。点击最后一段在同标签只读查看器准确选中 `server.go` 第四行。

初次注册因内置来源空路径校验返回 400，测试准备程序按已有来源规则归一化后成功；失败后已撤回临时网络连接再继续。原生输入输送最初省略了方括号，最终以已观察的纯文本标记和整份独立字节比对验证位置，没有改产品适配夹具。扫描更新期间的一次路径查询按版本保护取消，同步后重新查询成功。

## 清理和边界

来源注册表逐字节恢复，原保险库条目按完整密文与元数据规范化比较保持，临时凭据移除；原有网络端点完整恢复。七份测试文件先逐一核对原始字节，再仅删除本轮专用目录；原 SSH 样例项目继续保留。原 14 会话、鉴权、设置和挂载核对保持，无新增标签或模型调用。知识视角、全部来源、空查询和关闭的路径面板恢复，再回原会话和原文件来源。

测试观察进入既有有界历史，不声称历史缓存字节不变。刷新后曾出现较早恢复分支的待合并提示，尚未判定为产品缺陷；没有覆盖或丢弃其他分支。SSH 工作空间隔离、断线/中断恢复、审批/锁屏联动仍需各自验收。证据见 [原生核对收据](ssh-trusted-native-proof.json)。
