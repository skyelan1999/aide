## 两项直接负例

20,052 个节点的一次观察编码为 7,259,135 字节。当前源码对两次不同观察追加后仅留下1次，专项以 `lost distinct observations true <nil> 1` 失败；因此大星图无法比较前后证据。

只读检查现有历史的封装版本，确认当前安装已有 v2 文件；未解密或查看用户正文。独立构造默认 gzip 压缩、AES-GCM 加密的合法 v2 历史后，旧读取器以“知识历史封装损坏”拒绝，形成第二项失败用例。这是实际已有格式的兼容要求，不能仅增加未来写入容量。

## 修复设计

复用经核对的 `6e3d3e16` 中六个后端源码／回归文件补丁，额外加入由标准 gzip 编码器构造的已有 v2 兼容回归。历史最多32次、物理封装8 MiB、解码 JSON 32 MiB；保留原载荷1／2／3，向量编码不变。先压缩再加密，首次改写旧封装前保存原加密字节并检查原件指纹；读取不迁移。损坏、尾随内容和解压超额拒绝处理，预算淘汰继续计入 dropped。

格式化后源码的历史／结论相关专项 race 回归通过，用时21.098秒，覆盖两次20,052节点观察的完整差异、旧封装备份、已有v2只读兼容、独立容量限制和损坏输入。两项原负例均转为通过；详见[专项证据](timeline-retention-synced-proof.json)。本轮仍需新的源码门禁；之前指纹 `6dd563bb…` 的 full 只覆盖修复前源码，不能用于本轮发布。
