# 消息按钮布局与遮挡修复

任务：[message-buttons-ui-20261019](../../tasks/message-buttons-ui-20261019.json)。基线 main `e567f195`；修复分支 `fix/message-buttons-ui-20261019`。

## 改动与原因

原通知入口作为额外的文字按钮追加在标题操作组之外，与关闭／新建按钮不在同一布局组；窄面板空间不足时容易拥挤。会话通知菜单采用绝对定位，位于可滚动面板内部，存在覆盖相邻内容、被滚动边界裁切的结构风险。并非已复现所有用户设备的遮挡情况，也不将这些原因当作唯一根因。

现在标题入口归入右侧操作组，添加联系人、全部已读和会话通知使用统一 36px 命中区域与 SVG 图标，保留可访问名称和悬停说明。会话名称／设备码纵向排列，角标独立对齐。通知配置改为行内展开的完整卡片，不使用浮层或增加 z-index；窄屏字段单列，桌面双列。聊天工具栏中的卡片排在全部操作之后，避免标记已读按钮被挤到卡片下方。表单展开期间，普通轮询不销毁正在编辑的卡片。

关闭按钮和 Esc 收起卡片并恢复入口焦点；默认策略禁用无效的免打扰时长选择；保存失败保留表单并显示错误。通知计数、持久化 API、权限和已读边界均未改动。
