# 随机就绪队列与全部工作槽位（2026-11-01）

用户纠正“不必有一个倍速管理”。实现采用按需拆分/验收与代码调度分阶段运行：同步environment_run_queue期间主模型暂停自身推理，原本预留的一个名额借给工作池，10X可以同时有10项实际工作；没有额外管理模型常驻推理。主模型恢复前所有队列工作结束或取消join。异步接口保留主模型可同时工作、子环境最多X-1的兼容行为；1X、远程与普通主工具不变。

随机仅在就绪任务中选择；依赖、前置失败/取消、私有工作区、插件边界与普通提案/版本/冲突/审批沿用原实现。批次验证后才开始工作；返回精简清单，失败与冲突显式保留，原始证据可按ID取回，不把子任务完成称作验证成功。[接口与语义](../../designs/execution-environments-20261101.md)。

受控验证：50项任务使用10X，初始10个工作请求同时阻塞，检测到MainPaused=true、WorkerCapacity=10、Active=10；释放后50项全部完成、收集并释放，峰值不超过10，归还后异步容量恢复9。另测取消时先join再恢复、重复借槽拒绝、无效依赖无部分执行、随机仍遵守依赖、冲突不apply且不无限重试、子环境不能借槽、1X不创建运行时。受控模型验证不代替Luna耗时与质量实测。

Luna同20模块工程对照完成，使用high和与前轮相同契约/隐藏验收及分阶段计时。10X明确要求随机run_queue与独立任务积压，属于标注过的策略实验，并把2个集成模块和报告留在主阶段，不代表所有依赖工作已充分并行化。两组由于首连接失败而先后进入有效执行、部分重叠，并与长期源码审查重叠，上游负载未严格控制，不能据单次对比外推固定倍速。
