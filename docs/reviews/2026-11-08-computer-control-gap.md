关联任务：`assisted-ui-actions-20261108`、`computer-virtual-pointer-20261108`。基线 `3edafef7`，继承快捷键、全局截屏及目标应用定位的本地改动。

用户报告同模型在 Codex 与 Aide 中完成电脑任务的能力不同。本次按 Aide 的实际工具链排查；没有同模型、同上下文的受控 Codex 性能基线，不把结果写成模型对比测试。

| 链路 | 已确认的问题 | 候选行为 | 验证边界 |
| --- | --- | --- | --- |
| 应用发现 | 每次先找前台应用，截图唤起 Aide 后就无法定位原软件 | 可传准确名称或 bundle ID；status 提供运行中应用的元数据 | 原定位修复已在本机有道验收；状态清单新增待本轮复验 |

| 视觉坐标 | Go 转换只保留图片，丢弃原生窗口位置和尺寸 | 返回实际像素尺寸、窗口 ID、桌面矩形和坐标换算公式；支持负桌面坐标 | 元数据和负坐标回归通过；多显示器硬件未测 |
| 普通审批 | 普通点击/输入在进入审核模型前被排除，输入全文又被隐藏 | 审核准确操作、用户授权和新鲜控件证据；AX 无语义时，普通点击可用当前截图审核 | 本机首次回归点击已自动批准；输入当时因焦点失败正确转人工。新视觉审核的实际图片发送、无工具调用、内存生命周期回归通过 |
| 审批后变化 | 审核过程中窗口或控件可能变化 | 复核 PID、窗口/控件；视觉点击再核对目标周围像素，执行时再次校验窗口 ID/矩形 | 单元回归覆盖变化检测；不将截图视为后续界面永久不变 |
| 多任务控制 | 共享实体键鼠与单一焦点，任务之间会相互干扰 | 服务端派生 controller 身份；输入框支持 `focusOnly` 虚拟定位；不同应用优先后台 AX；同应用和系统输入各有 FIFO | 原生 FIFO、独立资源、取消/授予竞态及 Unicode 选区回归通过；两软件实测待运行候选 |
| 操作可见性 | 只有真实鼠标位置，无法分辨哪个任务在操作 | 每会话颜色的非交互虚拟光标；后台应用显示带软件名的边栏标记；最近通道状态可查 | 原生编译通过；桌面显示待实测 |

后台文字写入会读回核验；不支持时只在能恢复准确目标和选区的条件下使用排队的系统输入。按钮自身可能激活窗口，其短暂按压与系统输入事务互斥。对界面文字没有明确语义的操作仍须依赖真实视觉证据；模糊或敏感操作转人工。权限列表、系统权限、屏幕锁定检查和手动审批模式保持生效。

本次未修改用户的 EDA 工程、模型安全策略、系统权限或全局 Docker 分配。所有模型与界面验收复用当前本机 Aide；不创建第二个工作台服务。候选源码未提交、合并或推送，实际部署/验收状态以关联任务记录的最后结果为准。

## 当前实例验收补充

2026-11-08 使用现有 `aide-aide-1` 和本机 Aide.app，模型为 `gpt-6-luna`：

- 会话 #88 与 #89 同时开始。有道目标与 TextEdit 目标持有不同 controller ID；两边普通聚焦、全选、输入均经模型辅助审批通过，没有人工点“确认”。TextEdit 实际以 `background-ax` 完成替换并读回；有道的网页字段以 `system-input` 自动聚焦并输入，实际读回“今天早上吃了什么”和 “What did you eat this morning?”。通过独立 CUA 读取两应用复核，没有跨应用串写。测试文稿随后由 Aide 恢复原两行，不保存或关闭。
- 初次实测发现网页受控字段会接受 AXValue、随后清空。已在任何写入前识别 WebArea 祖先，改用系统队列，保留虚拟目标和精确选区；不能对已经发生的含糊 AX 写入自动重发。修复后上述有道流程通过。
- 会话 #90 只读 EDA 截图成功，返回 2560×1515、桌面窗口 `(0,33,1470,870)` 和换算公式；模型识别当前开始页及主要入口，与独立 CUA 截图一致。空白 AX 不再导致截图链路报超预算。
- 运行时记录了可见的原生虚拟光标窗口，名称包含“会话 #89 · 文本编辑 · 后台”、独立 controller ID 与 window ID。状态证明 NSPanel 已显示；本次未取得包含浮层的完整桌面截图，不声称完成光标位置/配色的逐像素视觉验收。
- 授权目标增加 Electron 官方的 `AXManualAccessibility` 握手。来源：[Electron accessibility](https://github.com/electron/electron/blob/main/docs/tutorial/accessibility.md)。不支持该属性或仍为空的应用继续用截图，不开启有已知界面副作用的 `AXEnhancedUserInterface`。
- EDA 菜单往返诊断 **未通过**：模型把“视图”换算到另一个普通菜单，审核模型也误认了菜单名称；随后又提议窗口外的 `y=17`，被证据门禁转人工，没有执行。提供坐标纠正后模型仍要求确认，已停止仅此诊断，使用 CUA 收起菜单。没有运行菜单项或修改工程。它说明图像到动作的定位仍有差距，不能把“视觉审批请求成功”写成“点击语义正确”。后续应优先提供图像坐标原生转换、目标区域放大证据和明确控件定位，而非放宽窗口边界。

原生编译、14 项原生回归、quick 和当前容器内 Go 审批/控件/图像相关回归通过。原生仅修改网页兼容分流和 Electron 握手后再次编译，并在当前实例完成上述复验。证据日志及运行镜像身份保存在任务记录；完整 Go race、跨平台真机、多显示器和单任务 10X 的真实多软件验收未执行。

## 仍有的能力差距

本轮补齐了发现、截图、审批和输入调度基础，并未达到通用桌面工具的全部动作覆盖。当前工具仍以单击、文字和有限按键为主，拖拽、滚动、右键/双击、任意组合键及精确窗口选择需要后续独立实现与验收。因此不以一次菜单测试推断能够完成 EDA 绘图、Layout 或 Gerber 导出，也不把已授权应用的边界扩大成所有应用无条件控制。
