# 源码构建完整性告警修复与运行验收

关联 [Issue #888](https://github.com/skyelan1999/aide/issues/888) 和 [修复 PR #889](https://github.com/skyelan1999/aide/pull/889)。本次只合并源码、更新原有运行实例并验证，不升版本、不创建 tag、不触发 Delivery、不发布 Aide Release。

## 原因与修复

原安装目录有既有未跟踪草稿。标准构建将身份记录为 `<提交>-dirty`，而完整性升级只接受纯 40 位提交，因此即使二进制匹配镜像内的可信校验文件，旧基线也不会更新。未通过移动、忽略、提交或删除草稿来改变这一事实。

修复沿用已有 `source-sha`，将非干净源码构建记录为 `<完整提交>-dirty.<完整源码 SHA-256>`。仅编译时为 `source` 模式的程序接受这种内容身份；发行模式和干净构建不变，旧的裸 `-dirty` 仍不被自动认可。镜像摘要的 root 所有、只读属性、实际二进制匹配、数据无异常、就绪确认前后状态重查、旧基线备份与原子替换全部保留。同一完整身份出现不同二进制仍拒绝，未直接编辑生产基线。
