# 本地工作区提交与远端 main 整合

用户在本地工作区全部有效改动提交后要求“推送”。推送前发现原仓库没有远端配置，旧 Git 对象读取异常导致常规拉取失败，因此使用不在 iCloud 中的干净临时克隆导入本地已提交历史。原仓库文件、恢复分支和其他工作树保留。

远端基线为 `903de5aa948b4e5d812cb682d5ad6580834128d6`，本地已验收提交为 `c3d67f3398b238356a37ef43b9aeaa9402e97945`。共同祖先后本地4个提交、远端50个提交；正常三方合并涉及28个文件冲突，不使用强推或覆盖远端历史。

解决冲突时保留本地普通 SIP 网关、中文播报、挂断／回拨、审批回执、按需历史缓存和 Writer 许可检查，也保留上游 VoIP 话机接管、Office Math、审批目的字段、独立窗口及终端输出协议、构建网络选择。设置中心同时保留两种电话入口；公共脚本缓存号单调更新。完整性检查保留旧摘要入口的兼容接口，启动使用新的 typed cache。保留上游实际 DWG 能力，不带回已废弃的“一概不能转换 DWG”错误引导。

验证：合并后354项 quick 检查通过；本地工作区相关158个服务端测试函数的race回归无失败（157通过，1项按既有条件需操作者图片样本）；额外上游VoIP、审批目的和摘要缓存兼容性回归通过。execsandbox、TTS、VoIP包的race测试以及全源码vet通过。原始证据保留在临时克隆的忽略目录 `.agent-state/push-integration/` 与 `.agent-state/push-compat/`。

这是源码整合与推送准备，不是新合并版本的浏览器／硬件矩阵验收或Release。不重启已有运行服务，不调用真实模型，不操作现有待审任务。实际远端结果以推送回执和远端 main 哈希核对为准。
