# 文件恢复与保存回执的异步归属修复

任务：[file-recovery-async-ownership-20261016](../../tasks/file-recovery-async-ownership-20261016.json)。基线main `93d3314f2ed3c3e7d94100b2146aa09c3c2d8c33`，移动硬盘开发目录；原12项中的现场恢复、保存状态及锁屏边界继续推进。

## 复现与修复

原位置恢复在异步读取完成后才记录用户操作计数。若读取期间用户移动光标，旧位置仍会覆盖新操作；用例实际失败，selectionStart实际0、期望2。现在在发起读取前捕获操作计数，在读取返回和双动画帧应用时均核对；同时核对当前内容hash，拒绝同一路径已保存新版本后的旧位置。未变化的当前内容仍正常恢复。

原成功保存分支只检查文件身份，缺少失败分支已有的锁态守卫。保存期间锁屏后成功响应仍调用onSaved，并可能清理恢复草稿。补用例实际失败，确认回调实际1、期望0。现在锁态下不更新baseline、不调用确认回调或清理草稿；完成后显示“保存结果待核对”，避免无限“正在保存”。这是客户端回执处理，不能撤销已经送达服务器的写入；解锁后保留现有hash冲突/重试流程，不静默覆盖服务器。

只改共享file-autosave.js及新增状态翻译；首页对应缓存版本更新。工作台与独立文件页沿用同一模块，没有改变文件API、授权、历史格式或存储容量。
