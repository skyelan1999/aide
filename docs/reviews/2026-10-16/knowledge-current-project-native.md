# Current project progressive indexing and native retrieval

The authenticated Safari 9999 map showed about 20,052 existing nodes. Its old reference root explicitly reported 13,391 unreadable bodies and ongoing bounded scanning. That count does not prove the underlying files are readable or that retrieval covers the whole tree.

A temporary read-only local source pointed to the actual external-drive AIDE project with AI visibility disabled. During native observation it displayed 510, then 1,124, then 1,497 nodes while directory/content review was still pending. Capacity grew from 800 to 1,600 and later 3,200. The bounded range eventually displayed 2,077 nodes (1,944 files and 133 directories), maximum depth seven and text prefixes of 8 KiB. Prior visible map content remained present throughout. This is a direct current-instance incremental display check, not proof of all repository content or arbitrary remote directories.

Literal original-text search scoped to that source returned real AIDE document hits, with 14/295 indexed documents checked and a continuation control. A hit at text line 51 showed a source locator and hash. The actual source file opened read-only in the existing workbench tab; rendered table text matched the hit and save/autosave controls were disabled. No model or vector request was made.

## Native gaps discovered

The ordinary map quick-preview click failed in this Safari environment: `window.open` returned no usable window and the application requested popup permission. No browser popup permission was changed. Navigating the observed source URL in the existing trusted workbench tab succeeded, but that is a separate file-view check and does not pass quick-preview acceptance. The source URL did not contain a line field, so exact line navigation is also unproven.

After temporary source removal the map correctly marked the source removed with zero nodes, but old original-search result buttons/snippets remained visible until changing retrieval/query state. A fresh authenticated read using that removed source was refused with HTTP 400. This stale UI must still be invalidated when its source disappears; API protection is not a substitute for clearing stale current results.

Original source registry bytes, authentication, settings, sessions, workspace configuration and unrelated mounts were verified restored/preserved. No project file was modified. No tab was added. The original node search mode, empty query, selected node and workbench tab were restored. Screenshots and full AX/logs remain private; [sanitized evidence](evidence/knowledge-current-project-native-proof.json) records the observed counts and limitations.
