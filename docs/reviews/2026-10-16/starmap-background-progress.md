# 星图后台续扫与连线性能

任务：[starmap-background-progress-20261016](../../tasks/starmap-background-progress-20261016.json)。用户观察到连线长时间未完成，且需点击激活浏览器才继续搜索和连线。

## 已确认原因与修改

1. 隐藏标签页调用 `stopLive()`，同步准备与调度也拒绝隐藏页面；服务端原先随请求逐批扫描。修改为页面显式请求后台续扫，服务端完成当前有界目录／正文队列并发布每批节点和连线，不依赖页面焦点或动画帧。模式任务去重，串行扫描门控保持；身份变化、关闭、连续错误／停滞和期限结束会退出。
2. 显式引用生成逐份正文遍历全部文件。改为一次构建编号、路径与来源命名路径索引，只查实际引用；保留旧关系顺序、证据行列和歧义规则。另外，旧 4,000 条引用限制误用了全图边数，目录包含边很多时几乎不给真实引用留下预算；现在仅计算显式引用边，仍限制 4,000 条并报告截断。
3. 后台暂停画布与大场景重建，但保留请求与低频同步；回前台立即追平，不再将后台时长叠加到节点出生时间而延迟连线显现。扫描仅新增材料或关系时，进行中的正文搜索继续；已知内容、来源身份、移除、改查和锁屏继续取消旧检索。
4. 原有引用目录现场已达到 20,000 条容量上限，却仍将 881 个未覆盖目录计作活动扫描。新增 `discoveryBlocked` 明确区分硬上限与可以继续扩展的队列；先完成已有正文复核，再结束续扫并显示范围受限。来源保持未完整覆盖。最后只有覆盖信息变化的批次也刷新状态，不再遗留旧“扫描中”文字。

- 引用生成与旧实现逐项等价测试覆盖 24 组混合来源、重名、编码、空格、Unicode、前后缀边界、编号引用及证据位置；原引用回归通过。20,000 文本节点的同机 race 合成用例，旧遍历约 48.12 秒、新索引约 0.875 秒，关系结果一致。这不是实际资料库的端到端耗时承诺。
