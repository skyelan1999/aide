### R01：压缩路径能锁住主要 API

**自动压缩触发条件：** 会话消息累计超过 48,000 字节，任务结束时摘要调用成功返回。`execute()` 已持有 `a.mu`，再调用压缩；模型返回后同步记录 Token，统计函数再次获取同一把锁。调用链为：

```text
execute 持有 a.mu
  → maybeAutoCompact → compactSessionInternal → buildCompactionSummary
  → complete → tokenUsageRecorder → recordTokenUsage → 再次 Lock(a.mu)
```

证据：[internal/server/workflow.go:262](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L262)、[internal/server/workflow.go:282](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L282)、[internal/server/workflow.go:874](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L874)、[internal/server/provider.go:127](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/provider.go#L127)、[internal/server/server.go:551](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/server.go#L551)。Go Mutex 在锁已占用时会阻塞，与该复现一致，见 [Go 官方同步原语说明](https://pkg.go.dev/sync#Mutex.Lock)。

隔离测试模拟任务调用方持锁；Mock 摘要已返回，但压缩不能结束。测试主动释放外层锁后才结束。真实调用外层使用延迟解锁，无法自行完成这一步。此时 `/healthz` 仍返回 200；模型 HTTP 超时无法解除已发生的锁等待。

**并发手动压缩：** 两个请求都拿到旧消息切分点，再释放锁调用模型，返回后分别按旧位置裁剪当前消息。隔离样例 20 条各 8,000 字节消息，两请求均计算折叠 17 条；首个留下 3 条，第二个执行 `[17:]` 越界。panic 发生时已取锁且没有 defer 释放，主要 API 同样会被阻塞。证据：[internal/server/workflow.go:841](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L841)、[internal/server/workflow.go:849](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L849)。

**整改：** 模型/网络调用全部移出全局锁；压缩按会话限制为一个进行中的操作；使用不可变消息快照和 revision，在提交时核对旧前缀仍一致；统计存储独立注入并使用独立同步；压缩继承请求/任务取消信号。区分存活检查与能响应业务操作的就绪检查。

**验收：** >48 KB 成功摘要、两个同时压缩请求、压缩与新任务交错、取消/超时四类场景下，配置与会话 API 仍及时返回；不重复裁剪、不遗失消息；第二次压缩应排队或明确返回冲突。

### R02：项目身份在读取、应用和执行之间不一致

**提案：** Session/Task 没有稳定 workspace ID。A 项目生成新文件提案，切换至 B 后点击应用，应用逻辑读取全局当前根目录。B 没有同名文件时版本检查通过，文件写入 B。已在两个临时目录中复现。已有文件如果同名同内容，内容哈希也不能识别项目身份变化。证据：[internal/server/workflow.go:39](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L39)、[internal/server/server.go:96](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/server.go#L96)、[internal/server/workflow.go:383](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L383)、[internal/server/workspace_config.go:269](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workspace_config.go#L269)。

**命令：** 切换只更换 `a.workspace`，命令 cwd 仍按初始化的 `a.workPath` 计算。临时环境选择 B 后执行 pwd，返回 A。SSH 分支又直接发送命令，没有进入配置的远程工作目录，且先校验本地 cwd。证据：[internal/server/workspace_config.go:147](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workspace_config.go#L147)、[internal/server/command.go:71](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/command.go#L71)、[internal/server/command.go:96](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/command.go#L96)。

**前端文件页：** 切换仅刷新文件列表；旧会话、附件与独立文件页没有固定项目身份，保存只提交 root/path/hash。证据：[internal/server/web/app.js:940](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L940)、[internal/server/web/app.js:1136](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L1136)、[internal/server/web/app.js:1156](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L1156)。

**整改：** 引入 `WorkspaceRef{ID, Driver, Root, ConfigRevision}`；会话、任务、提案、文件页、命令都绑定该身份。根句柄在使用完之前不能被切换操作关闭。应用时明确校验 workspace ID + revision + 文件 hash；远程命令通过统一驱动进入绑定的工作目录。切换时处理未保存草稿、旧请求和附件。

**验收：** A/B 同名同内容文件、跨标签编辑、运行中切换、服务重启后应用旧提案均不得写错项目；pwd、文件读取、提案落盘、测试执行四者始终指向同一工作区。

### R03：文件和执行权限的范围大于界面所表达的范围

1. Compose 默认把整个 HOME 可写挂入 `/local`，本轮实际配置也如此。辅助环境原本可以只读，但当前 shell/Node 插件按容器用户权限能访问更广的宿主目录。Docker 官方说明 bind mount 默认可写，容器可修改相应宿主文件，见 [Docker bind mount 文档](https://docs.docker.com/engine/storage/bind-mounts/)。证据：[compose.yaml:22](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/compose.yaml#L22)。
2. `resolveHostPath()` 对 `/workspace`、`/context`、`/local` 采用字符串前缀及 Join，没有做分支内的根目录包含关系验证。隔离测试 `/workspace/../data` 成功解析到应用数据目录，突破该虚拟工作区范围；`/workspaceXYZ` 也会被当作相同前缀。证据：[internal/server/workspace_config.go:112](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workspace_config.go#L112)。这需要已授权的配置入口，不意味着已发现匿名远程访问漏洞。
3. SSH/SFTP 读取走独立路径，绕过本地 readText 的相对路径、256 KiB、普通文本和 UTF-8 检查；`../` 可指向配置远程根外，且大文件先完整下载。实际可访问范围仍由远程账号权限决定。证据：[internal/server/files.go:31](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/files.go#L31)、[internal/server/files.go:168](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/files.go#L168)、[internal/server/ssh_session.go:177](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/ssh_session.go#L177)、[internal/server/sources.go:179](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/sources.go#L179)。
4. 插件通过 `require(file)` 加载，同一容器内 Node 子进程并不天然限制 Node 的 fs/child_process 权限；提供“写入提案 API”不能阻止插件直接写文件。内建插件 helper 又硬编码 `/workspace`，不跟随选择的工作区。证据：[internal/server/plugin_host.js:20](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/plugin_host.js#L20)、[internal/server/plugin_host.js:73](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/plugin_host.js#L73)。

**整改：** 默认仅挂显式项目；辅助资料默认只读，额外写目录逐项指定并在 UI 展示。所有驱动共享路径和内容策略；规范化后验证根范围，远程还需处理符号链接。配置更改应先验证全部资源，再原子切换，失败不得留下半更新状态。插件明确分为受信代码和受限工具；需要支持第三方插件时再把执行器放到不含服务密钥及数据卷的隔离运行环境。

**验收：** 项目外测试文件写入失败；正常项目可编辑；绝对路径、`..`、相似前缀、符号链接、目录、二进制与超限文件在各驱动行为一致。先在测试目录/测试 SSH 服务完成，不拿业务资料做写入探针。

### R04：二次压缩不合并上一版摘要

压缩函数只发送本次折叠的 Messages，未包含既有 Compact；结果又直接覆盖旧摘要。早期约束若只存在上一版摘要，下一次压缩后就不再进入后续模型请求。原内容可能仍在 Runs 中，但不能据此认为模型仍能访问它。

证据：[internal/server/workflow.go:864](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L864)、[internal/server/workflow.go:850](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L850)、[internal/server/workflow.go:917](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L917)。隔离测试在原摘要置入唯一约束标记，确认下一次摘要请求未携带该标记，存储的摘要也被替换。

**整改：** 新摘要输入包括“已有结构化摘要 + 新增待折叠历史”，并保留版本、原始消息范围与来源定位；用户明确约束、工作区身份、已批准权限单独持久化，不能仅依赖自由文本摘要。

**验收：** 连续三次压缩后，早期唯一约束仍存在于后续请求；摘要可回溯到原始消息；压缩失败不会删除任何原消息。

### R05：工具闭环尚未统一

`step()` 仅将四个 builtinTools 加入正式 tools；插件工具只以名称进入提示。插件 surface 连 parameters 都未保存。现有插件测试强制 Mock 返回 `greet_tool`，可证明 handler 能执行，不能证明真实模型能发现工具或生成正确参数。证据：[internal/server/workflow.go:217](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L217)、[internal/server/workflow.go:455](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L455)、[internal/server/plugin_host.js:58](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/plugin_host.js#L58)、[internal/server/tools_test.go:163](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/tools_test.go#L163)。

此外，阶段内工具原始响应留在 toolLoop 局部消息中，下一阶段主要继承最终文字，不继承完整工具证据；工具读取也不建立允许修改既有文件所需的 versions 快照。JSON 提案入口限制最多 10 文件、20 命令和总大小，recordToolProposal 入口没有等价的累计限制。证据：[internal/server/workflow.go:242](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L242)、[internal/server/workflow.go:491](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L491)、[internal/server/workflow.go:329](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L329)、[internal/server/workflow.go:642](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L642)。

**整改：** 单一工具注册表保存 name/description/schema/权限/预算，并同时供 UI、模型请求和执行器使用；工具结果作为有来源的执行记录保留；读文件时记录版本，是否允许将其转成编辑提案由明确策略决定。所有入口统一累计文件数、命令数、字节数、调用次数、取消和超时。模型审查输出与测试结果使用不同状态，避免把“审查结束”当作已验证。

**验收：** 严格校验请求 schema 的 Mock 确认插件可发现；无参数/非法参数被拒绝；内建/插件/JSON 三条路径均不能绕过同一预算；真实模型的插件验收单独记录。

### R06：写文件工具会修改正文空白

`executeToolCall()` 对所有字符串参数统一 TrimSpace，包含 content。输入 `"  indented first line\n"` 被改成 `"indented first line"`，已复现。可能破坏首行缩进、有意义的空白与末尾换行。证据：[internal/server/workflow.go:556](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L556)、[internal/server/workflow.go:609](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L609)。

**整改：** 仅对路径、工具名等适合规范化的字段处理空白；正文按原字节保留并单独验证类型、大小和编码。验收覆盖前导空格、制表符、空文件、末尾换行及 CRLF。

### R07：前端异步结果没有绑定发起时的对象

`selectSession()` 在任何响应完成时写 `state.session`；先选 A 再选 B，B 先返回、A 后返回，最终会显示 A，已在隔离 Node VM 复现。发送逻辑也在 await 前后继续使用可变全局 session，并清空当前输入/附件，可能影响切换后的草稿。证据：[internal/server/web/app.js:32](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L32)、[internal/server/web/app.js:188](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L188)。

**整改：** 请求捕获 session/workspace ID 与草稿 revision；选择采用递增请求序号或 AbortController，只提交最后一次仍有效的响应。会话列表、文件编辑器和发送框分别管理状态。

**验收：** 人工延迟响应、快速 A→B 切换、A 发送中编辑 B 草稿等测试，最终选择与草稿均与用户最后操作一致。

### R08：上下文和费用显示应更诚实、可追溯

上下文条只按 session.messages 的 JS length/4 估算，不含系统提示、压缩摘要、当前输入、附件、工具定义和结果；Go 后端回放以 UTF-8 字节计数。25,000 个中文字在前端是 25,000 单位、后端是 75,000 字节，会导致“纳入历史”范围不同。证据：[internal/server/web/app.js:769](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L769)、[internal/server/workflow.go:171](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/workflow.go#L171)。

费用按一组当前单价重算所有历史；每日汇总未保留模型维度和费率版本；`Number(value) || 默认值` 又让合法 0 价失效。不能把这个数字当作提供商账单。证据：[internal/server/web/app.js:557](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/web/app.js#L557)、[internal/server/server.go:551](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/server.go#L551)。

**整改：** 后端提供与实际请求共用构造器的预算预览，分列历史/摘要/附件/工具/输出预留，并标注估算方法；Token 逐调用保存 provider/model/time/usage 来源/缓存字段（提供商有返回时），费率带币种、生效时间和版本。价格调整不静默重算历史；0 必须是合法费率。账户余额与本地估算分开展示。

### R09：存储与发布需要可恢复、可定位

启动时加载全部 session JSON；单个文件解析错误会导致 New 返回错误，缺少隔离坏文件继续启动的恢复路径。大量会话和轨迹也会提高启动与全量存储成本。证据：[internal/server/server.go:315](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/server.go#L315)。

UI 版本来自挂载目录的 version.md，镜像构建未嵌入版本/commit，标签固定 aide:local。旧镜像配新目录可显示新版本，不能证明运行代码一致。现有 HANDOVER 仍对应 2026-09-21 的 4e0da10。证据：[internal/server/server.go:277](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/internal/server/server.go#L277)、[Dockerfile:12](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/Dockerfile#L12)、[HANDOVER.md:3](https://github.com/skyelan1999/aide/blob/6a4e441912aade4177537f07d9fb63c98918fad7/HANDOVER.md#L3)。

**整改：** 先增加 schema version、备份清单、坏文件隔离、恢复检查和分页；需要按会话/运行/事件查询及事务时，再引入服务私有本地数据库，不把正在写入的数据库放进 iCloud 同步目录。编译注入版本、commit、构建时间，并写镜像标签；镜像归档采用版本/commit 名及 SHA-256 manifest。源码、镜像、配置和数据备份共同构成发布基线。

**验收：** 独立 Compose 项目、新端口、新数据卷恢复；核对运行 commit、历史会话、工作区、插件和来源；损坏一个测试会话不应阻止其他数据访问。生产恢复前另行明确备份、停机和回退步骤。

## 4. 建议的实施顺序和目标结构

**第一批：恢复功能一致性。** 修复 R01/R02/R04/R06/R07，统一 R03 的目录边界，补对应失败回归测试。每项以“原先缺陷场景不能再发生”为验收条件；测试通过才更新 FR 状态。不要先给有缺陷的压缩或多工作区功能继续叠加入口。

**第二批：统一执行内核。** 仍使用 Go 模块化单体，明确以下所有权：

| 组件 | 应持有的状态 | 关键约束 |
| --- | --- | --- |
| WorkspaceManager/Driver | workspace ID、配置 revision、授权根、文件/命令驱动 | 所有读取、写入、运行共享同一绑定对象 |
| RunManager | 会话快照、运行状态、取消、审批与实际执行结果 | 模型调用不持全局锁；审批后只执行被批准的内容 |
| ContextBuilder | 摘要版本、近期消息、资料来源和预算 | 预览与实际请求来自同一个构造结果 |
| ToolRegistry/Policy | schema、权限、调用/字节预算、结果证据 | 内建工具、插件和后续 MCP 使用同一执行规则 |
| ProviderAdapter | 提供商、模型、凭据引用、能力配置、usage | 不依赖全局 singleton 回调；明确真实/估算 usage |
| Store/EventLog | 会话、任务、提案、摘要和不可变执行事件 | 有 schema/迁移/恢复能力；写入失败不能静默当成功 |

前端通过 API 与运行事件更新状态；先保证事件有稳定 session/run/workspace ID，再按需要用 SSE 提升流式体验。逐文件应用的部分成功应保留，显示哪些已经落盘、哪些失败，并提供可审阅的恢复材料。

**第三批：完善发布和体验。** 更新交接文档、做独立恢复演练、修正用量统计，之后按实际使用顺序增加流式模型输出、PTY 或 MCP。向量检索、多 agent、完整 DSH 插件兼容都应有独立需求和验收，不能由“有登记入口”推导为已支持。
