# 助理自动交办与 Weather 验收

2026-11-22，本地 Aide `0.1.19.0 RC2`。任务：`assistant-autonomy-weather-20261122`。主程序已有较多未提交工作，本次以增量修改保留；没有发布 Aide 主程序版本。

## 最终行为

- 明确的查询/处理请求本身就是交办授权，能力不足时建立并启动 Aide 会话，不再要求用户另说“转交”。模型失败不会把原话直接派发；漏调工具最多补查一次，仍失败则报告未执行。
- 用户补充要求后，已安装 Weather 的三个已知只读工具直接提供给助理；天气优先直接查询，不创建执行会话。禁用、插件归属、工作区、取消和审批查询隔离仍生效，写提案不进入助理查询路径。
- 原生通话共用助理工具循环；对明确工作请求，暂存未经核实的话语并补调 `assistant_work`，防止仅口头声称处理。新路径的真实物理电话直调未在本轮重拨验收，不能以合成 WS 回归替代。
- 任务结果已有持久推送回助理会话。当前没有“挂断后任务完成自动回拨”的调度，提示词已明确此限制。

## 实际证据

MiMo Pro 真实查询先验证了自动交办：新会话 #191 实际调用 `route_plugins` 和 `weather_forecast`，返回有时区、获取时间及 Open-Meteo 来源的天气结果。新会话 #192 实际只读获取 PDF 元数据及第 1–7 页文本，完成目录级说明；不是全文或医学建议验收。两项均无文件/命令变更提案，完成通知已持久回到助理会话。#192 新命令沿原有审批/辅助审批链执行，曾先发出授权等待通知，不能把它说成完全绕过审批。

最终直调版真实模型仅收到“天津今天的天气怎么样？”，实际工具集合为 `weather_forecast`，返回 `action=chat`、`dispatched=null`，调用前后会话集合一致。证明天气已直接接入助理，而不是继续新建天气执行任务。

原 189 个非助理任务文件 SHA-256 比较无变化；35 项待人工审批的事件 ID、会话、运行及状态一致。新建的 #191/#192 保留作为实际查询结果，没有审批旧任务。

39 项顶层 Go 定向 race 回归通过，Docker 构建的全包 vet 通过。另有 26 项工作台 JS、28 项记忆/主动性/结果刷新 JS、15 项桌面 Python、6 项 Weather Node 测试通过。文档检查通过。宽范围 i18n 扫描发现此前 app.js/assistant-call.js 四项未翻译词条，本次新增定位词条有英文翻译；未把该扫描报告为通过，也没有做完整 Aide 发行矩阵。

## Weather 发行与界面

独立 [公开 MIT 源码](https://github.com/skyelan1999/aide-pkg-Weather) 与 [0.1.0 预览包](https://github.com/skyelan1999/aide-pkg-Weather/releases/tag/v0.1.0) 已发布，包从六文件白名单生成，下载后重新核对 SHA-256，并经 Aide 鉴权安装/升级接口装入本机。

原生 Aide 工作台实际打开，中文城市检索、明确选择天津、七天预报和网络出口天气显示通过。本机定位入口需要独立宿主点击和系统授权，当前 Mac 返回不可用，不能记为定位成功。网络位置可能是代理/远程服务器出口，界面明确标注粗定位。没有后台定位或用户定位历史入包。插件源码 MIT 与天气 API/数据条款分开；默认 Open-Meteo 免费 API 仅限非商业用途。
