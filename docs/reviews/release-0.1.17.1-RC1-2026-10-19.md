# aide v0.1.17.1-RC1

本版本将 Docker 发行内容从 Git LFS 移回 GitHub Release，减少普通源码拉取的体积，并调整启动恢复顺序。

- 普通启动优先复用平台和完整性校验通过的本地镜像。
- 缺少可用本地镜像时，先编译当前源码；编译或依赖准备失败后，校验并导入官方 Release 镜像。
- 本地 Release 包优先作为下载缓存使用；下载后验证完整 SHA-256、实际镜像 ID、平台、源码标签和 CAD 运行时。
- `AIDE_FORCE_REBUILD=1` 和显式源码模式可触发构建；`AIDE_RELEASE_FALLBACK=0` 可关闭构建失败后的镜像回退。
- 撤下当前 Git LFS 大总包、属性与制作入口，新克隆不需要 Git LFS。未强制改写旧 Git 历史；历史 LFS 对象不等同于已从托管侧永久清除。
- 同步当前 main 中的插件市场、工作台桥接及外观等既有更新；具体能力和限制以仓库文档为准。

选择与 Docker 引擎架构相同的完整离线包，解压后运行内含的 `start.command` / `start.bat` / `start.sh`。ARM64 和 AMD64 使用独立包，不能互换；完整包自带应用和 CAD 运行时，不需要现场编译。更新时保留原安装位置中的用户配置、工作区与 `.aide-data`，不要删除数据目录代替升级。

源码仓库启动使用受控 Release 清单作为回退来源，可能回退到较早的已校验发行镜像；日志会明确说明，实际版本以镜像内版本为准。普通启动复用现有镜像时，刚拉取的源码不会自动替换正在运行的镜像，需要主动强制构建。

验收状态将在实际镜像及上传校验完成后补齐；Windows 原生和其他设备接收启动不作已验证声明。本次不替换当前生产服务。
