# aide 超长对话与工业复杂任务支持说明

日期：2026-10-12
适用：aide `0.1.17.0 RC2` 当前源码线。本文区分源码能力、估算、验证与工程使用边界；写入文档不代表发布或验收通过。

## 定位

aide 面向需要长期保留上下文、连续调用工具、审阅结果并恢复工作的工程任务。它由持久化会话、受预算约束的上下文构造、历史摘要压缩、项目级记忆、SSE 增量输出和人工审批组成。长上下文通过“近期消息 + 连续摘要 + 按需读取项目记忆/文件”组织，不能等同于模型无限上下文，也不保证摘要永不遗漏。

适合的工作包括：跨多个回合的故障定位、设计讨论、工程资料汇总、代码/文档迭代、验证计划与报告草拟。其用途是辅助专业人员调查、记录和审阅；输出中的事实、推断、未验证项应分开核对。

## 能力与数据路径

| 环节 | 当前源码行为 | 工程含义与限制 |
| --- | --- | --- |
| 会话连续性 | 会话 JSON 以原子写入保存在 active、archived 或 assistant 桶；任务与消息保存在会话记录中。服务启动会将仍在运行的任务标为 interrupted；用户可按任务状态继续，不等于进程可无缝跨重启。 | 服务异常/重启时已保存的会话可恢复；内存中尚未提交的流式片段、正在运行的模型请求不能保证保留。 |
| 上下文选择 | `internal/server/context.go` 按会话消息计算约 15,000 个历史 token 的截取预算，并构造系统指令、摘要、近期消息、附件和工具 schema。 | 这是回放历史的本地预算，不是总模型窗口；提示、工具、附件、输出预留仍占用窗口。 |
| Token 估算 | 本地估算按 UTF-16 code unit 密度（约 4 个单位/token）计算；图片使用保守上界；真实 provider usage 可作为校准锚点。 | 估算不是每家模型的 tokenizer，也不是计费账单。跨模型或带图片/工具时应查看请求预览和 provider usage。 |
| 自动压缩 | 超过约 12,000 token 或较小模型窗口的 55% 阈值时尝试整理早期历史；单次最多折叠 400 条并保留近期消息。触发受当前配置和可压缩历史影响。 | 触发阈值是估算值。若摘要请求失败或期间会话发生变化，原消息应保留，稍后可重试。 |
| 手动/超限压缩 | 手动 `/api/sessions/{id}/compact` 与发起请求前的窗口超限整理共用摘要构造器；保留近期历史预算受模型窗口、输出预留与安全余量约束。 | 对话很长时一次压缩可能折叠有限前缀；压缩后仍需检查上下文预览，不把压缩响应当作事实审计。 |
| 连续摘要 | 摘要字段包括整体目标、限制、决定、文件、事实、证据和待办；前序摘要与新历史经过有界分批归并。压缩提交前校验历史快照；结构无效、provider 错误、并发修改或保存错误不会用模型原始文本替代摘要。 | 摘要是便于继续工作的索引，不是原始证据的替代品。关键阈值、告警、版本、命令结果和审批依据应保留在受控文档/任务记录，并在需要时重新读取原文。 |
| 流式工作台 | SSE 按 delta 更新；浏览器对稳定 Markdown 块追加渲染，对未闭合块只处理活动片段；超长活动片段退化为纯文本，避免每个 token 都解析全文。稳定边界扫描只检查新增字符。思考记录有界保留，默认折叠且单行预览，展开时才装载保留内容。 | 浏览器仍要为完成态内容生成最终 Markdown DOM；极端巨型回答、浏览器内存上限和所有设备长时间稳定性须以实际设备压测为准。 |
| 单次任务连续执行 | 新聊天任务默认执行预算为 7,200 秒（2 小时），流式 provider 请求超时也为 2 小时；工作流任务默认 900 秒。预算到期或用户显式暂停时，系统保存检查点并允许继续。 | 两小时是单次活动执行上限，不是 SLA，也不代表模型请求、单个工具或浏览器可无限运行。运行中的任务保持创建时的策略快照；显式续跑是新的执行段，会刷新该模式的当前预算，其他策略仍沿用原快照。升级后已有配置若明确保存了 360 秒，须在“设置 → 执行策略”改为 7,200 秒并保存。 |
| 项目记忆 | `read_memory` / `write_memory` 作用于当前项目 `.cache/aide/` 下的 `memory.md` 与 `memory-tokens.json`。应用内文件锁串行化同一 App 的记忆读写；文本投影和 token JSON 原子写入，读取时验证 hash，容量上限 24 KiB。 | Tokenizer `unicode-scalar-v1` 是本地字符级编码，不是模型 BPE。项目记忆会进入后续请求上下文；使用远程 provider 时，发送到 provider 的提示内容受其服务边界约束。用户可编辑文本投影；检测到外部修改时作为替换快照导入，而不是重复追加。 |
| 工具与审批 | 模型可按执行策略请求工具；有副作用的命令/文件提案按现行审批策略处理，运行记录保留在任务中。工作流工具轮数默认 60，可设置 5–200。 | 较长任务要拆成可审阅阶段。审批通过只表示允许尝试该操作，不证明操作成功、输出正确或设备安全。 |

## 长对话中的准确性做法

1. 把目标、限制、参数单位、已决定事项和待办写成可核对的短条目；发生变更时明确新旧值和生效时间。
2. 对会影响设备/生产系统的结论，要求文件路径、日志时间戳、命令回执或仪表读数等原始证据。摘要中的“已完成”需回查独立记录。
3. 当模型切换、来源目录变化或任务跨班次时，重新读取当前配置和关键文件；不要假定旧摘要中的环境仍然有效。
4. 出现 provider 超限、网络中断或摘要失败时保留当前会话，并从最近一次持久化状态重试；不要反复压缩同一份未变化的巨大输入。
5. 涉及数值安全阈值时，来源文件/数据库或现场测量是控制依据；模型摘要只作为导航与解释材料。

## 工业场景的适用边界

aide 可用于工程知识检索、跨文档调查、变更方案草拟、故障排查过程记录、代码审阅辅助和报告整理。是否用于某条生产流程，应由组织按数据分类、provider 合同、权限配置、审计留存和人员复核流程评估。

当前源码与本说明**不构成**功能安全认证、设备控制许可、确定性实时系统、无人工监督的保护逻辑、法规符合性声明或 SLA。不得让模型摘要、模型建议或自动审批成为急停、联锁、保护定值、医疗/航空关键决策的唯一依据。对于会影响现场的动作，使用最小权限、逐项审批、可回滚步骤和独立测量/复核。
