# 消息未读、未完成事项与免打扰机制（设计稿）

状态：已进入实现候选；详见任务中的实际验收证据。任务：[message-notifications-20261019](../tasks/message-notifications-20261019.json)。基线 main `6136df16`。

## 目标与现状

用户希望消息入口、会话与群组显示未读气泡，未完成提醒也能汇总，在设置管理红点，并允许单聊和群组屏蔽提示。用户随后要求实现；本轮已实现候选，保持生产实例和现有 Release 不变。

原有 `internal/server/web/message-center.js` 的 `updateBadge()` 直接合计 incoming 消息、待处理邀请和提醒数量；提醒数字通过另一个 DOM 节点读取。原实现没有独立的分类角标策略和单会话免打扰。新机制复用消息、群组、邀请和提醒记录，避免再建立一份互相漂移的业务状态。

## 展示与计数

| 位置 | 默认展示 | 清除条件 |
| --- | --- | --- |
| 消息入口图标 | 红色总数，超过 99 显示 `99+`；悬停或聚焦显示分类明细 | 所有纳入统计的未读和待办均清除 |
| 会话、群组列表行 | 各自未读数；群组折叠后也保留聚合数 | 已实际阅读或手动标记已读 |
| 联系人／申请页签 | 仍有效且等待本人决定的申请数 | 同意、拒绝、撤销、过期 |
| 提醒页签 | 未完成事项数；列表同时展示未到期、到期、逾期状态 | 完成、取消、删除；稍后提醒只改变提醒时间 |
| 文件传输页签 | 等待本人接受、失败后需重试等需处理项 | 接受后进入传输、重试成功、取消等状态变化 |

默认将全部未完成提醒纳入数字，满足“未完成的都会显示”；设置可以改为仅统计已到期／逾期。未到期事项在列表中使用普通状态，不伪装成错误告警。后台正常传输、正常运行或排队中的任务只显示进度，不因尚未结束而不断增加红点；需要批准、补充信息或失败处理才属于待处理项。

总数 = 符合策略的未读消息数 + 去重后的待处理申请／传输数 + 符合策略的未完成提醒数。未读按消息条数、待办按事项数计；分类明细解释数字来源。页签数、群组聚合数和子项数不再次相加；同一个文件邀请出现在申请与传输两处，仍只计一项。同一提醒兼有“未完成”和“逾期”也只计一项。

红色气泡只有一种主样式；不同时叠放红点、数字和叹号。免打扰会话可以显示低强调的灰色未读数。角标不挤压图标或列表高度，数字使用等宽数字，保留足够对比度；读屏名称提供类别和真实数量，不只读“99+”。

## 已读与完成是两种状态

- 打开消息中心、进入会话列表、展开群组，不直接清空未读。
- 只有当前页面可见、已解锁、具体会话激活且相应新消息确实展示在可读区域，才推进该会话的已读游标。用户停在历史消息处时，后续消息继续保持未读。
- 标记已读提交明确的“已展示到哪条”游标；请求发出之后新到的消息不能被顺带清除。
- 提供“当前会话标记已读”和“全部消息标记已读”，不将未完成提醒顺带标为完成，也不自动同意申请。
- 查看提醒只表示已经看过；完成必须由明确操作或原有可靠的任务完成状态触发。到期再次提醒可以再次产生提示，但不重复增加事项数。
- 重启、刷新、流式重连不能把已经处理的历史事件重新变成未读。

## 设置入口与优先级

全局设置增加“通知与角标”，消息中心的设置按钮跳到同一配置，避免两份设置互相覆盖。

1. **角标样式**：数字（默认）／仅红点／关闭。关闭只隐藏角标，不删除未读记录。
2. **计入总数的内容**：单聊、群聊、联系人与群组申请、需处理的文件传输、未完成提醒，分别开关，默认开启。提醒范围可选全部未完成（默认）／仅到期与逾期。
3. **提示方式**：应用内提示、声音、浏览器桌面通知分别管理。声音和桌面通知默认关闭；桌面通知只有用户主动开启时才请求浏览器权限，拒绝后不反复弹权限申请。
4. **免打扰会话是否计入总角标**：默认不计入；开启后只恢复计数，不自动恢复声音和弹出提示。
5. **屏蔽列表**：统一查看并解除单聊／群组的设置，显示临时免打扰的到期时间。

单聊／群组右键或更多菜单提供：跟随全局、免打扰、屏蔽全部提示。免打扰默认不弹出、不响铃、不计入入口总红点，但会话行保留灰色未读数；屏蔽全部提示连该会话行的角标也隐藏，仅保留屏蔽标识。两者都继续接收并保存消息，均不等于拉黑、退群或标记已读。

免打扰时长可选 1 小时、8 小时、永久；到期恢复跟随全局，不追发过期声音或连续弹出积压通知。恢复后依照当前未读状态计算角标。

判定顺序：全局关闭某个提示渠道 → 会话屏蔽／免打扰策略 → 分类开关及提醒范围 → 展示样式。分类复选框只控制角标计数，不隐式修改弹出、声音或桌面通知渠道。全局关闭的渠道不能被会话设置重新打开；“计入免打扰总数”不能覆盖“屏蔽全部提示”。

群组内消息与自动生成的群组提示继承群组策略。用户主动创建的个人提醒独立遵循提醒设置，避免一次群组免打扰让个人定时事项意外失效。首版不承诺尚未具备协议支持的群聊 @ 提及或关键字特例。

## 状态、同步与性能

后端统一返回全局、分类及各会话的摘要；前端不再从提醒 DOM 或当前加载的消息页推导真实总数。消息分页多少、是否展开群组和浏览器是否前台，都不能改变应有的统计结果。推送只负责使摘要失效或增量更新，重连后用权威摘要校正。

配置保存在软件启动目录管理的持久配置区；已读游标保存在原消息持久存储中，均不放在可清理的 Docker 构建缓存内。以联系人稳定身份、群组 ID 为键，改名不丢设置。全局配置与会话覆盖分层存储，局部修改不能覆盖其他会话的配置；后端校验版本并返回实际保存结果。

同一实例的多个标签／浏览器共享服务端状态；已读游标单调推进，旧响应不能让角标反弹。不同独立安装实例不在首版擅自同步已读或偏好。锁屏时隐藏消息明细，锁屏后的请求不能继续标记已读；解锁后恢复摘要。提示按事件 ID 去重，只针对新事件发出，重连和初次加载不轰炸历史通知。

## 实施顺序与验收

先统一服务端摘要、去重与游标边界，再接入入口／页签／会话角标，最后加入设置和会话菜单。旧配置无新字段时采用上述默认；已有已读和完成状态保留，不把全部历史消息重置为未读。

验收至少覆盖：单聊和群聊计数、折叠群组、消息分页不漏数、同一邀请跨页签去重、已读请求与新到消息竞态、查看提醒不完成、全局总数分类明细、三种角标样式、两种会话屏蔽、免打扰到期、多窗口同步、刷新重启、重连去重、锁屏中止以及配置被 Docker 缓存清理后保留。

## 实现候选与边界

基础通知功能已合入 main（合并 `64e30f9f`，交付记录 `e567f195`），尚未发行包含该功能的新版本或替换用户生产服务。后续按钮与行内配置卡片修复已按用户要求合入本地 main（`9f3f5673`，推送状态见验收记录），详见[按钮布局验收](../reviews/2026-10-19/message-buttons-ui.md)。

- `internal/messaging/unread.go` 从全部保留的消息计算未读，不受快照仅返回最近 500 条影响。新建本机接收序号和已读序号，旧时间游标兼容迁移。新前端通过具体消息 ID 提交已读边界；明确的旧版“标记会话已读”接口继续兼容。
- `internal/server/message_notifications.go` 统一汇总消息、待处理邀请、传输清理错误和未完成提醒。文件邀请跨联系人／传输只计一次；工作区提醒仅统计全局和当前工作区。一般的传输进度和前端临时暂停不被伪称为服务端持久化错误。
- 配置位于启动目录挂载的数据区 `config/notifications.json`（权限 0600），独立于消息通信设置及 Docker 缓存；保存免打扰不重启网络。单条规则局部更新，版本冲突返回 409；锁屏或锁代际变化拒绝写入。
- `GET /api/messages/state` 增加 `notifications.config` 和 `notifications.summary`；消息数据增加 `unread` 和 `readThrough`。`GET/PUT /api/messages/notifications` 管理通知策略；`POST /api/messages/read` 可携带 `through`，`POST /api/messages/read-all` 接收各会话明确的消息边界。
- 设置 → 通知与角标，以及消息面板标题中的同名入口管理全局规则。按钮修复候选在各会话／群组行和聊天工具栏提供通知图标与行内展开配置卡片，避免浮层覆盖或滚动裁切；设置页集中列出屏蔽／免打扰会话。折叠群组保留子项聚合，只有免打扰未读时使用灰色，不再次加入入口总数。
- 新消息按会话批量合并，每轮最多 5 个弹出／桌面提示，提示音每轮一次。音频上下文复用并在页面离开时关闭；浏览器可能要求一次用户交互才能播放。只有用户主动保存启用桌面通知时才请求权限。首屏、刷新、重连的已有消息不集中补弹；锁屏、免打扰和正在阅读的会话不弹出。
- 后端状态持续持久化，浏览器只是展示摘要。页面打开时前台约 2 秒、后台目标约 15 秒轮询；后台计时仍受浏览器节流，浏览器彻底关闭时不提供系统推送服务。不会把这个方案称为独立于浏览器生命周期的系统推送。
