## 1. 需求来源（用户原话）

> 参考你的（deepseek dsh）的设计，在 aide 的左侧添加上下文统计和模型选择功能，模型可以在左下角的入口中添加多个模型，自动获取可支持的模型名称，api 还是之前的 api。

## 2. 需求分解

| 编号 | 需求 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| FR-67 | 多模型管理 | 模型设置支持多模型列表（id＋名称＋上下文窗口），可增删、标记当前；旧 `settings.json` 单模型格式自动迁移；模型数 ≤20；保存后写回 `/data/settings.json` | 已实现·已验证 |
| FR-68 | 模型名称自动获取 | `GET /api/models` 代理 `{baseURL}/models` 拉取可用模型列表（转发密钥，30s 超时，≤2 MiB）；前端「自动获取」填入候选；不支持/失败时友好提示 | 已实现·已验证 |
| FR-69 | 侧栏模型选择 | 左侧新增模型选择入口（参考 DSH 模型选择器）：展示当前模型，点击弹出列表切换，切换后立即生效于后续任务；任务记录本次所用模型（Task.Model） | 已实现·已验证 |
| FR-70 | 上下文统计 | 左侧新增上下文统计卡（参考 DSH token-meter）：估算 tokens = Σ ceil(消息字符数/4) + 每消息 4 开销（历史回放预算 60,000 字符内），进度条对照当前模型上下文窗口；随会话加载/发送/轮询/附件变化更新 | 已实现·已验证 |

## 3. 关键决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| D1 数据模型 | `Settings` 增 `models:[{id,name,contextWindow}]` + `activeModel`；`Model` 字段保留为当前生效模型 id（`complete()` 与既有校验零改动） | 最小侵入 + 向后兼容；`settings.json` 旧格式启动时内存迁移（Models 为空且 Model 非空 → 单模型包装），下次保存时落盘新格式 |
| D2 模型获取 | 后端代理 `GET {baseURL}/models`（OpenAI 兼容 `{data:[{id}]}`），解析失败报错；前端 datalist 展示候选 | 避免浏览器跨域/暴露密钥；服务端已持有密钥 |
| D3 上下文估算 | 采用 DSH token-meter 同款固定密度启发式：4 字符/词 + 每条消息 4 token 角色开销；只统计 60,000 字符回放预算内的最近消息；进度分母 = 当前模型 `contextWindow`（缺省 65,536） | 与 DSH 设计一致；无真实 tokenizer 依赖，界面标注「估算」 |
| D4 上下文窗口 | 每模型可配 `contextWindow`（1024–1,048,576，缺省 65,536） | DSH 模型目录携带上下文窗口，统计卡据此出进度 |
| D5 切换生效 | 侧栏切换模型 = `PUT /api/settings`（models + activeModel，密钥按既有规则保留）；任务启动时快照 `Model` 写入 Task.Model | 切换立即生效于后续任务；历史任务记录保持当时模型 |

## 4. 非目标（本期不做）

- 不做每个模型独立 API Key / Base URL（「api 还是之前的 api」）。
- 不做真实 tokenizer 精确计数（保持估算并标注）。
- 不做按会话记忆模型选择（全局当前模型）。
