# 锁屏跨页同步与解锁恢复

用户报告：多个页面锁屏状态不同步，解锁后会话／请求恢复异常。任务 [lock-sync-recovery-20261019](../tasks/lock-sync-recovery-20261019.json)，验收记录见 [review](../reviews/2026-10-19/lock-sync-recovery.md)。本轮没有修改密码验证算法、后端身份接口、锁文件格式或生产密码。

## 权威与状态转换

| 状态层 | 作用 | 不应承担的职责 |
| --- | --- | --- |
| 服务端 locked/gen | 当前持久锁态，旧代次不能覆盖新代次 | 不含页面选举身份 |
| joining/master/slave | 确认状态、选举心跳与空闲活动协调 | 心跳视觉值不能盖过已知服务端锁态 |
| 显式锁意图与序号 | 立即遮盖；待落盘或保存失败仍保持遮盖；新锁作废旧解锁收尾 | 不允许无身份验证写入全局解锁 |
| 本页已验证放行 | 保留现有局部放行语义；新锁使其失效 | 不改变其他页面和服务端全局锁态 |

首次 joining 显示中性遮罩，读取权威后收敛；不可达保留既有保守超时逻辑。页面在 joining／重选期间离开再返回时重新启动选举；已知锁态在重选中继续有效，不因短暂角色变化变成未锁。工作台和星图初始化在 onReady 后重新读取当前状态，避免使用过期的首次就绪结果。

相同锁态心跳只维持协调，不重复触发界面恢复。只有真正的锁定／放行边沿才触发一次本地停用／恢复。服务端拒绝未验证解锁、身份回执代次校验和新锁优先规则保留。联动策略暂沿用现有语义：主控页面解锁联动其他页面；slave 页面可独立验证并仅放行本页。用户若要求任意页面全局解锁，应作为明确的产品策略变化处理。

## 恢复内容

- 锁定取消旧的草稿写入、轮询与延迟会话对账；已有 SSE 继续接收增量缓冲，不主动断流造成文本缺段。后端任务继续运行。
- 解锁后读取当前会话新快照，清除终态运行的旧临时状态，修正仍运行任务的过期 done 标志，恢复轮询。读取失败最多补两次重试；重新锁定、切换会话／工作区／身份会取消或丢弃旧结果。
- 不重置发送框、附件或文件 XML 草稿，不自动重发任务，不替用户提交模型请求。
- 已打开且仍处于预览模式的 URDF，用当前草稿与新锁作用域重新安装查看器，避免旧的 isCurrent 永远失效。已关闭、换文件或切换工作区的预览不自动打开。其他格式原有生命周期不在本轮扩大重构。
- 自动保存仅按既有用户开关恢复调度，不强制保存未授权文件。远端全局放行不恢复其他页面麦克风。

## 验证与交付边界

新增真实模块多标签时钟回归、延迟响应隔离回归和实际工作台双页面验收。锁屏依然是视觉保护，不是 bearer API 的账户注销或访问撤销。触控 ID 硬件、Windows、不同浏览器和真实付费模型运行需分别验收。源码主线合并、Docker 启动验收、公开 Release 与生产部署分开记录，不互相替代。

源码检出目录中的普通启动会优先复用已有完整镜像。需要从新源码更新运行实例时，使用 `AIDE_BUILD_FROM_SOURCE=1 ./start.command` 进入源码检查／构建路径，再刷新各个旧页面。该命令更新运行服务，应安排在可接受服务重启的时点；本轮隔离候选与生产实例分别记录。
