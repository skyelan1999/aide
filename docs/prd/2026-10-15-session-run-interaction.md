# 会话运行控制与流式输出

任务：[session-run-interaction-20261015](../tasks/session-run-interaction-20261015.json)。用户希望参考 Codex 的运行交互，统一原来并列的暂停、停止，以及会话和流式渲染。

依据：OpenAI 公开[提示交互说明](https://learn.chatgpt.com/docs/prompting)区分 Steer（调整当前工作）与 Queue（等待当前回答后处理）；[IDE 设置说明](https://learn.chatgpt.com/docs/ide/settings)允许选择默认行为。以下是 AIDE 的产品设计，不声称复刻 Codex 私有实现，也不把“保存检查点并暂停”归为 Codex 已有功能。

## 控制区

| 状态 | 输入区行为 | 保留与后续 |
| --- | --- | --- |
| 空闲 | 向上箭头发送 | 新任务 |
| 运行、无草稿 | 原发送位置显示一个停止按钮 | 结束本轮，保留已输出正文和工具记录；之后发送新消息 |
| 运行、有草稿或附件 | 箭头发送；停止移到上方运行条 | 可随时插话或选择排队，不需要先停止 |
| 等待回答/审批 | 仍能停止；有草稿时标为发送回答 | 回答依照原澄清/审批门禁处理；排队开关禁用 |
| 暂停中 | 状态提示正在暂停，停止仍能升级结束本轮 | 不接受继续插话，等待后端确认 |
| 已暂停、检查点可用 | 运行条显示继续任务 | 恢复前保留原效果核查，不重放未确认操作 |
| 停止中 | 停止禁用，明确显示正在停止 | HTTP 成功只代表受理，持久化终态才决定最终结果 |
| 已停止/中断 | 保留正文与说明，无红色取消错误 | 停止不会撤销已完成的工具操作 |

“保存检查点并暂停”放入运行条“更多操作”，检查点尚未准备好时禁用。最新暂停任务的继续入口集中于输入区；历史暂停任务可在原记录恢复。停止优先于已受理的暂停，后来的暂停不能覆盖停止。任务已完成时的迟到停止不改变成功结果。

## 会话与流

沿用既有会话内插话与排队后端：插话在工具循环边界生效；排队在当前模型回答完成后接续处理。排队并不另建独立 Task，不声称等同 Codex 的内部 turn 实现。输入保留为正常用户气泡，不能凭受理回执声称模型已经采用。

正文增量使用既有稳定块缓存与动画帧批量渲染。`done` 到达后保持正文，直到 GET 获得当前运行的持久化结果再释放临时状态；GET 失败保持轮询兜底。迟到的动画帧不能覆盖终态正文。暂停/停止说明只出现一次；没有正文的取消不虚构模型错误。活动任务等待澄清时不显示重试、普通继续等终态操作。

思考内容由同一张状态卡负责，工具 intent 使用 callId 去重；不认识的工具结果不能把另一个调用标为完成。等待回答的 SSE 重连保持订阅，后续 clarification-resolved、delta、done 继续传送。连接关闭本身不能作为任务完成证据。

## 持久化与兼容

Task 新增可选 `stopRequested`；旧数据缺省 false。停止意图先保存，再释放全局锁并调用取消，避免阻塞其他会话。保存失败还原原暂停意图且不取消。服务重启时已受理停止的运行转 cancelled，保留可见输出，清理可恢复检查点；不会误显示为可续跑的 interrupted。检查点恢复建立新运行并重置停止意图。

现有 API 路径和成功码保持兼容；暂停、停止请求、草稿与渲染仍受工作区/会话归属约束。模型策略、并行上下文口径、沙箱与审批策略不因这次界面整理改变。
