# Context recovery and incomplete output

Issue: [#580](https://github.com/skyelan1999/aide/issues/580). Applies to normal execution and model-only parallel scheduling/workers.

The request builder meters all unsummarized session messages. It no longer takes an arbitrary 15k-token suffix, which could hide an early constraint or start with a tool result whose call was omitted. Existing preflight compares this complete request with the selected model window and output reserve before invoking session compaction. Histories beyond the 400-message batch limit continue through further progress-checked passes under one total deadline; a single pass is not mistaken for completion.

Compaction passes long message bodies and tool arguments through numbered, bounded source chunks. It does not remove a source message's middle before asking the summarizer to inspect it. This preserves coverage of source text, not lossless semantic memory: the model still produces a bounded, selective structured ledger. Arrays/field lengths remain bounded. Text-only goal arrays and scalar list items are normalized without a second model call; malformed JSON and numeric/object field shapes still fail without committing. Images are explicitly marked as not visually inspected by this text-only summary.

History cuts preserve assistant tool-call/result exchanges. A completed oversized final message may be folded completely; an unfinished tool exchange remains raw. Session writes retain the existing snapshot checks and atomic save; cancelled or invalid summaries do not overwrite source history. Summary parsing accepts a valid JSON object wrapped in a Markdown fence or brief surrounding prose, then applies the same strict field/type validation. If a model returns malformed or truncated JSON, the same bounded source batch is requested once more with a stricter concise-output instruction. The implementation never repairs missing JSON delimiters or commits a partial summary; if the retry is still invalid, compaction fails and the original history remains intact. Each tool-free summary HTTP request may additionally be replayed once after EOF or unexpected EOF, with a cancelable 200ms backoff. API-status errors, timeouts and user cancellation are not replayed. The generation and stricter-format regeneration each have this transport bound, so a malformed-response path with a transient EOF in both requests can issue at most four HTTP attempts. Original history still commits only after complete summary validation. This retry does not apply to executor tool calls or visible streamed output.

During an active loop, tool results and parallel notes can outgrow the starting request. A local candidate is compacted before model calls, retaining the initial policy, current and latest user scope, and image-bearing messages. The same budget check applies after model routing and to planner/worker calls. The candidate is used only after summarization succeeds and its actual estimated size fits. If pinned current input/images/tool definitions alone cannot fit, execution reports the capacity error without silently discarding them. Usage calibration is bound to the session compaction generation. Pre-compaction usage and transient active/parallel summary anchors cannot inflate the next ordinary request. Task checkpoints persist the accepted execution context; source session history is separate. Active compaction emits started/completed/failed SSE metadata.

A text SSE response needs either a finish reason or the terminal `[DONE]` marker to count as complete. Premature EOF preserves partial text and usage, discards tool-call fragments, and pauses a visible partial answer at a resumable checkpoint. It does not blindly repeat visible text. User cancellation and existing length continuation remain separate paths. Recovered checkpoint content contains the partial answer exactly once.

## Verification

`internal/server/context_recovery_test.go` exercises the four pre-fix failures, an oversized final message, incomplete tool exchange, active-loop capacity, failure rollback and resumable partial output/accounting. Adjacent compaction, provider-stream, parallel, staged-output, retry and cancellation tests guard shared behavior.

`TestContextRecoveryLiveModels` is opt-in through `AIDE_CONTEXT_LIVE_DATA` and uses a read-only local credential envelope. It does not load real sessions, project memory or personality. Tests call `gpt-6.1-sol` and `deepseek-flash` with synthetic records, compact middle facts, then supply only the produced summary to a new API run. The default matrix is 1x/3x; `AIDE_CONTEXT_LIVE_PARALLELISM=5,10` selects the extended matrix. `AIDE_CONTEXT_LIVE_MODELS` can narrow the model list, and `AIDE_CONTEXT_LIVE_TASKS=simple,complex` runs paired task types at each selected parallelism with fixed matching synthetic inputs. In this matrix, usage totals sum the app's provider call records since test setup, including preflight compaction; `taskUsageExcludingPreflight` is retained separately. More than one completed analysis worker is required for the 3x cases. The 5x/10x probes provide independent named design tasks and require exactly five/ten completed workers, one final occurrence of each task label, and fitted request budgets. Safe synthetic results may be written via `AIDE_CONTEXT_LIVE_PROOF`; credential envelopes and raw local config are never published. Without the opt-in, the test is skipped, not a model acceptance pass.

The [extended live-model evidence](../reviews/2026-10-29/context-recovery-high-fanout-proof.json) records four successful 5x/10x runs across both models, with 30 real completed analysis workers and only summary-based new-session recall. All workers completed in the first planning wave; snapshot counts were 7 for 5x and 12 for 10x, without truncation. The production source hashes match the original 1x/3x matrix. This supersedes the original matrix's real-10x coverage limit, while retaining its historical record. Codex Bridge usage is marked estimated; Flash usage is upstream-reported. This is one synthetic run per setting, with restored configured windows for fanout, not a near-capacity or sustained-load benchmark.

For chat tasks whose latest user prompt explicitly marks multiple items as independent (`[CASE01]`, `[TASK-02]`, or `[SUBTASK 3]`) and says they are independent, the scheduler dispatches those items directly instead of spending a serial model request asking a planner to rediscover the decomposition. A consecutive numbered list beginning at 1 can also dispatch directly when the surrounding prompt explicitly calls the items independent; sequential instructions, gaps, duplicates, malformed entries, and unmarked lists do not. If there are more items than the selected fanout, adjacent items are grouped so none are dropped. The common worker context drops only the recognized task lines. Other tasks still use model planning; simple or sequential tasks may correctly remain on the main executor. Analysis workers remain read-only and tool-free.

For legacy analysis checkpoints (new chats use the [async execution environments](../designs/execution-environments-20261101.md)), worker requests share one evidence history and differ only in the final assignment instruction. The scheduler fits the longest assignment template once against the smallest selected worker model window, then reuses that fitted history for each worker. This prevents redundant concurrent compaction calls and avoids resending oversized raw history to every worker. The original executor context remains intact for the final merge; if that full context plus results exceeds its own budget, the existing safe fallback continues with the original context. A regression test forces worker-context compaction and checks that every worker receives the compacted evidence and no tools.

For explicitly labeled, independent, tool-free analysis/drafting requests, the scheduler may skip the serial final synthesis call when every worker returns its exact label once and the assembled draft satisfies any explicit per-section requirements detected in the request (for example checks, evidence, unknowns, risks, dependencies, pass criteria, or two requested items). The usual task-delivery validation still runs. Missing labels or requested content fall back to the normal main-model synthesis. This shortcut is limited to the clearly scoped no-tool draft path; it does not skip tool execution, verification, approvals, writes, or other main-executor work.

When one model response batches two to ten independent local reads, the executor can run `read_file`, `list_files`, `semantic_search` and safe relative `.docx` `docx_structure` calls concurrently. Multiple local semantic searches share one read-only corpus scan within that batch. There must be no reference-source arguments or matching task hooks. It still checks and checkpoints each dispatch in call order, executes the reads concurrently, then records and returns results in the model's original call order. Mixed batches, SSH, reference-source reads, unsafe or malformed DOCX paths, stateful comment operations, unknown tools, shell, plugins, hooks, and batches above ten calls remain serial. This speeds independent repository/document inspection while preserving deterministic audit and conversation ordering; it does not parallelize build/test commands or write operations.

The performance acceptance target requested on 2026-11-01 is a very complex task taking about 10 minutes at 1x completing within 1 minute at 10x with equivalent coverage and quality. Earlier Luna synthetic 10x runs completed ten workers with label coverage and fitted budgets in about 30 seconds, but their 1x counterparts were only about 15 seconds and worker contexts fit without compaction. The stricter numbered-list pair also did not speed up at 10x. A separate oversized-context regression test exercises shared compaction locally; none of these measure a live 10-minute-class workload. These results therefore do not validate the target. Analysis fanout and independent local file-read batches can overlap; write operations, builds, tests, approvals, and final verification remain serial, so end-to-end speedup still depends on how much of the task can safely be split.

The explicitly labeled no-tool draft path has a deterministic assembly shortcut after worker completion. On the same synthetic Luna ten-domain prompt, the quality-checked 1x model call took 12.17 seconds of execution time (8,463 reported tokens); the latest strictly checked 10x run completed ten workers and skipped a separate synthesis call in 4.88 seconds, with 28,785 reported tokens. An earlier worker-level quality repeat took 4.26 seconds and 28,766 tokens. The latest 1x and 10x answers passed the stricter final-text acceptance check: every section contained the requested checks, evidence, unknowns, and two-check structure; the opening retained the synthetic identifier and threshold; labels appeared once; budgets fit; and the response clearly stated that the suggestions had not been executed. The harness's separate context-recovery preflight added 5.43–6.37 seconds for this final pair, so measured test wall time was about 10.7 seconds for 10x and 19 seconds for 1x. The 10x run used about 3.4x the upstream-reported tokens of the 1x reference. This short synthetic case shows about 2.5x faster model execution and 1.8x faster harness wall time; it is not a 10-minute-class benchmark and does not establish the requested 10x end-to-end target. Fast-path proof: first run (`.agent-state/parallelism-cost-luna-fast-assembly-10x-20261101.json`, local-only raw receipt), worker-level repeat (`.agent-state/parallelism-cost-luna-fast-assembly-10x-quality-repeat-20261101.json`, local-only raw receipt), and latest final-text quality run (`.agent-state/parallelism-cost-luna-fast-assembly-quality-final-10x-20261101.json`, local-only raw receipt); matched quality-checked 1x reference: paired run (`.agent-state/parallelism-cost-luna-fast-assembly-quality-pair-1x-20261101.json`, local-only raw receipt).

Parallel workers now inherit the requested profile output budget up to 8,192 tokens instead of being silently capped at 2,048. When the smallest selected worker context is known, the reserve is limited to half its window to leave room for shared evidence and instructions. Luna verified the reserve in ten worker snapshots; the matched short `extreme` workload still ran slower at 10x (28.60s execution, 37,395 tokens) than at 1x (20.50s execution, 8,922 tokens). The larger output budget removes a truncation limit but is not itself a speedup, and the 10-minute-to-1-minute target remains unverified. See worker-budget Luna pair (`.agent-state/parallelism-cost-luna-worker-budget-20261101.json`, local-only raw receipt) and [the measured benchmark report](../reviews/2026-11-01/parallelism-cost-luna-benchmark.md).

A stricter, same-prompt Luna sample using a plain numbered list required two checks, evidence, risks, dependencies, pass criteria, unknowns, all ten headings, the synthetic identifier and threshold, and an explicit non-execution statement. The 1x answer passed in 16.25 seconds of execution (8,933 reported tokens); the 10x answer passed with 10/10 completed workers in 18.34 seconds (37,315 reported tokens). Preflight took 5.02 seconds for 1x and 4.25 seconds for 10x. This workload did not get faster at 10x, because one concise single-call answer was cheaper than ten parallel prompts and drafts; it is a quality and numbered-direct-dispatch check, not the requested ten-minute workload. Proof: numbered extreme pair (`.agent-state/parallelism-cost-luna-numbered-extreme-20261101.json`, local-only raw receipt).

This change does not deploy 9999, publish a release or alter provider settings. Rollback is reverting the fix commit; no persisted schema migration is introduced.


For explicitly independent existing local code-file edits, the [parallel file-draft candidate](../designs/parallel-file-drafts-20261101.md) can wait for complete versioned reads, bind each original file into a model-only worker request, and register validated path/content drafts through ordinary main-executor write_file dispatch. It preserves normal approval and apply-time version checks, limits the optimization to fully retained originals, and falls back for clipped previews and unsupported policy/workspace conditions. Final explanation, proposal registration and approval/application remain main-executor stages; worker completion is not application or test evidence. See the current [coding benchmark evidence](../reviews/2026-11-01/parallelism-cost-luna-benchmark.md) rather than extrapolate ten-minute performance from the small pilot.
