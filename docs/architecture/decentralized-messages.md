## 用户确认的范围

将工作台“提醒”入口扩展为“消息”，保留原提醒与到期通知。增加联系人、聊天、语音、多人语音、群组与需接收许可的文件分块续传。用户已确认 Windows、macOS、Linux，局域网直连，并允许配置自托管引导/中继进行跨互联网通信。

消息中心按“会话、联系人、传输、提醒”分区，集中展示待处理申请、未读与通话状态；不把审批按钮散落在工作台 AI 会话里。麦克风采集、来电接听、加入群组、接收文件均由人明确操作，模型不能代同意。

## 设备身份与六位查找码

每个安装实例首次启用消息时生成独立 Ed25519 身份种子，在既有本机加密保险库存储。完整身份是公钥的 SHA-256 指纹；查找码取其前 30 位，采用六字符 Crockford Base32。查找码只用于发现索引，不是密码、访问令牌或全球唯一保证。不能截断为六位十六进制后当成身份。

任意有限短码都可能碰撞。发现结果保留相同码下的所有公钥候选；用户核对账户名称与完整指纹后才发联系人申请。已有联系人永远绑定完整指纹，地址变化只更新已签名路由提示；不把相同短码下的新密钥当成原联系人。发现节点的签名只能证明持有该密钥，不能证明其现实身份，首次添加须通过另一可信渠道核对。

密钥不依赖 IP、MAC、网卡序列号或可变主机名。重新启动或换网不改变身份。删除密钥、重装且未恢复专用身份备份会产生新身份；复制身份数据会克隆同一身份，不能把整个数据卷直接复制到多台电脑并期待得到不同设备号。普通配置导出不应导出设备私钥。后续身份迁移须显式告知旧、新设备，并撤销旧设备；不承诺跨系统存在不可复制的硬件标识。

## 端到端与中继边界

原工作台 HTTP 鉴权面向本机浏览器；设备间通信使用独立、默认关闭的监听器和独立密钥，不把工作台 access-token 发给联系人。Go 服务是本机通信端点，浏览器通过既有鉴权 API 访问它。

设备间采用标准 TLS 1.3 双向认证。发现卡包含签名的设备公钥、短期地址提示及该身份自签证书。客户端使用选定证书建立专用信任根，保留正常证书、主机名、有效期校验；不使用 `InsecureSkipVerify`。服务端校验证书与密钥持有证明，然后以 TLS 对端的完整公钥指纹进行应用权限判断，绝不信任 JSON 声称的发送者。

局域网发现与引导目录只交换签名发现卡。跨互联网中继转发字节隧道，内层 TLS 握手和内容在最终设备间完成；中继不能解密消息、文件、语音信令。中继仍可观察在线状态、连接地址、流量、时序和路由指纹；不声称匿名或元数据完全保密。可配置多个自托管中继，不能依赖开发者单点服务。没有公网可达地址、引导信息或可达中继时，六位码本身不能凭空建立跨 NAT 连接。

浏览器语音采用 WebRTC DTLS-SRTP；SDP/ICE 通过设备认证后的加密消息通道交换。STUN/TURN 是可配置的网络穿透设施，不是身份来源。TURN 中继无法解密端点之间的媒体；多人语音使用小组网状连接，不能将普通解密媒体的 SFU 宣称为端到端加密。首轮群组规模限定为 8 人，以约束网状媒体的连接数、带宽和设备负载；大量电脑可分属不同群组，不意味着一个通话支持无限人数。

TLS 的前向保密不等于聊天记录具有 Signal 双棘轮的事后入侵恢复能力。不把本方案描述为已实现 Double Ratchet、MLS 或经独立密码学审计的通信产品。本机后端、解锁的浏览器、系统管理员和恶意插件属于端点信任边界，不能由传输加密抵御。

## 双向同意与反骚扰

所有邀请具有随机 128 位 ID、资源范围、完整对端指纹、方向、状态和截止时间。联系人状态为待接收、已同意、已拒绝、已撤销；只有双方同意才开放私聊。正在等待、拒绝、过期、拉黑均不允许发送聊天内容。

联系人许可不扩展到任何群组、通话或文件。每个群组邀请、每次单人或多人通话、每份文件单独同意。群成员持有针对群组与邀请 ID 的设备签名入群证明；群主不能仅通过将某人列入名单使其成为已同意成员。多人来电只包含本次已接听的人，入群同意不能代替接听同意。

拉黑在后端执行，同时撤销该对端所有待处理与已同意的资源许可。解除拉黑不恢复联系人或旧许可。每条消息、每次信令和每一块文件都重新检查当前权限；打开页面时检查一次不能构成持续授权。拒绝、撤销、重放、错对端、错资源与存储失败均需回归测试。

陌生设备只能发送有界联系人申请。限制申请频率、待处理数量、发现包尺寸、请求体、连接数和存储容量；不将短码可猜测性当作访问控制。被拉黑者看见统一不可用结果，不返回拉黑详情。阻止同一身份不等于能阻止恶意用户生成无限新身份，因此仍需设备端与中继端的资源/速率控制。

## 文件传输

邀请阶段只发送显示名称、字节数、固定分块大小和每块 SHA-256。接收方同意后才允许上传数据。首轮单文件上限 1 GiB，块大小 1 MiB，接收配额 4 GiB；限制需要在发送端、接收端和存储层共同执行。

接收方逐块校验长度与 SHA-256，原子写入独立 AES-256-GCM 加密对象后持久化确认进度。网络中断后查询接收端确认的块位图，仅重传缺失块；不依赖发送端单方面显示的百分比。浏览器刷新后重新选择源文件，按原清单验证，不能将另一个同名文件续写到原传输。

用户文件名只作为元数据，磁盘对象使用内部随机 ID 与块序号；接收内容不覆盖工作区文件、不自动打开或执行。完成后通过鉴权下载接口流式输出并使用附件和 `nosniff` 响应头。取消/拉黑立即撤销后续写入资格，清理临时块；清理失败需真实报告并保留磁盘配额占用。

## 运行与部署

消息设置默认关闭。打开“主设置 → 消息”，先在账户设置填写账户名称后启用；通信显示名直接复用账户名称，不单独填写设备名；单机本身无须配置模型或调用模型 API。局域网监听默认 `:45840`，发现使用 UDP 组播 `239.255.76.33:45839`。应用不会自动修改防火墙或发布 Docker 端口。Docker Desktop 中的组播与容器地址通常不能直接被局域网电脑发现；可配置出站 HTTPS 中继，或由管理员明确配置容器监听映射和可达地址提示。浏览器工作台继续使用原有鉴权入口；不得把工作台 token 提供给联系人。

自托管目录/密文中继作为独立命令提供：

```sh
go build -mod=vendor -o aide-message-relay ./cmd/aide-message-relay
./aide-message-relay -listen :8443 -cert /path/to/fullchain.pem -key /path/to/privkey.pem
```

三个客户端分别填写相同的可信 HTTPS 源地址（例如 `https://relay.example.org:8443`），支持最多四个中继。证书必须被客户端系统正常信任；没有跳过证书验证的开关。需支持 HTTP/1.1 长连接隧道，普通只支持短请求的反向代理不能直接代替。中继不挂载工作台数据，不保存联系人私钥或聊天正文；目录短期保留签名发现卡，重放缓存、连接数和速率均有限制。跨网语音另外按网络情况配置 STUN/TURN，消息中继不转发 WebRTC 媒体。

首次添加通过另一可信渠道核对完整指纹，再由对方明确同意。文件先选择并计算清单，对方同意后发送；中断后在传输页重试，刷新浏览器后重新选择原文件。文件保存在接收端加密临时对象中，完成后由用户显式保存到当前工作目录；同名文件不覆盖。大文件使用后端流式保存，浏览器下载按钮限 64 MiB，以约束浏览器内存。

当前实现限制：8 人群组和网状语音，群语音由群主发起并逐人接听；单文件 1 GiB，块大小 1 MiB，接收预留配额 4 GiB；最多 128 个传输记录、2048 个设备关系、4096 个邀请。聊天持久保留最多 10000 条且文本总量有界，当前界面提供最近 500 条的查看；不是无限离线邮件系统，未确认送达会提示重试，不把本地保存等同于对方已收。清理失败保留配额并显示重试。

设备密钥与对象密钥均放在原有本机保险库，普通配置导入/导出排除这两类条目；通用凭据删除接口也不允许误删。保险库仍沿用现有本地解锁机制，不承诺抵御连同解锁材料一起被复制的整个数据卷、管理员或已攻陷端点。

语音浏览器页面必须运行在安全上下文（可信 HTTPS，或浏览器认可的本机 localhost）。远程电脑通过普通 HTTP IP 地址打开工作台不能据此获得麦克风能力。Windows 当前沿用仓库既有 Docker 启动架构；主程序仍有既存 Unix 专用进程/磁盘接口，不能把本轮通信包的 Windows 交叉编译当成整个主程序原生 Windows 支持。

## 消息设置与助理权限

消息配置位于主设置的「消息」页，侧栏保留会话、联系人、传输、提醒。通信展示名直接复用账户 UserName，忽略客户端传入的设备名称；账户名为空时无法启用，清空账户名会停止运行中的通信。改名不会更换设备密钥或六位设备码。

「允许助理读取和管理消息模块」默认关闭，配置保存在消息模块中。开启后普通工作台与小秘可使用 manage_messages 工具读取最近消息及联系人/群组/传输状态、发送文字、标记已读、拉黑/解除拉黑、取消邀请。工具不提供接受联系人/群组/语音/文件、开麦、修改权限或启用通信操作。工具执行时重查权限和锁屏，旧模型上下文中的调用也不能绕过撤销。消息正文作为不可信资料返回，不作为执行指令；发送文字应由用户发起。设置页明确提示：读取的消息会交给当前助理模型处理，若当前模型使用外部提供商则属于用户主动授权的模型处理路径。
