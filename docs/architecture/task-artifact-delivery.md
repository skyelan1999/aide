# 任务产物的交付验证

生成文件的任务要有本任务的新建、修改或实际写入证据，才能标记`delivered`。模型说“已完成”或链接一个原有文件，不足以证明交付。原有路径、内存权限、非空文件及类型检查继续参与验证；通用文件按请求扩展名匹配，媒体保留现有签名嗅探。这一层不验证报告内容质量，也不替代完整格式解析。

## 执行前基线

在工具循环和模型请求之前，服务端捕获工作区产物基线并保存到任务。只有明确要求交付文件或选择原生生成模型的任务需要这一步。基线保存失败时不调用模型；任务恢复沿用已保存、工作区身份和修订相符的基线。

目录按广度遍历，每次读取128个条目，最多处理20,000个条目，元数据采用128KiB估算预算，已有产物最多读取64MiB进行流式SHA-256。`Scanned`记录完成枚举的目录，`Directories`记录已存在的目录；它们能证明一个新路径或新输出目录原先不存在。未完成的子树不会被误认为空目录。被拒绝的内存目录、符号链接及`.git`、`node_modules`、`vendor`、`.venv`、`.cache`不作缺失证明。

已有文件大小变化可证明内容变化；相同大小则比较执行前后SHA-256。只改mtime不能通过。未取得哈希且大小相同的旧文件，不能仅凭路径或时间戳判定成功。新建文件、大小发生变化的文件以及有本任务写入记录的文件可以超过64MiB；该预算限制哈希工作量。

基线证据使用目录实际返回的路径拼写；验证时结合文件身份回查别名。符号链接目录、大小写/规范化/短名别名不能因为查不到原始路径键而被视为新产物。无法完整解析的歧义别名保守拒绝，非UTF-8路径不进入JSON基线或交付结果。验证最多处理32个链接，总哈希读取最多64MiB，路径枚举也有20,000条目的总预算。非阻塞打开、常规文件检查、前后文件身份/大小/时间及最终链接身份检查，拒绝被替换的叶节点或特殊文件。

## 服务端写入证据

- 原生媒体的`MediaGeneration.Asset`由服务端在实际写入成功后分配，且有生成身份和请求摘要，属于该任务的生成记录。恢复下载沿用原任务和原记录，不因基线检查重新提交付费生成。
- 已应用的工作区文件提案必须有正确目标绑定，实际字节与本任务`Change.Content`相符；未应用提案保持`pending_approval`。
- 其余文件使用基线判断新建/改写，不把模型或工具返回的成功文本当成写入证据。

读文件和哈希使用固定工作区及任务快照，在全局应用锁外执行；提交结果前再次核对工作区、任务和提案证据。已有文件写入仍按`filesMu`顺序串行。任务完成并成功保存后移除扫描基线，避免已完成历史持续携带目录元数据；保存失败保留基线。未完成任务保留它以便恢复，审批应用验证成功后也可移除。

这些是文件状态比较和服务端写入证据，不是多个外部进程并发修改同一路径时的独占作者证明。缺少覆盖或证据时报告交付未完成，保留生成记录与文件，避免虚报成功。远程工作区沿用现有交付验证边界。
