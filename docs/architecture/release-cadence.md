# 主线每周发布

从正在收尾的 RC7 之后，Aide 主线公开 Release 降为每周一次。公开预发布（RC）也计入，避免通过增加 RC 频率绕开政策。门禁按相邻公开版本至少间隔 7×24 小时执行，使用 GitHub 实际 `published_at`；不以 tag 创建时间或 CI 结束时间计数。

日常修复继续进入主分支并执行 CI、原生双架构候选构建。候选只保存在 Actions artifacts，不自动公开。到周更时，汇总本周变化，使用现有版本脚本升版；每个版本必须具备对应的 `docs/releases/<tag>.md`，且写明新增与改进、修复、升级影响、已知问题。不得只把校验 JSON 作为用户发布说明。可提前维护 [下一次周更草稿](../releases/next.md)。

发布仍由现有 Aide Delivery 的手动准确 tag 触发、受保护的发布环境和完整双架构门禁完成，不设置无人审核的定时发布。门禁在请求公开发布时、创建草稿前、解除草稿前检查频率；公开发布作业串行，防止多个版本同时通过间隔检查。查询失败会拒绝发布。当前没有自动紧急豁免；若用户另行决定紧急发布，先明确处理政策，不能自行绕过。

每次周更包含普通 ARM64/AMD64 包及同版可选开发工具 ARM64/AMD64 包，统一 SHA256 和机器验收元数据。开发工具不进入默认运行包；用户可按需下载。新的频率政策不取消正在进行中的旧 RC7 发布，也不要求重写旧版本或删除历史 Release。
