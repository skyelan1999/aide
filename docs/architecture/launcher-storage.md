# 启动目录持久化

通过 `start.command`、`start.sh`、`start.bat → aide-launcher.exe` 或开发启动脚本启动时，应用数据保存在启动器所在目录的 `.aide-data/`，不再依赖 Docker 命名卷。项目自己的 `.cache`、构建目录和仓库文件仍归项目管理；原生二进制的 `AIDE_DATA` 路径约定不变。

| 宿主路径 | 容器路径及用途 |
| --- | --- |
| `.aide-data/storage/data/` | `/data`：配置、会话、认证令牌、证书、保险库及密钥、索引缓存、插件数据等 |
| `.aide-data/storage/home/` | `/home/aide`：工具用户环境、SSH 用户配置、开发工具缓存等 |
| `.aide-data/storage/migration.json` | 原始来源的文件数及清单摘要；完整迁移凭据，不含文件内容 |
| `.aide-data/launcher.env` | 启动 `.env` 的私有恢复副本，不作为脚本执行 |
| `.aide-data/compose-project`、`image` | Compose 身份及离线镜像标记恢复副本 |

`.aide-data` 不进入 Git、镜像上下文、知识索引及普通工作区文件读取接口，也受 Agent 清理保护。目录包含秘密，应和私人备份同等保护；这些排除措施不代替宿主权限或任意 shell 的授权边界。macOS/Linux 根目录权限为 `0700`，启动配置副本为 `0600`；Windows 新目录设置当前用户的私有 ACL。

## 首次迁移

1. 启动器先确认镜像可用，再查找当前启动目录对应的旧容器及其 `/data`、`/home/aide` 挂载；无容器时检查相应 Compose 项目的旧卷，兼容旧 `.data`。来源含糊、其他运行容器正在使用旧卷、存在活动/暂停任务或会话不可读时，拒绝迁移。
2. 确认空闲后停止旧容器；隔离的无网络辅助容器只读挂载原数据，复制到 `.aide-data/.storage-import-<随机值>/`。逐文件比较内容 SHA-256、权限、目录和软链接目标，并再次确认源未变化。socket、FIFO 和设备文件属于临时执行对象，不复制。
3. 校验通过后一次重命名提交 `storage/` 和凭据，再以宿主目录绑定方式启动应用。已有但缺少有效凭据的 `storage/` 不会被合并或覆盖；缺失子目录也不会静默新建空安装。

迁移不会删除旧卷、旧 `.data` 或失败暂存目录。复制失败时尝试启动原容器及原挂载；若原容器也无法启动，保留停止标记并报告失败。Linux 按启动用户 UID/GID 修复新目录所有权；以 root 启动时应用仍使用 `1000:1000`。首次全新安装保留镜像内默认用户目录。

macOS Docker Desktop 的实际迁移、删除测试旧卷后恢复需以任务收据为准。Windows PowerShell 和 NTFS 权限/软链接未经过本机实测；无法完整保留时校验会失败并保留源，不应将其表述为跨平台迁移已验收。

## 备份与恢复

先停止会话和软件，再备份**整个启动目录及 `.aide-data`**，保留软链接和权限。不要只复制 `settings.json` 或保险库密文：解密材料、令牌和证书需要一起保留。复制到另一设备时还应核对工作区及引用的实际路径。

另一台设备升级时需要本次完整启动包中的启动器、Compose 和 `scripts/launcher-data.*`；只执行 `docker load` 或旧启动器的镜像槽切换不会更新宿主挂载策略。保留原 `.env` 和数据，不要用新空配置覆盖旧安装。

容器、旧命名卷和 Docker 缓存被清理后，保留 `.aide-data`，重新导入离线镜像包并运行启动器即可。丢失 `.env` 或 `.aide-image` 时启动器会恢复上次保存的副本；镜像本体仍需本地镜像或离线包，不能由配置缓存凭空恢复。不要删除 `.aide-data` 来排查 Docker 问题，也不要把备份放在会被格式化的 Docker 虚拟磁盘内。

回滚到旧镜像时先停止当前容器、保留新宿主数据备份，再使用旧版本 Compose 和原项目名挂载保留的 `aide-data`、`aide-home` 卷启动。旧卷是迁移时点的快照，不包含迁移后的新会话；不要把旧数据直接覆盖到新的 `storage/`。只回滚镜像、继续使用新宿主挂载时也需要确认旧版本的数据兼容性。

## 验证

`python3 scripts/test_launcher_data.py` 检查内容/权限/链接、失败保留、并发提交及启动配置恢复。`python3 scripts/test_launcher_data_docker.py` 是显式运行的真实 Docker 演练：使用 UUID 隔离项目和合成配置，检查活动任务保护、迁移失败恢复，以及删除测试旧卷/容器/启动缓存后的重启；只删除自身测试资源，不使用用户凭据，不清理 Docker 引擎。
