# 会话级自动审批与防篡改审计

## 模式边界

原有“手动审批 / 辅助审批”继续由 `ApprovalPolicy` 全局管理。新增的 `Session.ApprovalMode` 只覆盖所属会话，不写全局策略，也不影响其他会话：

- 空值：继承全局策略。
- `assisted_auto`（辅助通过审批）：复用独立辅助审核器。审核明确通过后立即确认或应用；拒绝、超时、证据不足、环境变化、回执保存失败时自动拒绝，不再转人工。
- `full_auto`（全部通过审批）：不调用辅助审核器，自动确认命令、文件提案、浏览器和电脑操作审批。普通模型澄清不属于审批，不会被自动回答。

两种模式只减少审批等待，不扩大执行权限。Shell 确定性拦截、沙箱、应用授权、工作区边界、目标路径、原文件哈希和版本检查仍在原执行路径生效。

## 风险确认与主身份授权

1. 前端显示高风险警示，用户点击“我熟知并已确认风险”。
2. 统一 `requestMasterAuth` 调用 `POST /api/auth/verify`，额外携带 `approvalSessionId` 和 `approvalMode`。
3. 只有账户密码或 WebAuthn 指纹明确校验成功后，服务端才签发随机 256 位一次性授权凭证。无密码安装的其他普通认证行为保持不变，但不能用于高风险审批；未配置密码或指纹时必须先前往“设置 → 账户”配置。服务端只保存凭证哈希，凭证绑定会话、模式和认证方式，两分钟过期。
4. `PUT /api/sessions/{id}/approval-mode` 再校验风险确认原文，并原子消费授权凭证。跨会话、跨模式、过期和重放均失败。前端隐藏按钮或仅显示弹窗不构成授权。

取消高风险模式不需要再次授权。选择全局手动／辅助模式会同时移除当前会话覆盖，使界面选择与有效行为一致。

## 执行回执

- 全部通过使用 `ApprovalReview.Source = session_full_auto`，先写防篡改审计及会话回执，再释放等待中的操作。
- 辅助通过保留独立模型审核回执，并追加会话级自动确认或自动拒绝审计。
- 文件提案仍通过 `applyTaskGuarded`；自动应用失败不会绕过错误，也不会重新伪装成人工已确认。
- 切换模式会增加审批代次并取消旧审核，避免上一模式的异步结果释放新审批。

## 防篡改日志

日志位于 `data/approval-audit.jsonl`，权限为 `0600`。每条记录包含序号、UTC 时间、动作、会话、运行、认证方式、模式、审批类型和指纹，不包含密码、WebAuthn 断言、API Key 或完整敏感输入。

每条记录使用独立随机 256 位密钥计算 HMAC-SHA256，并包含前一条记录的哈希。密钥及最新链头位于 `data/config/approval-audit-key.json`，权限为 `0600`，不通过 API 返回。每次追加和 `GET /api/approval-audit/verify` 都重新验证完整链，链头使应用关闭期间的删除和截断也能在重启时被发现。

这是**防篡改可检测**机制，不声称抵御同时控制整台机器、密钥和日志的攻击者。审计校验或写入失败时，高风险模式不会启用，自动通过不会释放操作；自动拒绝本身保持安全的拒绝方向。

- `scripts/session-approval.test.cjs`：菜单、风险文案、前端会话隔离、主身份授权绑定及不修改全局策略。
