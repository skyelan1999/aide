# 崩溃与异常诊断

工作台和知识星图在设置脚本之前同步加载独立监测模块，能记录初始化阶段的脚本异常。异常提示只显示一次，手动打开详情后可查看错误代码、事件编号、源文件位置和已遮蔽常见凭据的堆栈。正常工作台中也可从“设置 → 系统日志 → 崩溃与异常诊断”打开记录。

| 错误代码 | 含义 |
| --- | --- |
| AIDE-WEB-RUNTIME | 未捕获的页面脚本异常 |
| AIDE-WEB-PROMISE | 未处理的异步异常；主动取消不计入 |
| AIDE-WEB-ASSET | 同源工作台脚本或样式加载失败；普通图片失败不计入 |
| AIDE-WEB-UNCLEAN | 返回原标签时发现上次可能未正常结束，原因未知 |
| AIDE-SERVICE-UNREACHABLE | 连续三次健康检查失败，原因待确认 |
| AIDE-SERVICE-RESTARTED | 已连接服务的实例标识发生变化，重启或切换原因待确认 |
| AIDE-SERVER-PANIC | 服务请求处理时发生 panic |

健康检查每30秒执行一次，单次最多5秒；后台或锁定时不探测。浏览器离线不会被记成服务崩溃。检测到服务实例变化只证明实例更换，不单凭这一点推断崩溃、内存不足或其他根因。

页面不自动刷新、重发任务、撤销操作或停止其他会话。锁屏期间隐藏诊断详情和提示。相近重复错误合并计数，最多保留12条记录；持久存储只有错误代码、编号、时间、文件名、位置和次数，异常正文及堆栈只在当前标签内存中保留。复制由用户主动触发，不自动上传诊断。

页面正常离开时结束标记会清除。只有重新加载或历史返回且保留了未结束标记，才提示可能异常退出；新建标签继承的浏览器存储不作此判断。浏览器或系统直接终止时，页面无法当场显示诊断；重开后的提示取决于浏览器是否保留恢复状态，不是操作系统崩溃原因或退出码的确证。

服务端请求 panic 在响应尚未提交时返回500、固定代码和事件编号。日志记录同一编号、路由模式、异常类型和堆栈，不记录 panic 值或请求参数。已经提交的流式响应保持原内容并中止对应连接，编号写入服务日志，不追加错误 JSON；其他请求保持可用。无关 goroutine 或进程退出由服务可达性和实例变化观察覆盖，不由请求恢复层拦截。

按事件编号查阅本机服务日志时，可在项目目录执行：

```sh
docker compose logs --since 30m aide | rg 'AIDE-SERVER-PANIC|事件编号'
```

普通连接失败、模型返回错误和用户主动停止各自保留原有处理流程。只有明确的服务 panic 响应进入该诊断分类。
