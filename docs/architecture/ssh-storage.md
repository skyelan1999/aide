# SSH 与存储配置

本页描述0.1.17.0 RC1发行线源码；当前发布与完整门禁状态见[发行记录](../reviews/release-0.1.17.0-RC1-2026-10-08.md)。源码测试不代表现有运行实例或用户服务器已经升级、验收。对应证据见[SSH与存储检查](../reviews/2026-10-08-ssh-storage-audit.md)。

## 配置能力

| 内容 | 位置与连接 | 独立服务器配置 |
| --- | --- | --- |
| 工作空间 | `workspace.mode=local|ssh`，SSH 有独立 host、port、username、auth、path | 一个工作空间服务器 A |
| 自动系统文档来源 | `docs.location=local|workspace` 和 path | 远端复用 A；无独立 host/port 字段 |
| 项目缓存 | `cache.location=local|workspace` 和 path | 本机或 A；无独立服务器 C |
| 辅助文档来源 | `/api/sources` 中多个独立 `sftp` 来源 | 可配置 B、C 等；每个来源有自己的连接与凭据 |
| 会话、应用配置与凭据 | Aide 的 `/data` 数据卷；凭据保险库 | 不由 docs/cache 设置迁移 |
| 文档提取缓存 | 进程内缓存 | 不由项目缓存设置迁移 |

使用工作空间 A、参考文档 B、项目缓存 A 或本机的形式已经有驱动。要原生实现工作空间 A、自动系统文档 B、项目缓存 C，仍需独立连接配置、校验、同步和界面支持。给 docs/cache JSON 增加 host 字段不会启用该能力；现有请求解码会忽略未声明的字段。

配置入口为 `GET/PUT /api/workspace-config`。系统文档目录登记为内置 `system-docs` 来源。`docs.location=workspace` 时，它使用 `workspace-sftp` 驱动，复用工作区连接。独立 SFTP 来源通过 `PUT /api/sources` 注册。

独立来源只更新密码或私钥时，保留另一个未提交的凭据字段，并关闭旧 master 后重新认证。若旧凭据已在保险库中而当前无法解锁读取，部分更新返回明确错误，整批在预检阶段停止；空凭据更新不清空原值。显式清除仍按用户要求移除凭据。

目录浏览使用已保存的连接。初次设置时可先留空远端工作区目录并保存，再点击“浏览”；仅在输入框改了主机或凭据还未保存时，浏览仍使用原连接。“测试连接”会先保存当前输入，再进行测试。

## 目录含义

- 工作区 path 留空：SSH 账户登录主目录。
- 远端 docs/cache 相对路径：相对工作区目录。例如工作区 `/srv/project`、缓存 `cache` → `/srv/project/cache`。
- 远端 docs/cache 绝对路径：服务器上的配置目录。例如缓存 `/srv/cache` → `/srv/cache`。这不赋予账户额外权限；仍需远端账户可访问。
- 文件 API 中的 path：相对选中工作区或来源；不能通过绝对文件路径、`..` 逃逸。配置目录可以是绝对路径，不代表每次文件请求也可以。
- 系统文档来源目录：提供文件浏览/读取/保存；不是工作流建档的自动输出目的地。
- 工作流的需求、设计、实施、验证文档：项目缓存下 `system-docs/...`；项目记忆为缓存下 `aide/memory.md`。
- 远端缓存：上述项目产物经 SFTP 同步，本地工作副本位于 `/data/cache/remote-projects/<hash>`。远端是同步读取时的依据；不把整个 `/data` 上传远端。
- SSH 命令的 `AIDE_CACHE/GOCACHE`：只有明确选择远端缓存时指向该远端目录。

本机网络挂载可以在部署层表现为 local 目录，但必须显式纳入 Docker 挂载范围；这不属于产品的多服务器连接能力，也未在本轮验证网络文件系统一致性。

## 连接与恢复

工作区共用一个 OpenSSH ControlMaster，独立 SFTP 来源各有一个 master。建立/关闭按 socket 串行，已有连接上的传输通道可并行。建连总时限 10 秒；master 保活参数为每 15 秒一次、最多两次未响应。更换连接参数或来源凭据会使旧建连失效，并尝试关闭旧连接；关闭等待超时时，后续建连必须先清除旧 master，不能继续复用。

重启后可能留下没有监听进程的Unix控制socket，直接启动新master会因旧路径仍存在而失败。工作区与独立SFTP来源共用 `prepareSSHReconnect`：在持有该socket生命周期门闩且控制检查失败、调用方未取消后，先检查路径确为socket，再用最多1秒的Unix连接探测。只有探测明确返回 `ECONNREFUSED`，且再次检查inode及修改时间未变化、调用方仍未取消时，才清理该socket及对应临时凭据文件，再建立新master。探测能连通、检查／连接超时、取消、非socket路径或身份已变化均保留路径并返回具体错误；不能把一次 `-O check` 失败当作删除活动连接的依据，也不向可能已替换的socket发送退出命令。

发布轮补充真实回归覆盖工作区与独立来源的死socket恢复：原12项加2项，共14项×2=28项race PASS，15.848秒；活动socket与超时保留的4项×2=8项PASS。实际运行及后续新候选重启/完整门禁范围见[发布联调记录](../reviews/2026-10-08-release-integration.md)；这些结果不代表用户服务器的长期稳定性。

提案应用的读写固定到审批时的连接代次，并在网络操作前后复核任务、工作区和提案状态。普通目录浏览及编辑器读写仍允许并行，配置检查与通道建立之间仍存在切换窗口；不应在正在传输文件时切换连接。这不是所有文件操作的完整连接池隔离。

目录批次必须只含 `cd` 和 `ls -l`，且明确报告 Connection closed/reset、Broken pipe 等传输断开，才尝试重连并重新读取一次。目录不存在、权限拒绝、主机密钥变化不通过此方式重试；上传、删除、重命名等写批次不会自动重放。

`POST /api/workspace-config/test` 验证已保存的工作区连接及根目录读取，不验证系统文档目录、缓存写权限或长时间网络稳定性。目录或权限失败仍返回 SFTP 的具体原因，包括 SFTP 进程退出 0 但输出权限错误的情况。明确的 `File "..." not found.` 与 `No such file` 作为不存在处理；`Couldn't stat` 本身不证明文件不存在。正常远程命令使用 `setsid -w` 等待远端会话结束并保留真正退出码，取消后另行清理远端进程组。取消错误附带 `AIDE-CLEANUP` 结果；远端无法连接或无法确认清理时会报告失败/未确认，不能将本机命令退出当作远端进程已结束的证明。

SSH 首次连接采用 OpenSSH `accept-new`；已记录主机密钥发生变化时仍拒绝连接。不要删除 known_hosts 来掩盖密钥变化，应先核对服务器身份。

## 访问目录失败时

1. 核对已保存的主机、端口、用户和路径；留空目录使用该账户主目录。
2. `Permission denied`：区分 SSH 认证阶段与 SFTP 访问阶段，检查凭据及目录权限。
3. `No such file` / `Not a directory`：检查远端路径，特别是本机路径不能直接当作服务器路径。
4. `Connection closed/reset` / `Broken pipe`：目录查询会尝试恢复一次；仍失败时检查网络和服务器 SSH/SFTP 服务。
5. 保险库锁定：先解锁凭据；保存配置成功不代表认证成功。
6. 重启后残留控制socket：本发行线仅对确认无人监听、身份未变化的socket自动清理后重建。若提示控制连接仍运行、检查超时或配置已变化，应重新访问目录并核对具体错误；不要手动删除活动socket或known_hosts来掩盖失败。

本发行线的知识星图、原文／RAG和内置文档检索已接入SSH工作区、自动系统文档及独立SFTP来源，并共用有界读取、来源身份及原文指纹校验。接入范围与其他协议限制见[知识星图架构](knowledge-map.md)。插件仍可能有自己的本机路径约束，不能把来源可浏览等同于所有插件都支持远端。

## 开发验证

执行 `bash scripts/test-ssh-workspace.sh`，默认重复两次。依赖已缓存的 `aide-source-fixtures:test` 与 `aide:local` 镜像；缺镜像时脚本会停止，不隐式下载或构建。可使用现有 `scripts/test-source-protocols.sh` 准备来源测试镜像，准备步骤可能需要联网。

脚本创建两个隔离服务器和一个客户端容器，不发布端口、不挂载用户凭据/数据、不挂载 Docker socket。网络为 internal；客户端源码只读，`/tmp`、`/home/aide` 独立。退出后删除测试容器和网络，保留专用 Go 编译缓存及 `.agent-state/ssh-storage-audit/live` 收据。收据记录镜像 ID、输出摘要、源码前后 SHA；源码变化时不算有效验收。
