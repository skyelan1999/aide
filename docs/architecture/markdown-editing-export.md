# Markdown 编辑布局与 PDF 导出

## 使用

设置 → 文件查看与渲染 → **Markdown 编辑模式**提供“左右对比”和“纯文本”。默认左右对比；桌面左侧编辑原文、右侧实时预览，窄屏上下排列。纯文本只显示原文，仍可点“预览”阅读。选择自动保存到当前浏览器的 `aide-ui` 偏好，同源页面同步；不是服务端账户配置，不跨设备同步。切换不替换草稿。

文件弹窗及独立文件页的 Markdown 工具栏提供 **导出 PDF**。点击后使用当前编辑器内容生成 A4 打印排版，包括未保存修改；在浏览器打印窗口选择“存储为 PDF／保存为 PDF”。这不是一键后台下载，不调用模型或第三方转换服务。建议关闭浏览器打印页眉页脚，以免附加页面地址和日期。PDF 导出本身不保存源文档，也不新增历史版本。

## 内容与边界

- 复用原有 Markdown 渲染、相对图片／draw.io 资源解析与严格 Mermaid 渲染；导出中保留标题、列表、引用、表格、代码及已渲染图像。
- 图片等待载入，15 秒超时或失败会提示错误并取消导出，避免静默漏图。外部图片仍需浏览器能访问原地址；仅支持已有查看器能解析的资源。
- 中文使用浏览器本机字体，正文不是整页截图；分页与 PDF 保存路径由浏览器打印引擎控制。字体、打印设置和浏览器版本可能影响排版。
- 打印快照移除可执行元素及事件属性。锁屏、切换文件或离开页面时，不继续开启过期快照的打印；锁屏清理临时框架。已进入系统打印窗口的副本由操作系统管理，用户可取消。
- 实时预览延迟 250ms 更新，中文输入组合结束后刷新；保留输入内容与预览滚动位置。大型文档仍受现有渲染成本限制。

## 实现与验收

入口：`web/app.js` 的 `setEditorMode`、`setFileViewMode` 与 PDF 按钮绑定；`web/settings-init.js` 保存 `fileMarkdownEditing`；`web/settings-schema.json` 声明分段选项；`web/markdown-export.js` 生成打印快照。没有新增后端接口或配置迁移。

2026-10-09 浏览器组件验收：使用实际弹窗结构、模式切换函数、设置存储、样式及导出模块，观察左右对比、纯文本、刷新后偏好保留、实时预览、未保存正文打印快照、390px 无页面横向溢出及关闭后隐藏。Safari 实际打印保存了 1 页 PDF，中文正文可提取，标题和表格渲染已查看。内置浏览器的原生打印调用停住，故 PDF 保存证据来自 Safari。
