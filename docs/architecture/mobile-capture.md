# Opt-in mobile collection bridge (source change)

A generic, bounded collection service for installed workbenches. It does not implement private inventory rules, invoke plugin tools from a phone, grant file access, or persist raw queues. The private plugin stays outside the public Aide source/image. The latest instruction on 2026-10-21 authorizes Aide code push with simple tests only, and cancels Aide release. Production listeners and certificate trust are unchanged.

## Protocol and enforcement

An enabled manifest opts into `workbench.mobileCapture: true`. The parent advertises `capture` on its existing MessagePort; `client.capture(arguments)` uses `capture.control` through the existing authenticated workbench endpoint. Server-side enforcement requires a live, ready workbench with matching lock generation, workspace revision, management base, package digest and enabled opt-in capability. Calls share the busy/replay/request bounds and normal bridge renewal. Capture state follows the same bridge object across key rotation; old bridge keys do not work.

Desktop actions: `create`, `invite`, `status`, `approve`, `revoke`, `seal`, `stop`. Create takes title, mode (`receipt` or `count`), opaque baseline, pure HTTPS baseURL, scoped catalog `{id,name,unit,codes[]}` and zone names. Host state belongs to the workbench, up to four sessions, each two hours. Server certificate hostname and validity must match baseURL. Client trust still requires proper deployment; checking hostname alone does not install trust on a phone.

The top-level `/mobile-capture.html` page has self-only camera permission; sandboxed plugin frames retain camera/microphone denial and opaque origin. Only pinned local decoder scripts run, under the existing strict CSP. BarcodeDetector is preferred where available; the local ZXing browser wrapper (MIT) and library (Apache-2.0) provide fallback. QR images for pairing are generated by the private plugin, not embedded from private source in Aide. No CDN or image upload endpoint is used.

`POST /mobile-capture/api` is separate from admin `/api/` and independently enforces actual TLS, exact HTTPS Origin/Host, session origin, JSON body <=4096 bytes, strict known fields and a single JSON document. No CORS, cookies, query tokens, X-Forwarded-Proto trust, or arbitrary tool execution. This version targets direct Aide HTTPS, not plaintext upstreams behind a TLS-terminating proxy. Existing admin Bearer enforcement is unchanged.

Join uses a one-use 2-minute random invitation. Invitation secrets are URL fragments and cleared immediately. Phone receives a new random device token, held only in page memory; server stores its hash and compares in constant time. Both the phone and desktop independently confirm the six-digit displayed pairing code; desktop assigns an exclusive zone. Pending devices cannot obtain the catalog or records. An approved phone sees only the session catalog and its zone records; it never receives the baseline, project files, admin token, or other device secrets. Device tokens are scoped to one session, expire after ten idle minutes and fail closed on revoke, stop, lock, workspace change, plugin disable or workbench expiry/closure. Confirmations are application-layer pairing, not client-certificate mTLS.

Limits: 16 devices and zones per session, <=500 item-zone cells, catalog/control payload <=120000 bytes, <=8 exact codes/item, <=500 receipt records, <=2000 distinct submissions, <=600 requests/min/session; no address-keyed unbounded rate map. The owning workbench has the existing eight-instance global bound. Expired and stopped sessions are removed on the next creation; closing a bridge drops all its queues. No scan bytes or credentials are logged or persisted by this service.

## Concurrent collection and reviewed effects

Receipt events have a device-scoped event ID and content digest. Exact retries acknowledge the original event, changed reuse is rejected. Count records are absolute values per item/zone with optimistic versions. Quantities must be explicit, finite, nonnegative and at most six decimals, positive for receipts. An explicit zero is required for zero stock. A device cannot change zones after authorization; revoke/re-pair to change assignment.

Scanning stops on a decoded result and requires a separate quantity/submit action. Camera tracks stop on hidden/pagehide. Images decode locally. Ambiguous network outcomes retain the same pending event for retry; a definitively rejected input can be corrected after refresh. There is no offline durable queue. Pair tokens are lost on refresh, and application restart loses unmerged collections.

Desktop seals a collection to stop new records and reviews a snapshot. Business plugins apply their own atomic inventory baseline/purchase/reservation checks and save proposals; the phone never posts a ledger entry. A sealed flag or event timestamp is not a cryptographic signature or trusted timestamp. TLS encrypts transit; this feature does not claim encrypted `.pp` files or durable raw-queue storage.

## Capture protocol 2/3 (local development)

The bridge response advertises `mobileCaptureVersion: 3`. Version 2 adds `capture.locations` and `capture.unclassified`; version 3 adds `capture.person-binding`. Older opt-in clients retain legacy known-catalog capture behavior. New create arguments include `locations: [{id, zone, name, zoneName}]`, `allowUnknown` (receipt only) and `requirePerson` with organization `people`. Empty catalogs are accepted only for unclassified receipts. Devices can receive a fixed set of areas (`approve.zones`); count grants cannot overlap, receipt/issue grants may. Every record carries an authorized area and, if configured, its matching location. Count versions are scoped by item/area/location. `issue` is collection only; downstream tools retain stock validation and reviewed file writes.

## 当前组织人员绑定协议

`capture.person-binding`：私有工作台创建采集单时提供最多200条组织员工快照及 `requirePerson:true`。电脑审核设备必须选择该名册中的 `personId` 和区域；手机确认后允许采集，服务端自动写入 actor。手机不能提交人员字段，更换绑定须撤销设备重新邀请。手机快照只返回本设备绑定，不暴露完整员工目录。没有独立员工密码、保险库员工账号或登录会话。协议继续使用 HTTPS、过期邀请、双方确认、位置范围检查、封存和撤销。

## 插件独立服务的自动局域网入口

通用工作台桥新增 `capture.network(start/status/stop)`。仅声明 mobileCapture 的启用插件工作台可调用；实例、锁屏、工作区及包内容仍须有效。原生消息局域网 helper 接收45秒租约，动态打开物理网络监听，目的地固定为启动器解析出的回环 Docker 45841 映射，不接受调用者目标。结束、关闭工作台或租约到期关闭监听及已有连接。管理8080端口仍只绑定回环。私有插件服务、私钥和照片不进入公共镜像。首次手机证书信任仍由设备持有人操作。

`file.target` 检查声明扩展名的工作区文件版本；iframe 的 `file.save` 经宿主父页面校验后直接调用 `file.save.commit`，手动保存及自动保存均不再增加确认弹窗。iframe 无权直接提交该方法。复用原生本地/SSH文件写入、工作区身份、版本冲突和历史处理；不会全局关闭审批，普通 tool.call 的写入仍形成待审批提案。
