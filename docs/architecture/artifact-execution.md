# 制品任务执行与独立验收

用户通过自然语言提出资料整理、CAD 建模或其他制品任务后，由 Aide 自行盘点来源、实现、实际执行、处理错误和自测。外部开发者负责补齐通用能力及独立验收。不能把外部开发者代为生成工程代码或运行关键步骤，记成 Aide 自主完成。

## 按文件名查找

`list_files` 的可选 `glob` 按不区分大小写的文件基本名匹配 `*`、`?`、`[]`，不能写目录分隔符或正则表达式。`path` 指定相对目录，`recursive=true` 包含子目录；不传 `glob` 时保留原有目录列表格式及行为。此查询只支持当前绑定的本地工作区与当前可见的本地、Skill 引用源；SSH 和其他引用源仍可使用普通目录列表，不回退至本地目录。

查询只读取目录项及文件属性，返回普通文件路径，不读取内容、不建立写入基线、不跟随符号链接，并沿用现有路径排除及来源可见性。`maxResults` 默认 100，范围 1–200；同时限制两万目录项、32 层递归、匹配路径 JSON 约 12 KiB 和可取消的三秒协作时间预算。文件系统调用本身不具备硬超时保证。

返回 `complete`、`reasons` 和访问、排除统计。预算耗尽、目录读取异常或文件名无法完整表达时明确返回不完整；`complete=false` 不能证明文件不存在。路径清单不证明文件内容、版本、新产物交付或工程验收，后续使用仍须读取并核对真实版本。

## 慢启动期间重新打开

普通 `start` 或桌面重新连接仅在服务健康时复用并打开页面。若同一安装目录下的 Aide 容器仍在运行、但 HTTP 尚未就绪，启动器明确提示稍后重试并退出；保留该实例的镜像、资源设置及数据，不因历史会话加载耗时而重新创建旧镜像。检查同时绑定容器的工作目录和服务名，不能将其他安装的容器当成本实例。显式构建完成后的启动及 A/B 镜像激活仍遵守各自流程，不受普通重开保护替代。

## 待应用提案读取

`write_file` 返回的是候选文件，`read_file` 返回的是磁盘文件。候选尚未应用时，磁盘文件不存在或仍为旧版均属正常，不能据此要求用户重新上传候选。

`read_proposal` 只读取当前会话、当前工作区及版本绑定的候选记录，不落盘、不应用，也不建立磁盘版本读取凭据。所有正常工具禁用和工作流绑定检查仍生效；引用来源必须当前可见。

- 不传 `path`：列出候选元数据，默认每页 20 项，最多 50 项，使用 `offset` 翻页。
- 传 `runId`、`path`：读取本会话指定轮次的文件候选。不传 `runId` 时读取当前轮次。
- 文本按 UTF-8 字节分段，默认 12 KiB，最多 24 KiB；返回 `nextOffset` 和完整候选的 `sha256`。下一段可携带该哈希，候选变化时拒绝混读。
- `applied` 是历史记录的状态，不是当前磁盘内容或模型验收结论。应用前仍需正常审批和磁盘基线版本检查。

### 精确修改待审批提案

`write_file` 支持完整 `content` 或 `proposalPatch` 两种互斥输入。局部修改前用 `read_proposal` 查看准确候选，再传入 `proposalPatch.sha256` 和按顺序处理的 `replacements`（每项含 `oldText`、`newText`）；`runId` 可选，省略表示当前轮。旧文字必须恰好匹配一次，任何匹配失败或指纹变化均整批拒绝，不留下部分修改。

本地工作区的未保存候选可在同一会话与工作区版本中续改；选历史轮次时会在当前执行轮建立新候选，历史候选保持原样。沿用最初磁盘读取的 `BaseHash/Before`，不制造新的读取凭据；应用仍检查原磁盘版本，用户已改动的文件拒绝覆盖。已保存、历史归档待恢复、外部引用、SSH 或临时执行环境的候选不使用此功能，继续各自原有流程。文件绑定、工具禁用、锁屏保护和正常审批仍生效。

候选最多1 MiB，每次1–16段替换，替换文字合计最多64 KiB；要求有效UTF-8，不支持正则或模糊匹配。回执提供前后SHA、字节数、替换数和 `applied=false`，不写工作区文件，也不证明源码可运行或制品有效。完整内容方式保持兼容，清空文件必须显式提供空字符串，缺失 `content/proposalPatch` 会拒绝。

### 收尾审阅与应用交接

有待应用文件时仍保留首次收尾审阅；修订候选或新增实际操作后，继续在配置预算内复核。仅重复 `read_proposal` 或更新计划，不构成能解除应用门禁的新执行。依赖文件应用的未完成计划不会单独触发重复收尾，模型应准确结束当前提案输出，随后由既有流程进入文件审批。

这个交接不应用文件、不批准命令，也不把用户总目标记为完成。工作区、内容版本、历史归档及锁屏检查保持原样；全部候选应用后，未完成计划继续按原规则处理。持久化的执行计数沿用原编号，包括旧的候选读取记录，不因升级重置或改写历史。

## 部分保存与历史恢复

本地工作区文件提案的正文写入成功后，历史归档仍可能失败。只有写入器确认成功、并且实际内容哈希与当前提案一致时，才记录该文件 `applied=true`、`historyPending=true`；整个任务继续等待正常审批，不报告全部应用完成。交付视图以 `saved_history_pending` 标明此状态，`read_proposal` 同时返回历史是否待恢复。

正常重试先核对工作区、写入权限和每份已保存文件的当前哈希，保持原始编辑基线。内容被用户更改时拒绝继续；未记录成功写入的新文件，即使碰巧存在相同内容，也不能据此收编为已应用。历史待恢复的文件只重新检查内容并补归档，保留正文的字节、inode 和修改时间；归档成功后才继续其余文件。保存状态随任务序列化保留，原有审批与版本检查不变。此恢复仅覆盖本地工作区提案，不扩大 SSH 或文档绑定的写入能力。

## 工作区图片查看

`view_image` 将当前本地工作区中的 PNG/JPEG 作为视觉证据交给模型，支持原图像素坐标的 `crop`（`x/y/width/height`）和 `maxDimension`（默认 1600，范围 128–2048）。返回原文件与实际展示图的 SHA-256、原始尺寸和裁剪范围。图片内容仍是不可信资料；只覆盖本次展示范围，不代替 OCR、精确测量或独立验收。

该工具只读取当前绑定且未切换版本的本地工作区，拒绝符号链接、非普通文件、越界路径和错误的预期哈希；现有工具禁用、工作流绑定和恢复检查继续生效。引用来源、SSH 及没有视觉通道的执行节点不能使用此工具，不静默改读其他目录。读取不会建立文件写入基线，也不会修改原图。

原文件最多 16 MiB、8000 万像素，单边最多 32768；解码按像素格式估算的内存不超过 320 MiB。解码串行且等待可取消。返回图片不超过 2 MiB、400 万像素；每轮沿用现有最多四图及 4 MiB 的视觉通道预算。模型的普通文字记录只保存来源元数据，图片使用已有的临时视觉通道，恢复历史时不能声称旧图片仍在当前请求中。

受限命令的 `$AIDE_CACHE` 可能随单条命令清理。临时脚本在同一条命令中创建并执行；跨命令工程文件通过正常提案、审批保存至用户指定项目。实际生成的制品通过工作区相对 Markdown 链接交付，供现有交付核验读取真实文件；候选文件仍必须标明待审批。

## 明确输出路径的交付证据

大型工作区的初始扫描有边界，未遍历目录中的文件不能直接认定为本轮新产物。模型应在实际导出前调用 `prepare_artifacts`，用 `paths` 列出准确的工作区相对输出路径。后端记录该路径的存在状态及旧内容哈希，并先持久保存，随后才返回回执；文件缺失或内容改变的证据供正常交付检查使用。恢复任务保留这些记录。

每次接受 1–16 条路径，每个任务最多 128 条，既有文件读取总预算为 64 MiB。只支持现有制品格式和当前绑定的本地工作区；符号链接、非普通文件、越界或排除路径、旧版本工作区均被拒绝。重复调用保留首次观察，旧文件未改或仅改时间不能成为新交付，原始扫描已知的旧文件规则仍优先。无法取得旧内容哈希时应使用新的输出路径。

该工具不创建文件，不批准命令，不建立源码编辑凭据，也不验收几何或图纸准确性。导出后仍须实际回读、自测并提供工作区相对 Markdown 链接；独立验收另行进行。不可在文件生成后补记并把既有产物冒充新交付。

## 流式工具参数完整性

Responses 的函数参数可以出现在增量事件，也可以完整出现在 added、done 或 completed 事件。适配器收齐后按调用标识对照最终记录，再向执行器传递一次完整 JSON 对象，避免将完整参数丢成空值或重复拼接。多个调用保留最终顺序和各自参数；保留给下一轮模型的工具历史必须与实际执行一致。未完成、身份冲突、参数冲突或不完整 JSON 不进入工具执行，错误不包含参数正文。接收参数期间继续报告活动，文本、用量及模型推理上下文沿用原有传递路径。

该修复只处理参数传输，不推断缺失路径，不批准操作，也不改变工具禁用、工作区版本、文件审批或命令资源限制。

## 本地命令资源监控

Linux 工作台的 `run_shell` 在原有审批、工作区沙箱、超时和取消机制内，默认监控本次命令进程组及当前子进程的 RSS。默认预算 768 MiB，`memoryMiB` 接受 128–1536 的整数。数值库默认单线程，减少普通建模脚本的线程及内存放大。

监控每 25 ms 采样一次。超出预算时终止命令组和已观察到的子进程，向模型返回失败及分批处理建议。对子进程单独发送信号前核对进程出生时间，避免把复用的 PID 当成旧子进程。

这是采样式 RSS 监控，**不是 cgroup 硬分配上限或安全隔离边界**。共享页可能重复计入，短时分配也可能在采样间隔内出现。既有文件访问沙箱保持不变；远程 SSH 及非 Linux 原生执行沿用原有边界，不声称具备这一 RSS 监控。插件自行启动的进程也不由此工具接管。

重型任务超限后，Aide 应检查已产生文件的状态，按零件或工序缩小批次、释放中间对象并复用有效制品，再执行和核验。失败、提案生成、命令完成、格式回读通过、预览正常和原图准确性分别记录。

## 验收分工

Aide 提供来源指纹、执行结果、自测及未闭合项。独立验收者对照原始资料重新检查实际制品；CAD 场景还应核验单位、实体完整性、源尺寸、装配位置、干涉和原生查看操作。Aide 的自测和本页中的软件测试均不能代替工程验收。

## Python 静态预检 CLI

源码工具 `scripts/python_static_check.py` 可安装到经授权项目的工具目录，通过 Aide 原有命令流程调用；它不是新增的内建模型工具，也不需要更换工作台镜像。使用 `python3 -I -S <工具路径> --file <源码路径>`，或用 `--stdin` 传入程序正文。输入按数据解析，既不导入也不执行被检查代码。CLI 在导入可被目录覆盖的模块前要求隔离解释器及禁用 site；检查器只使用标准库。

工具检查语法和符号表中疑似未定义的全局名称，最多接收 64 KiB UTF-8、返回 50 条名称诊断，并提供实际输入字节的 SHA-256。超限输入不会声明完整源码哈希或检查通过。退出码 0 仅表示 `pass_static_only`，1 为语法错误，2 为建议核实的名称/通配导入警告，4 为未运行。动态全局、执行顺序、类型、API 契约、变量覆盖及工程几何不在此检查范围内。

检查回执不提供文件编辑基线，不授权执行，不代替普通提案应用、命令审批、实际运行或制品验收。模型应核实警告并修正自己的源码；有依据的动态名称不能仅凭此工具认定错误。通用回归使用 `python3 -I -S scripts/test_python_static_check.py`，覆盖非执行、导入隔离、大小限制、语法和作用域。

静态预检会将推导式转换为仅用于符号分析的生成器表达式，避免 Python 3.12 内联推导式符号表造成漏报；原始代码不会执行或修改。推导式出现时 scopeLine 为空，occurrenceLines 仍对应原始源码。15 项回归已在宿主及 Aide 的 Python 3.12.16 隔离运行环境通过。该结果只验证静态预检工具。

## 项目 CAD Python 入口

`scripts/cad_sdk_python.py` 安装为项目工具目录的 `cad_python.py`，与 `step-engine/`、`readers/` 及其他 SDK 工具同目录。入口将 SDK 自身、项目 `03_三维建模`、固定引擎和 readers 依次加入 Python 模块路径，并保留原有路径与动态库环境。这样从其他目录运行工程脚本时，同目录的 SDK 工具也可被导入。

入口检查固定 OCP 目录是否存在，直接转交当前 Python 的参数与环境，不使用 shell、不安装依赖、不构造几何；仅导入入口不会执行 main。普通提案应用、命令审批、资源限制和实际制品验收继续生效。`python3 -I -S scripts/test_cad_sdk_python.py` 的七项合成回归覆盖同目录工具、项目/外部路径、SDK 优先级、参数转交、缺引擎拒绝、用法与环境不变；宿主及工作台 Python 3.12 均通过。安装与二进制构建分别记录，真实模型导出仍须单独验证。


## CAD 有效性检查的初始化

Open CASCADE 的默认检查与 Exact 检查应分别在检查器初始化前选定模式。`BRepCheck_Analyzer(shape, True, False, True)` 可直接使用 Exact；若在已有检查器上调用 `SetExactMethod(True)`，须对形状重新 `Init` 后检查。仅切换标志不构成重新计算，可能将缓存的默认结果误报为 Exact 通过。实际 SDK 对照已复现两种用法结果不同，构造时启用 Exact 与设置后重新初始化的结果一致。其行为可对照[官方检查器源码](https://github.com/Open-Cascade-SAS/OCCT/blob/master/src/ModelingAlgorithms/TKTopAlgo/BRepCheck/BRepCheck_Analyzer.hxx)。

逐级诊断须列出默认或 Exact 任一种失败的子形状，并分别记录模式。边单独有效不证明其在面的参数曲线上有效；离散残差采样仅是诊断证据。检查工具修正后，受影响的旧验收结论应撤回并保留纠正记录，实际制品重新核验，不能覆盖旧失败报告或据此放宽原有几何约束。


## STEP 曲线与曲面偏差诊断

`scripts/cad_step_curve_check.py` 可安装到项目工具目录，用现有 `cad_python.py` 入口调用。它只读取一份指纹锁定的毫米 STEP，通过当前 OCP SDK 的 `GeomLib_CheckCurveOnSurface` 计算每个面与边出现的数值最大偏差，并用 33 点采样核对结果是否低于已观测误差；保留缝边的实际方向。内核状态错误、非有限值、缺失曲线和不相同参数化均明确记为未完成，不当成零误差。

命令为 `python3 工具环境/cad_python.py 工具环境/cad_step_curve_check.py --file <STEP> --sha256 <完整SHA256> --output <新JSON路径>`。输入最多 128 MiB，每次默认 2048 个配对出现，上限 8192；超限明确返回不完整。该工具不设置读入参数，不修补、写出模型或修改容差；原有命令审批、超时及 RSS 预算仍须使用。单次原生算法不提供独立硬超时。

退出码 0 仅表示测量流程完整，3 表示不完整，4 表示未运行；完整测量仍可能包含超出实体声明容差的配对。所有报告均为 `modelAccepted=false`。内核数值最大值不是严格数学误差上界，也不替代源图尺寸、材料、实体有效性、装配位姿或干涉验收。完整逐项数据仅写入新的独占报告文件，标准输出提供摘要和最差十项，既有报告不覆盖。

七项保护及错误路径回归在宿主和工作台 Python 3.12 通过；真实扁钢对照 72 个配对无超差，已知失效筒体 246 个配对中 70 个超出声明容差，单配对预算正确返回不完整。它们只验证诊断工具。[官方数值检查接口](https://occt3d.com/dev/doc/refman/html/class_geom_lib___check_curve_on_surface.html)说明了计算和错误状态。

## DXF 标注证据读取

[cad_dxf_dimensions.py](../../scripts/cad_dxf_dimensions.py) 可安装到项目工具目录，通过 `cad_python.py` 使用现有 ezdxf。命令为 `python3 工具环境/cad_python.py 工具环境/cad_dxf_dimensions.py --file <DXF> --sha256 <完整SHA256> --output <新JSON路径>`；`--handles` 可按十六进制句柄筛选，`--max-dimensions` 默认1024、最多4096。

每条记录分开保存 DIMENSION 原文字、直接匿名绘制块的 TEXT/MTEXT 显示文字、计算测量、原始见证点及其差向量/距离。打印覆盖值与原始测量可能冲突，单位码0不推定为毫米；工具不决定设计值，也不把二维点映射为三维位置。只读顶层标注，不递归块内标注、代理或外部参照；资料中的文字不是执行指令。

输入上限64 MiB、绘制块512实体、单文字4096 UTF-8字节，报告上限8 MiB。缺句柄、绘制块、非有限值、API错误和预算耗尽明确返回不完整，错误不转为0。报告独占写入新文件，开始/结束核对源指纹；既有报告拒绝覆盖。退出0只表示所选证据完整，3为不完整、4为未运行，所有报告均 `modelAccepted=false`。仍使用正常命令审批、超时与RSS门禁，不构造几何、不修改图纸或单位。

八项保护/错误路径回归在宿主与工作台 Python3.12 通过。实际 SDK 合成对照保留显示7与测量9的差别、预算1返回不完整；实际图纸只读对照保留了显示35/测量36、显示720/计算0并附横向见证差720。这些结果只验证证据工具，真实 Aide 调用与工程验收分别记录。
