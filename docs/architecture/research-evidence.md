# 来源驱动的调查与工程交付流程

## 目标

Aide 按当前任务调查来源、保存参数依据，再决定是否具备近似建模条件。不同模型可给出相似的受约束结论；流程不保证逐字或数值一致，也不内置某个厂商的参数作为调查结果。

## 执行链

1. `web_research.go` 在工程重建请求中注入调查流程：定义参数，读取已有来源记录作为线索，优先产品、配件商品、维修规格表与真实下载链接。
2. `workflow.go:webSearch` 对未配置搜索返回 `unconfigured` 与 `searched:false`，保留离线部署意图。模型不能将其解释为无结果或无外网。
3. `headless-browser-bridge.js` 返回正文长度、正文/链接截断标记。`plugins.go:normalizePluginResult` 将来源回执与 PDF 元数据保留给模型及任务工具记录。短正文只标为短页/框架，不能证明缺少商品。
4. `research_status` 基于整个任务的真实工具记录生成来源、PDF 完整页的并集、缺页和真实返回的候选链接；最后一页完整性未明确时保守排除。候选链接并不自动获得访问授权。
5. `record_research_finding` 保存来源/计算/假设三类输入。来源和计算值必须关联工具记录编号，引用须匹配该记录的真实结果；假设须说明局限。引用匹配只证明可追溯，不证明来源权威或物理正确。
6. 收尾检查带入全任务账本，避免最近 16 条短摘要丢掉早期参数。对超过实际 PDF 覆盖的完成声明最多纠正两轮，仍失败则返回实际范围。否定、撤回和历史错误陈述不当成新的完成声明。
7. 工程任务尚未调用浏览器却索取公开资料时，最多两次要求先调查。确认型问题、禁用浏览器、已有实际读取、离线任务不受该前置处理影响。实际工具/权限失败仍允许必要澄清。
8. 公开尺寸足以近似建模时，明确假设并继续几何、计算、图表交付；精确翼型/接口未知时保留缺口。BEMT 不称 CFD，轴功率不等同电池功率，文件提案不称已落盘。

## 边界

- 不新增视觉输入管线。只有实际支持并接收像素的模型才能作视觉叶片计数。
- 不自动配置联网搜索，不绕过浏览器范围或审批，不自动消耗付费模型额度。
- 来源账本不判断所有科学结论；完成声明检查是有界启发式，不是自然语言证明器。
- 未执行真实模型同题对比；源码构建不等于运行中 Aide 已应用。

## 人工等待与超时续跑修复

截图中的旧任务确实是超时失败，服务重启成功不能作为流程验收。发现聊天任务的 6 分钟墙钟时限包含 `ask_user` 人工等待。现在 `task_run_budget.go` 提供可暂停的执行预算：开始、重试、恢复及子任务统一使用；进入 `awaitUserAnswer` 暂停预算，离开后仅恢复剩余预算。用户停止仍立即取消；模型、插件和 shell 单次时限仍保留。界面人工等待时隐藏执行计时，并跳过无事件卡住看门狗。

实际执行预算耗尽时，有检查点则保存为 `paused` / `canResume`，供显式继续；没有检查点仍失败并允许重试。不自动继续或触发付费调用，不修改历史失败任务来伪装成功。此轮仅构建和语法检查，未运行测试、超过 6 分钟的等待验收或真实模型同题对比。
