# 执行中的并行机会评估

普通会话的1–5x、10x表示单轮独立分析请求的并发上限。主执行器负责工具、插件、审批与文件写入，分析请求只返回待核实笔记，由主执行器结合真实证据继续执行并汇总。

起始规划不是永久结论。主循环在完整工具结果入链、用户插话或排队内容提升为插话后，按新证据重新评估剩余任务；没有新证据时跳过检查。先顺序读取资料，之后才出现独立分析机会属于正常流程，不记为任务规划失败。自动收尾检查、自己的分析笔记、研究参数记账及相同参数/结果的工具重放不构成新证据。实际执行计划变化仍可触发评估。

每次评估携带当前执行链、工具结果、用户调整及已完成分析标题。规划只能拆分互不依赖的剩余分析，不能为了填满倍率而凑重复任务。完全相同的已完成标题由服务端再次排除；语义相近但改写的重复仍依赖规划模型及主执行器核对。各轮笔记和分析状态累计保留，主请求只新增当前一轮笔记，不重新插入历史笔记。

规划和子分析使用独立的组件级system指令，明确不承担主执行器的工具/记账职责；汇总说明这些模型分析已由调度层派发，禁止再通过子代理或插件任务图重复派发同一分析。规划请求使用90秒上限、2048输出额度，并单独关闭隐藏推理以优先产出调度JSON；不修改会话设置，子分析和主执行器沿用用户选择的推理强度。规划格式异常、空结果、超时、上下文不足或没有足够独立任务时，主执行器继续；新证据到达后可以再评估。评估只发生在既有主工具循环边界，沿用该任务的轮数、活动时间及取消预算；不另设固定评估次数后的永久关闭条件。没有新信息不调用规划器，倍率不保证等比例提速。

证据指纹和每轮计数持久化，完成的同一检查点在恢复时不重放。旧版已准备检查点先采用当前指纹，再等待新证据；中断中的只读分析可在恢复时重试。取消信号传递至规划和所有当前子分析请求，不启动下一轮。工具调用仍由既有主执行器按顺序配对结果，既有审批及插件依赖调度不变。

组件请求有独立system指令，原执行器的system/assistant/tool消息序列被编码为只读参考资料，不能作为组件继续调用工具的协议。图片仍以原生图片内容携带，图片数据URL与本地消息归属编号不会序列化进参考文本。支持或尚未声明不支持结构化输出的模型，调度请求使用JSON对象模式；明确不支持时仍沿用文本JSON提示。解析继续校验任务数量、非空、重复标题和长度，格式异常不执行子任务。

进度卡显示已评估轮数、各轮任务与累计完成数。上下文详情保留各轮规划请求以及所有子分析的独立窗口；最新主汇总请求仍单独展示。累计 Token 消耗包含所有规划、子分析、主请求和标题辅助，不能当作一个共享上下文窗口。
