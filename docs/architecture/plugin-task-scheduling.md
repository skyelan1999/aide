# 插件任务依赖与资源调度

状态：显式资源依赖图尚未接入执行器；统一插件入口已接入资源预约，见下方当前实现。当前已实现的范围见[复测任务](../tasks/parallel-document-plugin-scheduling-20261014.json)，不能据此宣称插件分支已随 5x 自动执行。

## 用户场景与当前行为

用户选择 5x 后要求编写 ROS2 文档，应先显示独立章节规划，允许并行准备资料和草稿，最后核验、汇总、写入一个成品。存在插件调用时，无依赖的操作可以同时进行；依赖前一步结果的操作等待前置成功，同一输出文件的修改保持明确顺序。

当前 `conversation_parallel.go` 只并行分析和起草，主任务的 `workflow.go` 工具循环按模型返回顺序执行。`plugin_call_queue.go` 对同一工作区/插件提供 FIFO 排队，不同插件的跨会话调用可以重叠。现已通过宿主发布的资源声明协调跨插件文件读写；无声明调用保守独占整个插件执行域。声明不构成系统权限限制，也不能自动发现插件隐瞒的效果。

## 执行前的任务图

任务节点需要稳定 ID、工具和参数、显式依赖列表、读写资源声明与可见状态。模型可以建议这些信息，服务端必须校验：重复 ID、未知依赖、自依赖、环、超过节点/工具预算、已禁用工具或工作区变化均不得派发。缺少依赖的操作不能猜测上一操作已经产生结果；参数引用仅能读取已成功的前置结果。

资源身份包含工作区代际、来源身份与受控根下的规范路径。SSH 身份必须包含实际连接和 AgentRoot，不能只按文件名或主机名加锁。单次调用同时申请全部资源，避免按不同顺序逐个持锁而死锁。读读可以重叠；读写、写写互斥，冲突操作按入队顺序等待。缺少可靠资源声明的插件按工作区独占处理，不能从函数名猜测其只读。

插件的只读或资源声明属于调度契约，不能提升既有权限，也不构成操作系统沙箱。所有当前审批、禁用策略、路径检查和工具入口校验必须保留。声明只读的节点返回写入提案时不得静默落盘，应报告契约不一致并交由主任务重新决策。

## 并发与顺序

同一任务的运行上限沿用用户选择的 1x–5x；没有显式依赖且资源不冲突的节点才可同时运行。整份文档写入是依赖全部必要章节成功的后置节点，不能让多个工作者各自覆盖最终文件。某节点失败时，依赖它的节点标记未执行，并显示原因；独立节点可以继续，汇总必须公开缺口。

浏览器和电脑控制等需要人工确认的操作，先按顺序完成可见审批，再派发被批准的具体调用。现有 `awaitUserAnswer` 只有单个任务问题槽，不能由多个并行节点同时写入。工具结果归并、提案入库与共享 `versions` 也不能直接在多个 goroutine 中修改。

## 日志、取消与恢复

每个节点派发前保存自己的工具意图，结果返回后保存节点结果和摘要，最后由主任务按稳定顺序归并模型上下文。已有 `ToolExecutionIntent` 和 JSONL 日志需要按节点保留，不能只留下最后一个在途工具。状态至少区分：等待依赖、等待资源、等待审批、运行、成功、失败、未执行、结果待核实。

暂停时不再派发等待节点，传播可取消执行的上下文。已经派发但没有可靠完成回执的写操作保留“结果待核实”，恢复后不能自动重放。当前 daemon RPC 没有通用撤回协议；超时入口已补齐“停止对应进程实例后返回待核实”，防止处理器继续与下一调用重叠。这个停止动作不撤回外部副作用，也不代替依赖图的恢复核实。不能因调用方停止等待就释放资源并启动下一个可能冲突的写操作。需先确认处理器结束或显式停止对应执行实例。

## 接入门禁

- 真实处理器屏障证明独立调用重叠，并发上限覆盖 1x 和 5x；不是只检查 goroutine 数。
- 同一文件的读写/写写顺序、多个资源的公平等待、不同工作区/SSH 根的隔离。
- 环与未知依赖在任何工具执行前拒绝；前置失败使依赖节点明确未执行。
- 人工审批不会被另一个节点覆盖；每项批准对应具体工具和参数。
- 暂停、超时、进程重启和未确认写入不触发重复副作用。
- 每个节点有执行意图与结果证据；提案、`versions` 和模型工具消息按稳定顺序归并，Go race 通过。
- ROS2 文档场景实际展示规划、等待、并发、单份输出及缺口；模拟模型和真实模型证据分别记录。

以上门禁通过后才能把执行器标记为完整资源依赖调度。当前 FIFO 队列和五路草稿测试是前置基础，不替代这些门禁。

## 当前实现：资源预约与中断收尾

`plugin_resources.go` 已接入 `callPluginToolContext`，读取宿主surface中的 `scheduling.resources`，不采信模型参数。多资源同时预约，读读可以重叠，冲突操作按资源队列顺序等待；同插件原FIFO保留。目录按祖先关系冲突，符号链接和硬链接别名回退独占。缺少或无效契约、跨插件服务消费者、SSH和电脑/浏览器控制插件回退整个插件执行域独占。有契约且无服务依赖的短命调用只加载目标模块；读取其他插件模块以装配服务的调用保持独占。只读或越界提案在进入审批队列前拒绝；有效提案仍须原有审批与应用检查。

短命宿主与daemon使用独立进程组；中断时终止同组子进程，之后释放预约。daemon新增上下文取消，登记和派发在生命周期锁内绑定一个进程代际，不能将旧调用误发给替代实例。主动脱离进程组及外部副作用仍不保证撤回。协议细节见[插件资源契约](../plugin-protocol.md#31-工具读写资源调度2026-10-14兼容-v12)。

这一步解决的是统一入口中跨插件已派发调用的资源协调。自动5x工具派发、显式依赖校验、并行审批预检、按节点持久日志、结果稳定归并和断点恢复仍待接入；不得以队列测试替代完整ROS2工具计划验收。测试、候选部署及镜像状态见[资源调度任务](../tasks/plugin-resource-scheduling-20261014.json)。

### 2026-10-15：资源预约先于同插件 FIFO

完整资源范围现在先进入共享预约队列，再取得同插件 FIFO。此前相反的顺序会隐藏同插件内排队的写操作，导致另一个插件后来的读取插队。每个有效资源范围已包含插件状态目录的独占预约，未声明调用则独占整个执行域，因此取得资源后再进入 FIFO 不会产生反向持锁等待；工作区、契约、启停及禁用策略仍在两道门之后复核。等待阶段不启动处理器。

真实 Node 回归先运行插件 A 的读取，再排 A 的写入及插件 B 的读取；B 必须等写入完成并读到新内容。插件 C 声明独立资源，其处理器同时能进入执行。修复前该场景实际出现 B 插队，不能用原有单独 FIFO 和资源队列单测通过代替组合入口验收。此修复仍不是完整任务 DAG，详见[排队顺序任务](../tasks/plugin-resource-order-20261015.json)。
