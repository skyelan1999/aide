# 插件任务依赖与资源调度

状态：统一插件入口已接入资源预约；显式插件任务图正在候选分支接入，见本文末尾。候选的部署和验收状态以[任务图账本](../tasks/plugin-dependency-plan-20261015.json)为准，不能把源码或模拟模型测试等同于用户真实模型已采用 5x 工具计划。

## 用户场景与当前行为

用户选择 5x 后要求编写 ROS2 文档，应先显示独立章节规划，允许并行准备资料和草稿，最后核验、汇总、写入一个成品。存在插件调用时，无依赖的操作可以同时进行；依赖前一步结果的操作等待前置成功，同一输出文件的修改保持明确顺序。

`conversation_parallel.go` 并行分析和起草；`workflow.go` 的普通工具调用仍按模型返回顺序处理，显式插件任务图在主任务内单独调度节点。`plugin_call_queue.go` 对同一工作区/插件提供 FIFO 排队，不同插件的跨会话调用可以重叠。宿主发布的资源声明协调跨插件文件读写；无声明调用保守独占整个插件执行域。声明不构成系统权限限制，也不能自动发现插件隐瞒的效果。

## 执行前的任务图

任务节点需要稳定 ID、工具和参数、显式依赖列表、读写资源声明与可见状态。模型可以建议这些信息，服务端必须校验：重复 ID、未知依赖、自依赖、环、超过节点/工具预算、已禁用工具或工作区变化均不得派发。缺少依赖的操作不能猜测上一操作已经产生结果；参数引用仅能读取已成功的前置结果。

资源身份包含工作区代际、来源身份与受控根下的规范路径。SSH 身份必须包含实际连接和 AgentRoot，不能只按文件名或主机名加锁。单次调用同时申请全部资源，避免按不同顺序逐个持锁而死锁。读读可以重叠；读写、写写互斥，冲突操作按入队顺序等待。缺少可靠资源声明的插件按工作区独占处理，不能从函数名猜测其只读。

插件的只读或资源声明属于调度契约，不能提升既有权限，也不构成操作系统沙箱。所有当前审批、禁用策略、路径检查和工具入口校验必须保留。声明只读的节点返回写入提案时不得静默落盘，应报告契约不一致并交由主任务重新决策。

## 并发与顺序

同一任务的运行上限沿用用户选择的 1x–5x；没有显式依赖且资源不冲突的节点才可同时运行。整份文档写入是依赖全部必要章节成功的后置节点，不能让多个工作者各自覆盖最终文件。某节点失败时，依赖它的节点标记未执行，并显示原因；独立节点可以继续，汇总必须公开缺口。

浏览器和电脑控制等需要人工确认的操作，先按顺序完成可见审批，再派发被批准的具体调用。现有 `awaitUserAnswer` 只有单个任务问题槽，不能由多个并行节点同时写入。工具结果归并、提案入库与共享 `versions` 也不能直接在多个 goroutine 中修改。

## 日志、取消与恢复

每个节点派发前保存自己的工具意图，结果返回后保存节点结果和摘要，最后由主任务按稳定顺序归并模型上下文。已有 `ToolExecutionIntent` 和 JSONL 日志需要按节点保留，不能只留下最后一个在途工具。状态至少区分：等待依赖、等待资源、等待审批、运行、成功、失败、未执行、结果待核实。

暂停时不再派发等待节点，传播可取消执行的上下文。已经派发但没有可靠完成回执的写操作保留“结果待核实”，恢复后不能自动重放。当前 daemon RPC 没有通用撤回协议；超时入口已补齐“停止对应进程实例后返回待核实”，防止处理器继续与下一调用重叠。这个停止动作不撤回外部副作用，也不代替依赖图的恢复核实。不能因调用方停止等待就释放资源并启动下一个可能冲突的写操作。需先确认处理器结束或显式停止对应执行实例。

## 接入门禁

- 真实处理器屏障证明独立调用重叠，并发上限覆盖 1x 和 5x；不是只检查 goroutine 数。
- 同一文件的读写/写写顺序、多个资源的公平等待、不同工作区/SSH 根的隔离。
- 环与未知依赖在任何工具执行前拒绝；前置失败使依赖节点明确未执行。
- 人工审批不会被另一个节点覆盖；每项批准对应具体工具和参数。
- 暂停、超时、进程重启和未确认写入不触发重复副作用。
- 每个节点有执行意图与结果证据；提案、`versions` 和模型工具消息按稳定顺序归并，Go race 通过。
- ROS2 文档场景实际展示规划、等待、并发、单份输出及缺口；模拟模型和真实模型证据分别记录。

以上门禁通过后才能把执行器标记为完整资源依赖调度。当前 FIFO 队列和五路草稿测试是前置基础，不替代这些门禁。

## 当前实现：资源预约与中断收尾

`plugin_resources.go` 已接入 `callPluginToolContext`，读取宿主surface中的 `scheduling.resources`，不采信模型参数。多资源同时预约，读读可以重叠，冲突操作按资源队列顺序等待；同插件原FIFO保留。目录按祖先关系冲突，符号链接和硬链接别名回退独占。缺少或无效契约、跨插件服务消费者、SSH和电脑/浏览器控制插件回退整个插件执行域独占。有契约且无服务依赖的短命调用只加载目标模块；读取其他插件模块以装配服务的调用保持独占。只读或越界提案在进入审批队列前拒绝；有效提案仍须原有审批与应用检查。

短命宿主与daemon使用独立进程组；中断时终止同组子进程，之后释放预约。daemon新增上下文取消，登记和派发在生命周期锁内绑定一个进程代际，不能将旧调用误发给替代实例。主动脱离进程组及外部副作用仍不保证撤回。协议细节见[插件资源契约](../plugin-protocol.md#31-工具读写资源调度2026-10-14兼容-v12)。

资源预约解决统一入口中跨插件已派发调用的协调，本身不提供任务图。新增显式图派发、依赖校验与节点日志见后文候选；模型实际采用、完整状态界面和未知效果核实仍待验收。不得以队列测试替代完整ROS2工具计划验收。原资源层测试、部署及镜像状态见[资源调度任务](../tasks/plugin-resource-scheduling-20261014.json)。

### 2026-10-15：资源预约先于同插件 FIFO

完整资源范围现在先进入共享预约队列，再取得同插件 FIFO。此前相反的顺序会隐藏同插件内排队的写操作，导致另一个插件后来的读取插队。每个有效资源范围已包含插件状态目录的独占预约，未声明调用则独占整个执行域，因此取得资源后再进入 FIFO 不会产生反向持锁等待；工作区、契约、启停及禁用策略仍在两道门之后复核。等待阶段不启动处理器。

真实 Node 回归先运行插件 A 的读取，再排 A 的写入及插件 B 的读取；B 必须等写入完成并读到新内容。插件 C 声明独立资源，其处理器同时能进入执行。修复前该场景实际出现 B 插队，不能用原有单独 FIFO 和资源队列单测通过代替组合入口验收。此修复仍不是完整任务 DAG，详见[排队顺序任务](../tasks/plugin-resource-order-20261015.json)。

## 显式插件任务图候选（2026-10-15）

`run_plugin_plan` 接受最多20个插件节点，字段为 `id`、`tool`、`arguments`、可选 `title`、`dependsOn` 和 `bindings`。`bindings` 将参数名映射到一个直接依赖节点的 ID，传入该节点已成功返回的文本，不执行字符串模板或代码。重复 ID、未知依赖、自依赖、环、无效绑定、停用工具、沙箱或任务工具限制在整图派发之前检查；内置工具、内置别名及递归任务图不作为节点。嵌套节点和外层图共同计入原工具调用预算，单任务最多保留8份图记录。

就绪节点最多按任务所选1x–5x派发，仍经过统一插件资源预约与同插件顺序门；实际准入时再次检查工作区、当前沙箱及工具策略。单控制器处理确认问题、Hook、日志和归并，节点工作者不写共享提案与 `versions`。如匹配的工具 Hook 没有完整资源契约，图会明确报告请求倍率和实际1x，避免 Hook 与其他节点写入交叉；这项限制仍待资源化 Hook 的后续设计。

节点先保存意图，再进入资源等待或执行；返回后保存结果。当前状态为 `waiting`、`dispatched`、`succeeded`、`proposed`、`skipped`、`uncertain`，其中 `dispatched` 包含资源等待，不宣称处理器已经进入。确认问题按就绪顺序逐项呈现，实际参数只对应那一项确认。规划、节点意图和返回结果使用已有流事件发布；专用节点状态面板的只展示验收见后文；实时执行与审批流程仍待浏览器验收。

只有成功节点可解锁依赖。写入提案标为 `proposed`，依赖它的节点暂不执行，须在后续确认应用并读回后重新安排。主控制器按输入节点顺序归并工具记录和提案；竞争同一文件的后续提案明确拒绝，不能静默覆盖先前提案。`mergeState` 区分 `pending`、`queued`、`withheld`、`rejected` 和部分接受的 `partial`；queued 仍不是已应用。

取消后不再派发，等待所有已派发工作者退出。可以证明未进入处理器的拒绝标为 skipped；处理器错误、中断或缺少可靠回执则保留 uncertain 和未完成意图。重启将未完成派发恢复为 uncertain，尚未派发的节点记为 skipped；相同图调用 ID 只返回持久记录，不自动重放。前一图仍有未知效果时，不派发新图。恢复后的不确定节点继续进入成果舱缺口，不能因临时意图退休就消失。人工核查记录入口见下节；恢复管理、基于外部证据的自动校验及真实模型联调仍未闭环。

候选测试使用隔离模型 HTTP 接口和真实 Node 插件，区分模型协议、实际处理器并发、提案与真实写入、重启记录与外部副作用；不调用用户真实模型，不证明真实 ROS2 文档质量。原分析型并行阶段仍只生成草稿，工具图属于主执行器的后续操作，两者不混记为同一证据。

### 节点状态面板与证据入口

当前会话每轮输出可以展开插件任务图，查看依赖、请求倍率、实际倍率和节点状态。已派发不等于处理器已运行，返回成功不等于成果已核验，提案排队不等于文件已应用；未知效果单独标识并连接该轮成果证据。停止的任务中，不确定节点可追加人工核查记录；界面不提供重放按钮。

图元数据独立参与会话和输出卡片的刷新判断，流中的意图事件触发快照刷新。用户收起状态、结果展开与键盘焦点在重绘时保留。标题、原因和结果均作为纯文本显示，结果按需展开并截取前4096字符；参数与提案正文不加入显示指纹或节点面板。

本批通过 canonical `start.command` 在9999打开实际 Safari，使用明确标注的只展示会话检查桌面、实际581×971窄窗口、当前深色表现、空格展开结果及非最新轮次的证据跳转。检查后仅删除自建会话，保留原会话。该证据不包含真实模型执行、实时多节点审批、其他主题或390像素布局；这些项目仍待验收。详见[节点界面任务](../tasks/plugin-plan-ui-20261015.json)。

### 人工核查记录（2026-10-15 候选）

停止的任务（paused/interrupted/completed/failed/cancelled）中，非运行图的不确定节点支持“记录人工核查”。操作者选择观察到效果、未观察到效果或仍无法判断，填写1–4096字节依据；每节点最多保留20条，不覆盖早期记录。服务端生成 UTC 记录时间、`operator_observation` 归属及记录 SHA256。共用本机鉴权令牌无法区分自然人身份，因此不伪造实名核查者，也不把人工陈述标作系统验证。

`POST /api/sessions/{id}/runs/{run}/plugin-plans/{plan}/nodes/{node}/checks` 接受 `planDigest`、`expected`（已有记录条数）、`conclusion` 和 `evidence`。整图参数摘要与修订必须匹配；错误会话/轮次/图/节点拒绝，运行中或非不确定节点拒绝。写入与修订校验在同一互斥区，磁盘保存失败恢复内存；请求失败后可保留编辑依据，409须重新加载记录再核对。UI 对话框绑定会话、工作区和导航代际，切换或锁屏清除临时依据，双击不会并发重复提交。

记录保留于所属会话，成果舱只投影结论、来源、时间及指纹，不导出详细依据或插件私有参数。人工核查不填造原始工具回执：节点仍为 uncertain，成果舱继续报告缺失结果，原图禁止重放、依赖不自动恢复、任务恢复屏障不清除。记录核查本身不恢复任务；后续明确继续的流程见下节，仍不自动重放原调用。实际验收范围见[核查任务](../tasks/plugin-effect-checks-20261015.json)。

### 核查后明确继续（2026-10-15 候选）

暂停或中断任务的“恢复任务”先请求 `GET /api/sessions/{id}/runs/{run}/recovery`。预览只公开未完成图、未知节点、最新核查结论与指纹、其他未确认调用编号及旧后台／Hook 警告；不公开工具参数、核查依据或检查点正文。每个不确定图节点必须有有效人工核查记录；“仍无法判断”也如实保留，不能据此改称执行成功。

需要核查时，原 `POST .../resume` 载荷额外要求 `recovery: {snapshot, decision: "continue_without_replay", note}`。说明为1–4096字节。快照绑定会话、任务内容、工作区及代际；核查更新、工作区切换或旧任务仍在停止会拒绝提交。并发确认只有一次能创建后继任务，保存失败保持原状态且不启动工作者。没有未知效果的普通检查点沿用原恢复方式。

继续决策仅记录于后继任务的 `recoveryContinuation`，包含来源任务、操作者提交归属、时间、内容指纹及已审阅旧图／调用身份；共享令牌不能证明自然人身份。旧图编号只返回历史记录，旧节点和依赖保持原状态；两个图准入阶段均复核旧图内容没有改变，才允许另建新图。相同工具和规范化 JSON 参数的未确认效果，不能仅更换调用／图编号重试；图参数绑定后也再次检查。它不是语义去重，无法识别不同命令或参数造成的同一外部效果。内置只读查询仍可用来核查状态。整轮“重试”不能绕过未知效果审阅。

后继任务重新遵循当前全局工具禁用、沙箱及审批；原任务的 Hook 和工具约束快照继续保留，不因继续而删除 Hook。明确决定只解除已审阅的恢复阻塞，后续新调用仍正常执行其任务 Hook。说明与详细核查依据不自动发送给模型；缓存旧图作为工具结果返回时也剔除详细依据。成果舱展示继续决策来源与指纹，同时保留旧未知结果，继续决策不是验证回执。

[本批验收](../tasks/plugin-recovery-continuation-20261015.json)使用本地模拟模型和真实 Node 屏障／文件标记核对旧调用不执行、新图执行、策略拒绝、状态变化、并发、保存失败及重启。指定 `start.command` 的实际 Safari 验收使用独立构造会话和 Docker 内网模拟模型，检查缺核查禁用、说明／确认必填、过期快照拒绝与说明保留、成功后继任务和成果舱。它不验证真实提供商采用规划、真实外部副作用、跨设备导入或完整发布。
