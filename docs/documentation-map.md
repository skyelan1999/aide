## 清理过时内容的规则

1. 从当前首页和导航删除失效的功能描述、重复安装步骤与旧版本“当前状态”；保留通向历史证据的入口。
2. 对仍有价值的专题直接更新当前正文，移除相互矛盾的“最新更新”堆叠。历史过程引用原审查记录，不继续塞进操作说明。
3. 不把旧任务全部标记完成，不删除测试日志、失败收据、发布记录和用户资料。需要清理的是误导当前操作的内容。
4. 源码、编译产物、运行实例和公开 Release 分开标识。`version.md` 是版本声明；实际公开附件应查对应 tag/Release 和摘要。
5. 参数必须说明语义。例如 Markdown 的 16 KiB 是共享内联上下文预算，不是文件上传上限；并行倍率是请求并发上限，不是提速保证。
6. 配置变化、AI 审批通过、工具返回成功和当前文件内容一致是不同事实。文档应说明检查发生在何处、失败后保留什么。

## 本次维护范围

本次更新 Aide 首页、文档中心、交接、架构入口、模块索引、功能与用户说明、PRD 的当前元信息，以及并行和电脑控制专题；新增署名 Skye Lan 的技术白皮书与源码/发行身份快照。只核对这些入口关联的核心实现，不宣称逐份重审全部历史文档。

外部插件仓库、市场条目、用户工作区、程序代码、镜像和当前本地 Aide 实例不在本次修改范围。

## 文档校验

在仓库根执行：

```bash
python3 scripts/check_docs.py
git diff --check
```

检查覆盖仓库 Markdown 本地链接、图片签名和历史 FR 编号。它不验证远程网站可用性、Mermaid 的所有渲染环境、产品行为或跨平台兼容性。技术变更需另按模块运行测试；本次文档维护不新建 Aide 或 Docker 实例。
