## 0. 如何使用本文档

### 0.1 开发前核对流程（每次开工必做）

1. **读状态**：`git log -3 --oneline`、`git status --short`，确认基线没被动过、工作区干净。
2. **读本文第 4 节**：找到本次要做的 FR 编号，确认它的当前状态是"未实现"或"已实现·未验收"，而不是被误标为已完成。
3. **读本文第 3.2 节**：确认这件事**不在非目标列表**里。在非目标里的事情，必须先改需求再动手。
4. **读本文第 6 节**：确认方案没有突破量化限制（文件大小、超时、并发、挂载只读等），否则要连带更新限制表。
5. **收尾**：改完代码后回来更新第 7 节验收状态矩阵、第 11 节变更记录；有新的边界限制就同步第 6.5 节。

### 0.2 需求编号规则

- `FR-xx`：功能需求（Functional Requirement）
- `NFR-xx`：非功能需求（Non-Functional Requirement）
- `OOS-xx`：明确排除在范围外的项（Out of Scope）
- `LIM-xx`：硬性量化限制

编号一旦分配不再复用。废弃的需求标为"已废弃"并写明原因，不删行。

### 0.3 状态标记含义

| 标记 | 含义 | 可以据此做什么 |
| --- | --- | --- |
| `已实现·已验证` | 代码已写，且有测试或实测证据 | 可以依赖，但改动后要重跑对应验证 |
| `已实现·未验收` | 代码已写，只跑过模拟/本地受控验证，真实场景未验 | **不能对外宣称可用**，不能当成已完成 |
| `未实现` | 代码里没有 | 需要新开发 |
| `部分实现` | 有主体，缺关键环节 | 需要补齐，并在备注写明缺什么 |

> 关键纪律：**"模型说已完成"不是证据**。只有工具执行输出、测试结果、主机侧实际读取才算证据。模拟 API 通过 ≠ 真实模型通过。

## 1. 项目定位

### 1.1 一句话定义

aide 是一个**运行在本地 Docker 中、以浏览器为界面的 AI 开发工作台**：Go 单服务后端，可读写挂载本地项目目录，提供会话对话、文件编辑、容器命令执行，以及"规划 → 文件提案 → 审查 → 人工应用"的三阶段 AI 工作流。

### 1.2 背景与来源

目标是复刻 DeepSeek Harness（DSH）的使用体验（会话、模型适配、工具分层、工作流），但**代码完全独立实现**，不引入 Cordis 插件运行时。DSH 的源码与文档作为 `/context` 只读参考资料挂载，仅用于理解架构。

### 1.3 设计原则（改动时不可违背）

| 编号 | 原则 | 含义 |
| --- | --- | --- |
| P1 | **不伪造能力** | 未配置模型时不给假回答；未运行的命令不宣称跑过；未验证的结论标注未验证 |
| P2 | **不自动执行破坏性动作** | 模型生成的命令只展示、不自动运行；文件改动必须用户点"应用"才落盘 |
| P3 | **附件即全部上下文** | 只有用户显式附加的文件才提交给模型；未附加的现有文件不可被提案覆盖 |
| P4 | **不可信输入隔离** | 附件内容、历史模型输出一律视为"资料"，不是指令；只有用户任务定义任务 |
| P5 | **本地单用户** | 只绑定 `127.0.0.1`，随机令牌 + 同源校验；不做多用户授权 |
| P6 | **数据可迁移** | 源码走 Git、镜像走归档、状态走命名卷，三者独立备份 |

## 2. 目标用户与使用场景

### 2.1 目标用户

单一可信用户（本机开发者），在自己的 Mac 上管理多个本地代码项目。

### 2.2 典型场景

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| S1 | 让 AI 读懂一个陌生项目 | 附加若干源码文件 → 对话模式提问架构与模块职责 |
| S2 | 让 AI 产出一份可审阅的改动方案 | 工作流模式 → 得到规划、JSON 文件提案、审查意见 |
| S3 | 把方案落到磁盘 | 展开 diff、确认无误后点击应用，主机文件同步更新 |
| S4 | 改完立刻验证 | 把建议命令填进命令面板，手动运行看输出与退出码 |
| S5 | 快速改一个小文件 | 在右侧文件面板打开编辑器，改完保存，哈希校验防冲突 |

### 6.3 任务状态机

```text
running → completed                        对话，或无文件提案
running → awaiting_approval → completed     有文件提案，经用户应用
running → failed / cancelled               模型错误、协议错误、停止、超时
running → interrupted                      服务重启后的恢复标记
```

### 6.4 API 契约

除静态资源与 `/healthz` 外，全部需要 `Authorization: Bearer <token>`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/healthz` | 健康检查（免鉴权） |
| GET | `/api/config` | 不含密钥的配置与运行信息 |
| PUT | `/api/settings` | 保存 API 地址、模型、密钥（支持 `clearKey`） |
| GET | `/api/files?root=workspace&path=.` | 列目录 |
| GET | `/api/file?root=workspace&path=README.md` | 读文本与版本哈希 |
| PUT | `/api/file` | `{path,content,hash}` |
| GET / POST | `/api/sessions` | 列出 / 创建会话 |
| GET | `/api/sessions/{id}` | 完整会话与任务状态 |
| POST | `/api/sessions/{id}/runs` | `{prompt,mode,attachments}` |
| POST | `/api/sessions/{id}/runs/{run}/cancel` | 取消任务 |
| POST | `/api/sessions/{id}/runs/{run}/apply` | 应用已审查的文件方案 |
| POST | `/api/command` | `{command,cwd}`，返回 NDJSON |

附件格式：`[{"root":"workspace","path":"README.md"}]`。只有 workspace 可写。

### 6.5 量化限制（改动必须同步此处）

| 编号 | 对象 | 限制 | 定义位置 |
| --- | --- | --- | --- |
| LIM-01 | HTTP JSON 请求体 | 1 MiB | `server.go: decode` |
| LIM-02 | 用户任务长度 | 1 – 20,000 字节 | `workflow.go: startTask` |
| LIM-03 | 显式附件 | 最多 8 个；拼装后 ≤80,000 字节 | `startTask` |
| LIM-04 | 单个文本文件 | 256 KiB；拒绝非 UTF-8 / 含 NUL | `files.go: readText` |
| LIM-05 | 文件提案 | ≤10 文件；总内容 ≤512 KiB；≤20 条命令 | `acceptProposal` |
| LIM-06 | 历史回放 | 文本总量 <60,000 字节 | `startTask` |
| LIM-07 | 模型并发 | 每会话 1 个；全服务 4 个 | `startTask` |
| LIM-08 | 模型时限 | 单次请求 120 秒；整体任务 6 分钟 | `provider.go` / `workflow.go` |
| LIM-09 | 命令 | 最多 4 并发；最长 60 秒；输出 ≤128 KiB；命令串 ≤16,000 字节 | `command.go` |
| LIM-10 | 目录浏览 | 单次 ≤2,000 项，无翻页 | `files.go: listFiles` |
| LIM-11 | 命令会话 | 每次独立 shell；不保留 `cd`；无 stdin / PTY | `command.go` |
| LIM-12 | HTTP 服务 | 读头超时 10s；空闲超时 60s；最大头 16 KiB | `server.go: Run` |
| LIM-13 | 模型响应体 | 读取上限 2 MiB | `provider.go` |
| LIM-14 | 容器资源 | 2 CPU / 2 GiB / 256 PID | `compose.yaml` |

### 6.6 挂载与存储

| 主机路径（默认） | 容器路径 | 用途 | 备份方式 |
| --- | --- | --- | --- |
| 当前 `aide/` | `/workspace` | 可读写项目 | Git + 文件备份 |
| 上一级 `Harness/` | `/context` | 只读参考资料 | 单独保存或重建 |
| 卷 `aide_aide-data` | `/data` | `access-token`、`settings.json`、`session-*.json` | **必须单独备份**，可能含密钥与私有对话 |
| 卷 `aide_aide-home` | `/home/aide` | 工具缓存与用户配置 | 有自定义环境时迁移 |

**配置优先级**：`/data/settings.json` **整体优先于** `.env` 环境变量。只改 `.env` 可能不生效，应从浏览器模型设置更新。

AI_MODEL=

`.env` 已被 Git 忽略；不存在时复制 `.env.example`，**不要覆盖已有 `.env`**。

## 8. 已知缺陷与风险

| 编号 | 问题 | 影响 | 状态 |
| --- | --- | --- | --- |
| R-01 | "审查完成"无自动判据 | 用户仍须逐条审阅提案 | 待 FR-32 |

| R-03 | 无会话格式版本迁移 | 改数据结构可能读到旧格式 | 待 NFR-11 |
| R-04 | 附件非持久快照库 | 新一轮分析需重新附加文件 | 待设计 |
| R-05 | 镜像归档仅 ARM64 | x86 环境需另行构建验收 | 见 FR-47 |
| R-06 | 0600 权限不等于加密 | 手动 shell 仍有容器用户对数据卷的权限 | 已接受 |
| R-07 | 目录无翻页 | 大目录只见前 2000 项 | 见 FR-13 |
| R-08 | 命令面板权限高于文件 API | 文件 API 隐藏 `.git`/`.env`，但命令面板可读 | 已接受（可信单用户前提） |
