二、/data 分层目录设计

把当前 30+ 平铺文件归入语义子目录；徽章表示敏感度，鼠标悬停可看说明。
机密（加密/600） 敏感（600） 常规状态 可再生/缓存
小蜜的加密会话放哪：小蜜是服务于「你这个人」的全局助理，不隶属于任何项目，因此其对话历史、记忆与性格统一放在状态卷 /data/assistant/，全部 AES-256-GCM 加密、密钥由你的密码经 Argon2id 派生；跨项目、跨升级持续可用，且不进入任何项目目录，避免随项目分享时泄露隐私。

数据归属决策矩阵

逐类数据明确位置、是否加密、是否可再生、备份与恢复来源。
数据类型位置加密可再生备份 / 恢复来源
关键原则：跟「项目」走的只有用户自己的工作产物与参考资料；aide 的一切私有状态（会话、记忆、小蜜、密钥、统计）都在命名卷 /data，绝不写进用户项目目录，从而不会被 git 提交、打包或随项目外发。

核心组件完整性校验

分「程序层」与「数据层」两类对象，在启动 / 运行时 / 升级三个时机校验。
1

构建期：生成基线清单（程序层）

Docker 构建阶段对二进制、内置模板/脚本/插件计算 SHA-256，写入随镜像分发的 manifest.json（go:embed 前端已在二进制内，校验二进制哈希即覆盖前端）。

/app.manifest → { aide: sha256, templates/*: sha256, version, commit }
2

启动校验（boot-time）

① 比对程序层哈希与基线，防篡改；② 校验 /data 目录结构（缺失则建/迁移）；③ 关键文件可解析性（settings、sessions、证书、密钥格式）。

3

运行时巡检（periodic / event）

周期性轻量校验 + 敏感操作（解锁、外部接入）前校验；所有写入走原子写（temp+rename，已具备 atomicJSON），杜绝写一半损坏；版本升级时做 schema 迁移校验。

4

状态上报与闭环

/healthz 输出 integrity 状态（ok / degraded / recovering / quarantined）；外部 AI 调试接口 /api/debug 暴露校验结果与恢复历史，无浏览器也可诊断。

自动恢复策略

按数据性质选择恢复路径；用户数据只隔离、不自动删除。
恢复安全边界：自动恢复只作用于「有模板 / 有备份 / 可再生」的内容；会话、记忆、小蜜历史等用户数据一旦异常，移入 /data/.quarantine/ 隔离并提示，绝不自动删除；每次校验与恢复都写入 /data/.integrity/recovery.log，恢复后再校验形成闭环。

现有平铺 /data 的一次性迁移

  • 启动时运行幂等迁移器：按映射把平铺文件移入对应子目录，移动采用「复制→校验→删除」，失败可重入、不丢数据。
  • 迁移与 #29（Argon2id / re-wrap、TLS 证书目录）、#30（会话编号、小蜜系统会话）合并在同一次启动流程，按固定顺序执行：目录建立 → 文件迁移 → 密码/KDF 升级与密文 re-wrap → 编号分配 → 完整性校验。
  • 保留 settings.json.pre-import 等历史副本到 config/backups/。

各平台关键局限

  • Linux：docker 组成员权限等价 root，脚本不自动 sudo / systemctl，引擎需自行确保运行；macos-root 不适用，默认仅能经 /local 访问 $HOME；无桌面服务器缺 xdg-open，需手动带令牌访问；Touch ID 不可用。
  • Windows：须 WSL2 后端，绑定挂载需在 Docker Desktop 共享盘符；PowerShell 默认执行策略可能阻止 .ps1（已提供 start.bat 绕过）；/local 映射 Windows 用户目录路径特殊；Touch ID 不可用；CRLF 与路径不敏感可能与容器内行为不一致。
  • 通用：TLS 自签证书三平台均需手动信任，否则浏览器告警；服务端口绑定 127.0.0.1 仅本机可达，远程访问请用 SSH 隧道或 Tailscale。
验证声明：macOS 为当前唯一真机验证平台；Linux 与 Windows 的启动脚本（start.sh / start.ps1 / start.bat）仅完成逻辑编写，标记 NOT_RUN，未在对应系统实际运行，后续需在该平台补测。
