01核心结论

一句话：iPad 不本地跑后端，而是作为 aide 的移动控制台，连接一台常驻主机。

推荐方案：远程常驻 aide 主机 + Tailscale 组网 + iPad「添加到主屏」PWA

  • 执行在主机，交互在 iPad：aide 的执行核心（Docker、命令行、文件读写、构建、插件）必须运行在一台真正的计算机；iPadOS 不提供容器、也不允许常驻后端。模型本就走云端，iPad 只负责对话、呈现与触控，体验可与桌面一致。
  • 改造成本可控：前端已具备响应式骨架（viewport 安全区、多档断点、抽屉式面板），主要补齐 PWA、触摸手势与文件进出。
  • 安全且零公网端口：用 Tailscale 端到端加密组网，iPad 在外也能安全回家，配合强密码、锁屏与 Face ID。
  • 原生壳为可选项：需要 Face ID 解锁、系统推送、更稳后台时，再做 SwiftUI + WKWebView 壳，可走 TestFlight。
阶段 1–2即可在 iPad 获得完整可用体验
0 个需要开放的公网入站端口（Tailscale）
不推荐在 iPad 本地完整运行后端（系统限制）

02现状与约束

基于当前代码实际盘点，区分「已具备」与「iPad 限制」。

aide 当前架构

Go 标准库 HTTP 单体，前端 go:embed 编入二进制，Docker Compose 部署；SSE 增量推送。

  • 工具：命令面板 run_shell、文件读写（/workspace、/context、/local）、SSH/SFTP 驱动、Node 插件宿主
  • 模型：DeepSeek 等兼容 Chat Completions，云端调用

前端已具备的移动基础

  • viewport 含 viewport-fit=cover（适配刘海/圆角安全区）
  • 响应式断点 1600 / 1150 / 950 / 600
  • ≤950 文件面板改右侧抽屉；≤600 侧栏隐藏 + 遮罩 + 迷你 Logo
  • 渲染库本地 vendor（marked / mermaid / three），不依赖 CDN

iPadOS 提供的能力

  • PWA：添加到主屏、全屏、离线缓存；Web Push（16.4+）
  • WebAuthn：可调用 Face ID / 触控 ID 做平台认证
  • Files App 文件提供者、Apple Pencil、麦克风/语音合成
  • 妙控键盘 / 触控板指针、分屏与台前调度

iPadOS 的关键限制

  • 无 Docker / 无任意可执行二进制、无常驻后台服务
  • 第三方浏览器统一使用 WebKit 内核
  • 后台标签会被挂起/回收，长连接受限
  • a-Shell / iSH 等本地终端能力弱、后台即停，仅适合降级

04三条候选路线对比

先看路线，再看维度评分；推荐 A 先行、B 按需、C 仅做降级。

路线 A · 远程后端 + PWA 推荐

aide 跑在常驻主机，iPad 用 Safari“添加到主屏”，全屏、离线外壳、安全接入。

  • 无需上架，改造量小
  • 能力与桌面一致
  • 依赖网络连接主机

路线 B · 原生 App 壳 后期增强

SwiftUI + WKWebView 封装，壳负责 Face ID、钥匙串、推送、Files、更稳后台。

  • 体验与安全最佳
  • 需 Swift 开发与签名
  • 可 TestFlight 分发

路线 C · iPad 本地运行 不推荐

尝试 a-Shell / iSH 在本地跑工具，受沙箱与后台限制，能力残缺。

  • 仅适合只读/演示降级
  • 无容器、后台即停
  • 投入高、收益低
对比维度A 远程 + PWAB 原生壳C 本地运行
离线可用性外壳可缓存，操作需连主机外壳可缓存，操作需连主机可离线，但能力残缺

06网络拓扑与安全

零公网入站端口：iPad 从任意网络经加密 tailnet 回家；主机只主动出站访问模型。

iPad蜂窝 / 家庭 / 公共 Wi-Fi
Tailscale · 优先 P2P 打洞，必要时 DERP 中继
加密隧道WireGuard
ACL仅 aide 端口
常驻主机aide 仅监听 tailnet IP · 防火墙拒绝公网入站
模型 / TTS 为主机主动出站访问（云端），或直接走本地模型；任何情况下都不需要在路由器做端口转发，也不把 aide 暴露到公网。

接入与传输

  • aide 端口仅绑定 tailnet 地址（100.x.x.x），不监听 0.0.0.0
  • Tailscale MagicDNS + 自动 HTTPS 证书，避免自签证书告警
  • ACL 最小权限：iPad 只能访问主机 aide 端口

鉴权与数据

  • 用户密码（哈希存储）+ 访问令牌；外部 AI 调试接口默认关闭
  • Face ID 走 WebAuthn，仅存公钥，私钥与生物特征不离设备
  • 会话与小秘历史 AES-256 加密；多设备登录可审计、可吊销

09风险与未知情况（红队）

提前列出可能踩坑的点与应对，避免实施时返工。

后台标签挂起，SSE 被断

切走后连接中断、任务在主机继续。需给事件编号，重连后按序号增量回放，否则用户误判“卡死”。

PWA 存储被系统清理

存储紧张时 iOS 可能清理 PWA 数据。关键数据只存主机，iPad 仅做缓存，不做唯一副本。

WebAuthn 起源一致性

RP ID 必须与固定域名一致，IP 直连无法注册。需固定 Tailscale MagicDNS 域名与有效证书。

Tailscale 登录与中继延迟

首次需登录并加入 tailnet；打洞失败走 DERP 会增加延迟，必要时自建 DERP 节点。

主机休眠或宕机

主机不可用则 iPad 不可访问。设置断电自启、休眠唤醒、健康检查与异常通知。

浏览器内核与 PWA 差异

iOS 全为 WebKit，PWA 以 Safari 为准；Chrome for iOS 不能添加完整 PWA，需引导用 Safari。

音频会话被打断

来电或其他音频会中断小秘，需监听中断事件并支持手动/自动恢复。

多端同时操作竞争

iPad 与桌面操作同一工作区，依赖文件自动刷新与主从锁定规则避免覆盖与状态错乱。

10需要你决策的点

  1. 常驻主机选型：现有 Mac 常开 / Mac mini / 小主机或 NAS / 云服务器？
  2. 组网方式：Tailscale（推荐）还是自建 WireGuard / VPN？
  3. 模型策略：继续云端 DeepSeek，保密场景是否切本地模型？
  4. 是否做原生壳（路线 B）及其上线节奏。
  5. 小秘默认语音引擎：待团队产出 2–4 个引擎对比样本后由你盲听确定。
  6. 是否需要本方案的英文版（可同步产出）。
