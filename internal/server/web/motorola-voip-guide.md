# Motorola IP9910-2W 接入 AIDE R&D

拿起话机，选 SIP1。拨 **1000** 找本机助理。拨 **8 位成员编号** 找消息联系人，对方接听后双方才能说话。已经能给小绵打电话的用户，可以直接从第 3 步开始。

## 1　让电脑和话机在同一局域网

1. 在话机的状态或网络信息页记下 IPv4 地址。在以下命令里，用它替换示例地址 `192.168.1.50`。在路由器为话机保留这个地址，换网后重新核对。
2. 在运行 AIDE R&D 的电脑上打开工作台，解锁。点击左上角 AIDE R&D 标志打开设置，选择 **助理与语音 → VoIP 话机**。刷新网关状态。如果已显示“普通通话”以及“成员语音组件已就绪”，直接进入第 2 步。
3. 首次配置使用带有 `scripts/aide_sip_phone.py` 的 AIDE R&D 安装目录。在此目录打开终端，使用 Python 3.9–3.12。先完成 AIDE R&D 首次启动。本地 HTTPS 默认端口为 9999；若启动器显示其他端口，在下方手动配置或 Windows 前台命令末尾追加 --aide-port 和实际端口。macOS 桌面启动器自动带入本次使用的端口。以下命令在电脑宿主上执行。

**macOS / Linux**（若已存在网关虚拟环境，只执行第二行安装依赖）

```sh
python3 -m venv .aide-data/sip-phone/venv
.aide-data/sip-phone/venv/bin/python -m pip install -r scripts/sip-phone-requirements.txt
```

首次使用时，运行下面这行，把示例 IP 换成话机屏幕上的地址。命令会写入本机配置并保留已有的账号和端口。已经能打 1000 的用户直接跳到启动步骤。

```sh
python3 scripts/aide_sip_service.py configure --root . --phone 192.168.1.50
```

自定义时可追加 `--phone-user 1001`（SIP1 账号）、`--sip-port 5060`（电脑监听端口）、`--phone-port 5060`（话机监听端口）。

话机空闲时启动网关，或用同一命令加载升级后的宿主代码。macOS 桌面启动时也会检查这份配置。

```sh
python3 scripts/aide_sip_service.py restart --root .
```

再去设置页点“刷新网关状态”，以此时显示的地址为准。进程启动与收到注册请求是两个独立步骤。手动停止网关可执行 `python3 scripts/aide_sip_service.py stop --root .`。

**Windows PowerShell**（前台启动；保持该终端打开，Ctrl+C 停止）

```powershell
py -3.12 -m venv .aide-data/sip-phone/venv
.\.aide-data\sip-phone\venv\Scripts\python.exe -m pip install -r scripts/sip-phone-requirements.txt
.\.aide-data\sip-phone\venv\Scripts\python.exe scripts/aide_sip_phone.py --normal --serve --assistant auto --phone 192.168.1.50 --phone-user 1001 --call-seconds 1800
```

## 2　在摩托罗拉话机填写 SIP1

在话机菜单找到网络状态，或用同网电脑通过话机自己的地址打开管理页，使用设备已有的管理员账户登录。打开“线路 / SIP 账号”中的 **SIP1**。固件菜单文字可能略有不同。先记下已有设置，已经正常注册的线路可跳过这一步。

| 话机字段 | 填什么 |
| --- | --- |
| 账号启用 | 开 |
| SIP 服务器 / 注册服务器 | AIDE R&D 设置页显示的**电脑局域网 IP**，只填地址 |
| 注册服务器端口 / 传输 | 设置页显示的网关端口，通常为 5060 / UDP |
| SIP 用户名 / 号码 | 设置页中的话机账号，默认 1001 |
| 鉴权用户名 / 密码 | 本地单话机配置留空 |
| 话机本地 SIP 端口 | 通常为 5060。自定义时在电脑配置命令中使用 --phone-port 指定同一端口 |
| 音频编码 / 包长 | G.711U（PCMU）优先，G.711A（PCMA）备用，20 ms |
| DTMF / 拨号 / 接听 | RFC2833，按拨号键发送，支持时可设置 # 立即拨出，手动接听 |

点击保存或应用，等 SIP1 显示已注册，再刷新 AIDE R&D 页面查看最近注册请求。若启用了自定义号码规则，须允许 1000 与完整八位数字原样送出，并保留开头的零。1001 是话机账号；呼叫助理请拨 1000。

## 3　拨一次 1000

在“助理与语音 → 语音助理”选好通话模型与音色，打开并解锁小绵。在听筒或免提上选 SIP1，按 1000，再按拨号键。说一句简短的话，确认听到了与问题对应的回答。挂回听筒，再拨一次，检查线路已释放。

## 4　查成员编号，拨一次成员电话

1. 双方分别在 AIDE R&D 设置里填写账户名称，在消息设置中启用设备通信，并保持工作台解锁。
2. 打开 **消息 → 联系人**。首次添加用对方的 **6 位设备码** 查找，核对完整设备指纹，双方完成联系人同意。
3. 已互相同意的联系人名字下显示 **8 位十进制通话编号**。自己的编号在“我的设备码”下方，可告诉其他已添加自己的成员。编号按设备身份计算，重启或改显示名称后可继续用原编号。
4. 在 SIP1 一次拨全这 8 位数字再按拨号键，或在联系人页“输入 8 位成员编号”后点“呼叫成员”。对方在 AIDE R&D 的语音邀请中点“接听”。双方各报一个不同的数字，让对方复述，再从任意一端挂断。成员电话使用消息语音，通话期间无需助理模型。
5. 同号时页面会提示选择具体联系人。打开相应单聊点击语音呼叫。被拉黑、尚未互相同意或不可达的成员无法按编号接通。

## 5　按需开启工作台来电和任务回拨

展开 VoIP 设置里的“从工作台呼叫话机”。点击“带入网关当前的话机地址和账号”，核对带入的是**话机**的 IPv4、本地 SIP 端口与 SIP1 账号。勾选所需的“接管消息语音”或“接管助理电话”，点击“保存话机设置”。从工作台发起或接听对应通话，话机应响铃；此时摘机。用话机主动拨号无需开启接管。

“任务完成后回拨原话机”是另一项开关。需要时开启，在 1000 通话中新交办一件任务后挂断。任务实际结束且满足回拨条件才会来电，未接听时不自动重拨。

## 遇到问题时

| 现象 | 如何判断和处理 |
| --- | --- |
| 网关未运行 | 确认 AIDE R&D 已启动。核对 Python 版本和依赖，检查主机 UDP 监听端口是否占用，再查看本机 .aide-data/sip-phone/gateway.log 的错误类型。 |
| 网关运行，SIP1 未注册 | 话机的服务器应填电脑地址；电脑允许接入的地址应填话机地址。核对 UDP、两个端口及账号，重新应用 SIP1。工作台的最近注册时间只代表收到过该账号的 REGISTER。 |
| 1000 能通，8 位号码不能通 | 看设置页是否显示“成员语音组件已就绪”。旧网关升级依赖后重新启动。核对双方消息通信、联系人同意、前导零及对方是否接听；工作台“呼叫成员”可单独验证消息侧。 |
| 收到邀请却无声音 | 核对话机静音、音量、G.711 和局域网双向 RTP。对方用浏览器时应允许麦克风；跨网时检查消息设置里的 STUN / TURN。 |
| AIDE R&D 能打出，工作台不能让话机响铃 | 展开“从工作台呼叫话机”，检查本机 VoIP 组件状态、接管开关和话机端口。用配套启动器运行 AIDE R&D，手动接听。 |
| 想回到原来的使用方式 | 在工作台取消勾选需要关闭的接管项并保存。话机 SIP1 可继续主动拨号；关闭任务回拨会取消仍在等待的回拨。 |
